# CR-144: 워크플로우 삭제 시 실행 기록 보존 설계

- 발번: 2026-10-10
- 원본 요구사항: `docs/origins/원본_요구사항_CR144_워크플로우_삭제_실행기록_보존_20261010.md`
- 관련 규칙: BIZ-116 (신규), BIZ-059
- 상태: 구현 완료, 2026-10-10 운영 배포

## 1. 문제

워크플로우 삭제는 행을 바로 지운다. 실행 기록(`workflow_runs.workflow_id`)이 외래키로 워크플로우를 가리키므로
한 번이라도 실행한 워크플로우는 DB 가 삭제를 거부하고 API 는 500 을 돌려준다.

워크플로우에는 `is_active` 컬럼이 있고 목록 조회 일부가 이를 거르지만, 값을 false 로 바꾸는 경로가 없어 쓰이지 않는다.
공용 워크플로우(`platform_workflows`)는 같은 컬럼으로 숨기고 실행을 막는다.

## 2. 실측 근거

| 항목 | 위치 |
|---|---|
| 삭제가 행 삭제 | `WorkflowController.delete` (api/WorkflowController.java:118), `AdminToolService.deleteWorkflow` (mcp/admin/AdminToolService.java:191) |
| 실행 기록 외래키, ON DELETE 없음 | `V8__create_workflow_runs.sql:3` |
| 실행 기록을 가리키는 곳 | `action_logs.workflow_run_id`(외래키), `workflow_run_events.run_id`, `tool_execution_log.workflow_run_id`, `large_input_jobs.run_id` |
| 활성 컬럼 | `V7__create_workflows.sql:8` `is_active BOOLEAN DEFAULT true` |
| 기본 목록이 활성을 거르지 않음 | `WorkflowController.list` `findAll(pageable)` (api/WorkflowController.java:68) |
| 새 run 시작은 모두 엔진 execute 를 거침 | 실행 API, 재실행, 관리 MCP `run_workflow`, 크론(CronScheduleManager:193), 원격 트리거 도구(RemoteTriggerTool:110) |
| 공용 워크플로우의 같은 방식 | `PlatformWorkflowController` 실행 시 `isActive()` 확인 (api/PlatformWorkflowController.java:108) |

## 3. 설계

삭제는 `is_active = false` 로 바꾸는 것이다. 행과 실행 기록은 남는다.

1. 삭제: 활성 워크플로우를 비활성으로 바꾸고 204. 없거나 이미 삭제된 것이면 404
2. 정의 조회: 기본 목록, 상세, 수정은 활성만 대상이다. 삭제된 것은 목록에 없고 상세·수정은 404
3. 새 실행: 엔진 `execute` 가 활성 워크플로우만 찾는다. 이를 거치는 실행 API, 재실행, 관리 MCP 실행 도구, 크론, 원격 트리거 도구가 함께 막힌다. 실행 API 와 재실행은 404
4. 진행 중인 run: 삭제 전에 시작한 run 은 끝까지 진행한다. 재개(`resume`)와 스텝 실행(`executeStepById`)은 활성 여부를 보지 않는다
5. 실행 기록 조회: run 상세, run 목록, 이벤트, 횡단 실행 내역은 삭제와 무관하게 그대로 조회된다
6. 관리 MCP 도구 `get_workflow`, `update_workflow`, `delete_workflow` 도 1, 2 와 같다
7. 같은 ID 로 다시 생성하면 새 정의로 활성화되고, 이전 실행 기록은 같은 ID 아래 이어진다

## 4. 범위 밖

- 삭제된 워크플로우를 대상으로 한 크론 작업은 실행 때마다 실패하고 BIZ-059 에 따라 3회 실패 후 비활성화된다. 삭제 시 크론을 함께 끄는 것은 이번에 다루지 않는다
- 생성 API 는 이미 있는 활성 ID 로 요청해도 거부하지 않고 덮어쓴다. 이번 결함과 별개이며 따로 다룬다
- 실행 기록 보관 기간 정책은 정해져 있지 않다

## 5. 영향

모든 테넌트의 워크플로우 삭제가 대상이다. 삭제가 500 대신 204 로 끝나고, 실행 기록이 남는다.
기본 목록은 비활성 워크플로우를 더 보여주지 않는다. 지금까지 코드로 비활성화하는 경로가 없었으므로 대부분의 테넌트는 목록이 그대로다.
DB 스키마 변경은 없다.
