## 1. 무엇이 문제인가

실행기의 CLI 계정은 계정 폴더(`config_dir`)에 `/login` 으로 남긴 로그인 파일로 돈다. 이 인증은 8시간마다 갱신해야 하는데, 실행기는 한 계정으로 CLI 를 여러 개 동시에 띄우고 계정 묶음은 같은 계정을 여러 연결이 나눠 쓴다. 갱신이 어긋나면 그 계정이 끊긴다.

`claude setup-token` 은 1년 동안 쓰는 토큰을 준다. CLI 는 토큰을 줄 때 `CLAUDE_CODE_OAUTH_TOKEN` 환경변수로 쓰라고 안내하고, 공식 문서도 같다. 로그인 파일은 `/login`, `/logout` 이 관리한다고 적는다. 그런데 실행기에는 이 환경변수로 토큰을 넘기는 길이 없었다.

CR-194 창이 05:49 에 기동 스크립트 `token` 단계를 넣었다(fedf01d8). 1년 토큰을 로그인 파일 모양으로 흉내 내 적는 방식이다. 만료일은 CLI 가 준 값이 아니라 스크립트가 넣은 날에서 센 값이고, CLI 판이 그 파일 모양을 바꾸면 깨지며, 떠 있던 CLI 가 파일을 되돌려 쓸 수 있다(그 단계 주석이 스스로 적었다). 문서에 없는 길이다.

## 3. 1단계 실행기는 1년 토큰으로만 CLI 를 띄운다

### 3.1 토큰 파일

계정 폴더에 `oauth-token.json` 하나를 둔다. 권한은 600 이다.

```json
{"token": "sk-ant-oat01-...", "issued_at": "2026-11-16T06:30:00+09:00", "expires_at": "2027-11-16T06:30:00+09:00"}
```

- `token` 은 `sk-ant-oat01-` 로 시작해야 한다.
- `issued_at`, `expires_at` 은 시간대가 붙은 ISO 시각이다. 넣는 순서가 넣은 시각과 그로부터 1년(`TOKEN_DAYS`, 기본 365일) 뒤를 적는다. 토큰 자체는 기한을 알려 주지 않으므로 넣은 시각이 기준이다.
- 계정 폴더는 연결의 `config_dir` 이다. 없으면 실행기 프로세스의 `CLAUDE_CONFIG_DIR`, 그것도 없으면 `~/.claude` 다. 맥 로컬과 고객 PC 의 기본 계정이 여기에 해당한다.

### 3.2 실행기 동작 (BIZ-283)

1. CLI 를 띄우기 전에 그 계정 폴더의 토큰 파일을 읽는다.
2. 파일이 없거나 읽을 수 없거나 `token` 이 `sk-ant-oat01-` 로 시작하지 않으면 CLI 를 띄우지 않고 `cli_account_token_missing:<계정 폴더>` 로 실패한다.
3. `expires_at` 이 지났으면 `cli_account_token_expired:<계정 폴더>:expires_at=<시각>` 으로 실패한다.
4. 통과하면 CLI 환경에 `CLAUDE_CODE_OAUTH_TOKEN` 을 넣는다. 공식 인증 순서에서 이보다 앞서는 값(`ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`)은 실행기 환경에 있어도 CLI 에 넘기지 않는다. 그래야 넣은 1년 토큰이 실제로 쓰인다.
5. 로그인 파일(`.credentials.json`)은 보지도 고치지도 않는다. 환경변수가 로그인 파일보다 앞서므로 남아 있어도 쓰이지 않는다.
6. 토큰 값은 기록, 오류 메시지, 응답 어디에도 싣지 않는다.

이 검사는 실행기가 CLI 워커를 만드는 두 곳(실행기 모드 `RunnerAutoConfiguration`, 내장 `ClaudeCliAdapterConfig`)에 같이 건다. 워커를 만드는 길은 이 둘뿐이다.

실패는 지금의 CLI 실패와 같은 길로 api 에 간다(`/v1/chat` 은 `{"error": 메시지}`, 스트림은 error 이벤트). 갈래 워커(fork)를 만들다 실패하면 run 자리도 돌려준다. 지금은 입출력 오류일 때만 돌려줘서, 토큰 실패 같은 실행 오류에 자리가 샌다.

api 는 토큰 실패를 계정 한도처럼 다룬다(06:54 결정). 지금은 실행기에 닿은 실패라 `cli_runner_unreachable` 로 감싸고, 연결 묶음은 넘기지 않는 실패로 보아 다른 계정이 멀쩡해도 그대로 실패한다.

1. 어댑터는 실행기 실패에서 `cli_account_token_missing:`, `cli_account_token_expired:` 머리를 찾으면 감싸지 않고 그 머리만 실은 토큰 예외로 올린다. 한도 머리를 먼저 본다.
2. 연결 묶음은 그 머리를 보면 그 멤버를 5분(한도 시각을 모를 때와 같은 간격) 빼고 다음 멤버로 넘긴다. 실행기가 CLI 를 띄우기 전에 거절하므로 같은 일을 두 번 하지 않는다. 모든 멤버가 빠지면 지금처럼 `connection_group_unavailable:retry_after=` 이다.
3. 단일 커넥션 비실시간 요청은 503 에 그 머리 그대로다. 실시간은 SSE 오류로 끝난다. 소비앱에는 API 가이드 § 5, § 25-3 으로 알리고 bp-wes, bp-wms, bp-3plgw 에 알림 문서를 둔다.

근거: 59 의 CLI 2.1.325 에 가짜 값을 `CLAUDE_CODE_OAUTH_TOKEN` 으로 넣으면 로그인 파일이 멀쩡해도 401 이었다(다른 창 실측). 환경변수가 로그인 파일보다 앞선다.

### 3.3 토큰 넣기

토큰은 사람이 받는다. `claude setup-token` 을 치면 주소가 나오고, 맥 브라우저에서 그 계정으로 승인해 받은 코드를 붙여 넣으면 `sk-ant-oat01-` 로 시작하는 값이 한 번 찍힌다. 값은 어디에도 저장되지 않는다.

| 곳 | 방법 |
|---|---|
| 서버(chaws, 59) | `ssh -t <서버> 'cd <aimbase 폴더> && bash build/chaws-bootstrap.sh token <대상 또는 실행기 서비스> <계정>'`. 실행기 컨테이너 안에서 `setup-token` 을 띄우고, 붙여 넣은 값을 계정 폴더의 토큰 파일로 적은 뒤 짧은 질문 하나로 확인한다. 둘째 인자가 대상(`wms`, `wes-cs`, `wes-assist`, `3plgw`)이 아니면 compose 서비스 이름으로 본다(59 의 `aimbase-agent-axopm` 등) |
| 레포가 있는 맥, 리눅스 | `python3 scripts/cli-token.py [계정 폴더]`. setup-token 을 띄우고 붙여 넣은 값을 토큰 파일로 적은 뒤 확인한다. 서버의 `token` 단계도 실행기 컨테이너 안에서 이 파일을 돌린다 |
| 설치 패키지만 있는 PC(맥, 윈도) | `claude setup-token` 으로 값을 받고 계정 폴더에 3.1 의 파일을 손으로 만든다(운용 가이드 시나리오 H) |

붙여 넣는 값은 화면에 보이지 않게 받고, 명령 인자나 기록에 남기지 않는다.

### 3.4 이미 로그인 파일에 넣은 1년 토큰 옮기기

CR-194 단계로 넣었거나 59 `local-agent-1` 처럼 로그인 파일에 1년 토큰이 들어 있는 계정이 있다(`accessToken` 이 `sk-ant-oat01-`, `refreshToken` 이 빈 값). `token` 단계는 그런 계정이면 다시 받지 않고 그 값을 토큰 파일로 옮길지 묻는다. 기한은 로그인 파일의 `expiresAt` 을 쓰고 넣은 시각은 그 1년 전으로 적는다. 로그인 파일은 그대로 둔다.

### 3.5 묶음 구성원

기동 스크립트 `connections` 단계는 계정 폴더 가운데 토큰 파일이 있는 것만 센다. 지금은 로그인 파일이 있는 것을 센다. 토큰을 새로 넣은 뒤 `connections` 를 다시 돌리면 연결과 묶음 구성원이 맞춰진다.

### 3.6 반영 순서

새 실행기는 토큰 파일이 없는 계정을 바로 막는다. 그래서 서버마다 쓰는 계정에 토큰을 먼저 넣고(3.3, 3.4), 실행기를 나중에 다시 올린다. 계정 폴더 `claude-accounts` 를 같이 붙인 실행기들은 하나에서 넣으면 모두에 들어간다. wes-cs, wes-assist 실행기는 59 와 chaws 모두 계정 폴더를 따로 쓰므로(`claude-accounts-wes-cs`, `claude-accounts-wes-assist`) 따로 넣는다. `token` 단계가 쓰는 `cli-token.py` 는 `chaws-bootstrap.sh` 와 같이 서버 `build/` 에 올린다.

## 4. 2단계 화면에서 넣는 토큰과 만료 알림 (BIZ-284, BIZ-289)

### 4.1 누가 무엇을 하나 (07:29, 14:39 결정)

| 순번 | 일 | 하는 사람 |
|---|---|---|
| 1 | 그 Claude 계정으로 `claude setup-token` 을 쳐 브라우저로 승인하고 값을 받는다 | 계정 주인 |
| 2 | 받은 값을 Aimbase 화면에 붙여 넣는다. Aimbase 는 값을 그 연결의 실행기에 넘겨 계정 폴더에 적게 하고, 자기는 남기지 않는다 | 소비앱 계정은 그 테넌트 관리자(연결 관리 화면). Aimbase 가 빌려준 계정은 플랫폼 관리자(실행기 계정 토큰 화면) |
| 3 | 만료 30, 7, 1, 0일 전에 메일과 문자를 받고 1, 2 를 다시 한다 | 소비앱 계정은 그 테넌트의 만료 알림 수신자. Aimbase 계정은 런타임 설정의 수신자 |

토큰은 연결이나 테넌트가 아니라 실행기의 계정 폴더에 붙는다. 실행기가 보는 것이 그 폴더의 토큰 파일 하나이기 때문이다.

- 실행기는 테넌트마다 따로 등록된다. 그래서 테넌트 관리자는 자기 테넌트에 등록된 실행기의 계정 폴더에만 넣을 수 있다.
- 같은 계정을 여러 소비앱이 가져오면(같은 회사) 소비앱마다 자기 실행기 폴더에 넣는다. 같은 값을 여러 폴더에 넣어도 된다. 1년 토큰은 갱신 값이 없어 여러 곳이 같이 써도 서로 어긋나지 않는다.
- 같은 폴더를 쓰는 연결이 여럿이면 하나에서 넣은 토큰을 모두가 쓴다. 화면은 그 연결 수를 함께 보여 준다.
- 지금 운영의 work01~03 은 Aimbase 가 빌려준 계정이고, 서버에서 실행기 여럿이 폴더 하나를 같이 붙인다. Aimbase 는 이 겹침을 연결 정보로 알 수 없다. 그래서 실행기 설정 `aimbase.runner.token-managed-by=platform` 인 실행기의 폴더는 테넌트 관리자가 넣지 못하고(409 `account_token_platform_managed`), 플랫폼 관리자가 실행기 계정 토큰 화면에서 넣는다(14:39 결정). 테넌트 화면에는 「Aimbase 관리」 로 보인다.
- 사용자 PC 실행기(연결에 `agent_name` 이 없는 것)는 PC 주인이 `scripts/cli-token.py` 로 넣는다. 화면 대상이 아니다.
- 서버 `token` 단계(3.3)는 실행기를 처음 세울 때와 화면을 쓸 수 없을 때를 위해 남긴다.

### 4.2 실행기 토큰 API

머리글 `X-Api-Key`(실행기 호출 키). 토큰 값은 응답과 기록에 싣지 않고, 요청 본문도 기록하지 않는다.

| 순번 | 요청 | 하는 일 | 응답 |
|---|---|---|---|
| 1 | `GET /v1/account-token?config_dir=<계정 폴더>` | 토큰 파일을 읽는다. `config_dir` 을 비우면 3.1 의 기본 계정 폴더 | `{config_dir, present, issued_at, expires_at, managed_by}` |
| 2 | `PUT /v1/account-token` 본문 `{config_dir, token, by}` | `by` 는 `tenant` 또는 `platform` 이고 api 가 정한다. `managed_by=platform` 인데 `by=tenant` 이면 409 `account_token_platform_managed`. 값이 `sk-ant-oat01-` 로 시작하지 않으면 400 `account_token_invalid`. 그 값으로 짧은 질문 하나를 CLI 에 던져(앞서는 인증 다섯을 뺀 환경, 모델은 `aimbase.runner.token-verify-model`) 답이 오면 토큰 파일을 600 으로 바꿔 적는다. 답이 없으면 파일을 그대로 두고 400 `account_token_rejected` | 1 과 같다 |

새로 적는 파일의 `issued_at` 은 지금, `expires_at` 은 지금부터 `aimbase.runner.token-days`(기본 365)일 뒤다. 이미 떠 있는 워커는 쓰던 값으로 그 실행을 마치고, 새 워커부터 새 값을 쓴다. 기한 전에 바꾸므로 쓰던 값도 그때까지 살아 있다.

### 4.3 Aimbase 테넌트 API

| 순번 | 요청 | 하는 일 |
|---|---|---|
| 1 | `GET /api/v1/cli-account-tokens` | 이 테넌트의 서버 실행기 연결을 `(agent_name, config_dir)` 로 묶어 실행기마다 4.2-1 로 함께 묻는다(한 곳당 `aimbase.cli-token.query-timeout`, 기본 5초). 줄마다 `{agent_name, config_dir, managed_by, present, issued_at, expires_at, days_left, reachable, connection_ids}`. 꺼진 실행기는 `reachable=false` 로 둔다. 결과를 4.8-3 에 적는다 |
| 2 | `GET /api/v1/connections/{id}/account-token` | 그 연결 하나로 1 과 같은 한 줄 |
| 3 | `PUT /api/v1/connections/{id}/account-token` 본문 `{token}` | 그 연결의 실행기에 4.2-2 로 넘긴다. `by` 는 임퍼소네이션 토큰(CR-096, `impersonating=true`)이면 `platform`, 아니면 `tenant`. 결과를 4.8-3 에 적는다. 감사 기록(BIZ-020)에는 누가(임퍼소네이션이면 플랫폼 관리자), 어느 연결, 새 기한만 남긴다 |
| 4 | `GET /api/v1/cli-token-recipients`, `PUT` 본문 `{emails: [], phones: []}` | 이 테넌트의 만료 알림 수신자 |

2, 3 은 `anthropic-cli` 연결이고 `config.agent_name` 이 있을 때만 된다. 아니면 400 `account_token_not_server_runner`. 실행기가 꺼져 있으면 503 `cli_runner_unreachable:AGENT_OFFLINE:`, 없는 연결은 404. 3 은 실행기가 확인 질문의 답을 기다리므로 연결 호출 시간 제한 `platform.llm.anthropic-cli.http-timeout-seconds`(기본 300초)까지 기다린다. 테넌트 관리자 권한이다.

### 4.7 발송과 런타임 설정

bp-notification 의 `POST /api/v1/messages/email`, `POST /api/v1/messages/sms` 로 보낸다. 양식 코드는 런타임 설정에서 읽고, 변수는 `runner`(실행기 이름), `account`(계정 폴더 이름), `expiresOn`(만료일 yyyy-MM-dd), `daysLeft`(남은 날) 넷이다. 수신자가 비어 있는 채널은 보내지 않는다. 둘 다 비어 있으면 보낸 기록을 남기지 않아, 나중에 수신자를 채우면 그날 보낸다. bp-notification 주소와 키는 api 환경의 `notification.base-url`, `notification.api-key` 다(내장 도구 `send_notification` 과 같은 값). 키가 비어 있거나 한 통이라도 실패하면 보낸 기록을 남기지 않아 다음 확인에서 다시 보낸다. 한 통을 기다리는 시간은 `aimbase.runner.token-expiry.send-timeout`(기본 10초)이다.

| 키 (분류 runner) | 기본값 | 뜻 |
|---|---|---|
| `runner.token_expiry.notify_days` | `30,7,1,0` | 만료 며칠 전에 알릴지 |
| `runner.token_expiry.emails` | 빈 값 | Aimbase 관리 계정의 수신 메일 주소(쉼표) |
| `runner.token_expiry.phones` | 빈 값 | Aimbase 관리 계정의 수신 휴대폰 번호(쉼표) |
| `runner.token_expiry.email_template` | `AIMBASE_CLI_TOKEN_EXPIRY_EMAIL` | bp-notification 메일 양식 코드 |
| `runner.token_expiry.sms_template` | `AIMBASE_CLI_TOKEN_EXPIRY_SMS` | bp-notification 문자 양식 코드 |

### 4.9 bp-notification 에 요청할 것
