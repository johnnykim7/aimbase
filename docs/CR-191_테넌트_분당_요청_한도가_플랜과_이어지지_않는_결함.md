## 1. 배경

- 2026-11-14 Lexflow 서면 초안 시험 중 59(aimbase.banpoom.co.kr)에서 `lexflow` 요청이 429 로 거절됐다. 응답 머리 `X-RateLimit-Limit: 60`, `Retry-After: 6`
- `lexflow` 는 `plan=pro`, `api_rpm_limit=60` 이었다. 11:33 사용자 승인으로 구독 변경 API 를 불러 300 으로 올렸다. 이 값은 되돌리지 않는다
- 같은 증상의 앞 건이 11-03 chaws `bp_wms`(60 에서 600, CR-167 7.8절)다. CR-169 는 값을 바꾸는 길을 냈고, 처음 값이 플랜을 따르지 않는 것은 남았다

## 2. 원인 (코드 확인 2026-11-14)

플랜은 이름표일 뿐이고, 코드 어디에도 플랜을 보고 한도를 정하는 곳이 없다.

| 순번 | 자리 | 지금 동작 | 근거 |

플랜과 이어지지 않는 것은 분당 요청 한도만이 아니다. 월 토큰 한도, 최대 연결 수, 지식 소스 수, 워크플로 수, 저장 용량도 엔티티 기본값으로 시작한다. 이 건은 요청대로 분당 요청 한도만 다룬다(9절).

## 4. 결정

### 결정 1. 플랜과 한도를 잇는 방식

1. 플랜별 기본 한도를 운영 설정에 두고, 테넌트를 만들 때와 플랜을 바꿀 때 그 값을 한도에 넣는다. 테넌트마다 따로 정할 값은 지금처럼 구독 변경으로 바꾼다(권장)
2. 한도를 플랜과 무관한 테넌트 값으로 둔다. 만들 때는 설정값 하나로 시작하고 플랜은 이름으로만 남는다(잃는 것: 플랜을 올려도 한도가 그대로라 오늘 같은 거절을 플랜으로 막을 수 없고, pro 인 workmap 이 60 인 지금 상태가 테넌트마다 계속 생긴다)

### 결정 2. 플랜 이름

1. free, starter, pro, enterprise 넷으로 맞추고, 목록은 운영 설정에서 읽는다. 화면의 standard 는 없앤다. standard 로 저장된 행(59 `flowguard_dev`, 로컬 2행)은 같은 가운데 등급인 starter 로 옮기고 한도는 건드리지 않는다(권장)
2. 화면의 이름(free, standard, enterprise)으로 맞춘다(잃는 것: 59 의 pro 4행, starter 1행과 V12 의 값 대응을 모두 바꿔야 하고, 운영 `lexflow` 의 pro 가 없는 이름이 된다)

## 5. 설계 (결정 1, 2 의 ① 기준, 승인 뒤 확정)

### 5.1 운영 설정

master `global_config` 에 둔다. 마이그레이션은 `ON CONFLICT DO NOTHING` 으로 넣어 운영에서 바꾼 값을 덮지 않는다.

| 순번 | 키 | 처음 값 | 뜻 |
|---|---|---|---|
| 1 | `plan.codes` | `free,starter,pro,enterprise` | 플랜 목록. 적힌 순서가 화면 순서다 |
| 2 | `plan.default` | `free` | 플랜 없이 테넌트를 만들 때의 플랜 |
| 3 | `plan.free.api-rpm-limit` | 60 | 그 플랜의 분당 요청 한도. 0 은 무제한 |
| 4 | `plan.starter.api-rpm-limit` | 300 | |
| 5 | `plan.pro.api-rpm-limit` | 1000 | |
| 6 | `plan.enterprise.api-rpm-limit` | 0 | |

- 운영 설정 화면에 「플랜」 묶음으로 보이고 값을 바꿀 수 있다
- 저장할 때 거절하는 값: 한도가 0 이상의 정수가 아님, `plan.default` 가 목록에 없음, 목록에 한도 키가 없는 이름이 있음, 목록이 비었음
- 플랜을 새로 더하려면 한도 키 행이 있어야 해서 마이그레이션으로 한다

### 5.4 플랜 목록 API (새)

`GET /api/v1/platform/plans` 는 플랜 목록 순서대로 이름과 분당 요청 한도, 그리고 기본 플랜을 준다. 화면은 이 목록으로 생성 창의 선택지와 처음 선택을 채운다.

### 5.5 한도 판정

구독 행이 없는 테넌트는 `plan.default` 의 한도를 쓴다. 설정 행이 아직 없는 서버(마이그레이션 전)를 위해 코드의 60 은 그때만 남긴다(CR-168 과 같은 방식).
