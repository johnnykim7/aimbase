## 3. 서버

### 3.1 문서 그리기 (공통) [PRD-500, PRD-501, PRD-502]

마크다운을 HTML, DOCX, PDF 로 바꾸는 부품 하나를 두고 3.2 ~ 3.5 가 같이 쓴다.

| 순번 | 출력 | 방법 |
|---|---|---|
| 1 | 마크다운 해석 | commonmark-java 와 GFM 표, 취소선, 자동 링크 확장. 마크다운 안의 HTML 은 글자로 바꾸고(escapeHtml), 위험한 링크 주소(javascript: 등)는 지운다(sanitizeUrls) |
| 2 | HTML | 스타일을 품은 한 장. 스크립트, 외부 파일 없음. 무채색, 표 테두리, 코드 블록 고정폭 |
| 3 | PDF | 2 의 HTML 을 openhtmltopdf(PDFBox 위)로 A4 에 그린다. 한글 글꼴을 등록한다 |
| 4 | DOCX | POI XWPF 로 해석 결과를 바로 옮긴다. 제목 1 ~ 6, 문단, 굵게, 기울임, 인라인 코드, 글머리와 번호 목록(겹친 목록 포함), 표(머리 행 굵게), 코드 블록(고정폭, 회색 바탕), 인용, 링크, 가로줄 |

- 마크다운 이미지가 외부 주소면 그리지 않고 링크로 남긴다. PDF 를 그리는 동안 서버가 바깥 주소로 요청을 보내지 않게 한다.
- 수식, 그래프, 머메이드 코드 블록은 코드 블록 그대로 옮긴다(1.2 의 3).
- PDF 글꼴 폴더는 설정 `aimbase.document.pdf-font-dir`(환경변수 `AIMBASE_DOCUMENT_PDF_FONT_DIR`, 기본 `/usr/share/fonts/truetype/nanum`). api 이미지에 `fonts-nanum` 을 깐다. 폴더에 글꼴이 없으면 PDF 요청만 503 `pdf_font_missing` 이고 다른 형식은 돈다.

### 3.2 파일 만들기 서버 도구 `create_file` [PRD-500, BIZ-210]

모델이 부르는 서버 도구. API 연결은 도구 고리로, CLI 연결은 서버 MCP 로 같은 도구를 부른다. 서버가 그려서 세션 작업 폴더의 `out/` 에 쓰므로 실행기 볼륨이 달라도 파일이 위젯에 닿는다(2절 3, 4).

입력:

```json
{"file_name": "3분기 반품 현황", "format": "xlsx", "title": "3분기 반품 현황",
 "content": "# 요약\n...",
 "sheets": [{"name": "요약", "rows": [["항목", "건수"], ["반품", 12]]}],
 "slides": [{"title": "3분기 반품", "bullets": ["반품 12건", "교환 3건"], "notes": "말할 거리"}],
 "overwrite": false}
```

| format | 쓰는 칸 | 만드는 법 |
|---|---|---|
| docx, pdf | content(마크다운), title | 3.1. title 이 있으면 맨 위 제목 |
| md, txt | content | 그대로 UTF-8 |
| html | content(마크다운), title | 3.1 의 HTML |
| xlsx | sheets | POI XSSF. 첫 행 머리(굵게, 고정), 열 너비 맞춤, 숫자로 읽히는 글은 숫자 칸 |
| csv | sheets 첫 장, 없으면 content | UTF-8 BOM(엑셀에서 한글이 깨지지 않게) |
| pptx | slides, title | POI XSLF, 16:9. title 이 있으면 표지 한 장, 장마다 제목과 글머리, notes 는 발표자 메모 |

- 파일 이름: 경로 문자(`/ \ : * ? " < > |`), 앞 점, 제어 문자를 지우고 120자로 자른다. 확장자는 format 이 붙인다. 같은 이름이 있으면 `overwrite` 가 false 일 때 `이름 (2).xlsx` 처럼 번호를 붙이고, true 면 바꿔 쓴다.
- 원본 저장: 도구 입력을 그대로 `out/.source/<파일 이름>.json` 에 쓴다. CR-181 이 옆 창 문서를 대화로 고칠 때 이 원본을 읽어 고친 판을 `overwrite: true` 로 다시 만든다. 지움 주기(24시간)는 파일과 같다(CR-132 지움 작업이 `out/.source/` 안까지 지운다). 위젯 목록과 다운로드에는 나오지 않는다.
- 저장 위치: 세션 작업 폴더의 `out/`. 세션에 작업 폴더가 없으면 이때 `{base}/chat/{session_id}` 를 잡는다(연결 종류와 관계없이). 서버 MCP 로 부르면 실행기가 보낸 작업 폴더를 쓰고, 그 폴더가 허용 폴더 밖이면 거절한다.
- 한도: 만든 파일 크기 상한 런타임 설정 `chat.file-create.max-bytes`(기본 20971520, 20MB). 넘으면 쓰지 않고 `file_too_large`.
- 결과: `{"file_name": "3분기 반품 현황.xlsx", "size": 10240}`. 끝 이벤트 `artifacts` 는 CR-132 대로 `out/` 을 훑어 싣는다.

| 오류 (도구 결과) | 경우 |
|---|---|
| `file_invalid:format` | 표에 없는 형식 |
| `file_invalid:content` | 형식에 필요한 칸이 없거나 비었다(xlsx 에 sheets 없음 등) |
| `file_invalid:file_name` | 지우고 나니 이름이 비었다 |
| `file_too_large` | 크기 상한을 넘었다 |
| `pdf_font_missing` | PDF 글꼴이 없다 |
| `file_create_disabled` | 런타임 설정으로 꺼져 있다 |
| `file_no_workspace` | 세션 작업 폴더를 잡지 못했다(기본 위치가 비었거나, 실행기가 보낸 폴더가 허용 폴더 밖) |
| `file_write_failed` | 디스크에 쓰지 못했다 |

도구 설명(모델에게 보이는 글)은 프롬프트 틀 `tool.create-file.description` 으로 뺀다. 요지: 사용자가 파일(워드, PDF, 엑셀, PPT, CSV)을 달라고 할 때만 부른다. 이 도구로 만든 파일만 사용자 화면에 내려받기로 뜬다. 답 본문에는 파일 내용을 다시 늘어놓지 않고 무엇을 만들었는지만 짧게 쓴다.

#### 3.2.1 도구를 주는 조건

| 순번 | 경우 | 동작 |
|---|---|---|
| 1 | 대화 요청에 `file_create: true`, 런타임 설정 `chat.file-create.enabled` 켬 | API 연결: `actions_enabled` 가 없어도 도구 고리를 돌리되 도구는 `create_file` 하나만 싣는다. `actions_enabled` 면 다른 도구와 함께. CLI 연결: 실행기에 보내는 허용 도구 목록(요청 도구 > 연결 `exposed_tools`)에 `create_file` 을 더한다. 목록이 비어 전체를 여는 연결은 그대로 둔다(서버 MCP 노출 목록에 `create_file` 을 더한다) |
| 2 | `file_create` 가 없거나 false | 지금과 같다. 붙이는 앱의 서버 호출(CS 초안 등)이 바뀌지 않는다 |
| 3 | 설정이 꺼짐 | `file_create` 를 무시한다. 도구를 부르면 `file_create_disabled` |

- 위젯은 위젯 설정(3.6)의 `file_create_enabled` 가 참이면 대화 요청마다 `file_create: true` 를 싣는다.
- 도구 고리 최대 5회(BIZ-001)는 그대로다.

### 3.3 응답 저장 [PRD-501, BIZ-211]

`GET /api/v1/chat/sessions/{session_id}/turns/{turn_id}/export?format=pdf|docx&tz=`

- CR-175 의 답 번호로 그 대화 요청이 만든 응답 메시지를 모아(도구 결과, 생각은 빼고 응답 글만) 3.1 로 그려 바로 내려준다. 서버에 남기지 않는다.
- 세션 주인 대조는 CR-175 답 찾기(`ChatTurnLookup`)를 쓴다. 남의 세션이거나 없는 답이면 404 `turn_not_found`.
- 파일 이름: `<대화 제목>_<응답 시각 yyyyMMdd-HHmm>.pdf`. 시각은 쿼리 `tz`(IANA 이름, 위젯이 보는 사람 시간대를 싣는다. 없거나 틀리면 런타임 설정 `chat.export.default-timezone`, 기본 `Asia/Seoul`)로 적는다. Content-Disposition attachment, UTF-8 이름.
- 맨 위에 대화 제목, 응답 시각, 답한 모델 이름을 적는다. 질문은 넣지 않는다(응답 하나를 저장하는 기능).

| 오류 | 경우 |
|---|---|
| 400 `export_invalid:format` | pdf, docx 가 아님 |
| 404 `turn_not_found` | 없는 답, 남의 세션 |
| 503 `pdf_font_missing` | 3.1 |

### 3.4 대화 내보내기 [PRD-502, BIZ-211]

`GET /api/v1/chat/sessions/{session_id}/export?format=pdf|docx|md&tz=`

- 세션의 살아 있는 메시지(지운 표시 없는 것)를 순서대로 질문, 응답 쌍으로 그린다. 질문은 「질문」, 응답은 「응답」 머리와 시각을 단다. 첨부는 이름만 적는다. 생각, 도구 사용은 뺀다.
- 맨 위에 대화 제목, 내보낸 시각, 메시지 수.
- 세션 주인이 아니면 404 `session_not_found`. 메시지가 없으면 409 `export_empty`.
- 파일 이름 `<대화 제목>_<내보낸 시각>.<형식>`. 나머지는 3.3 과 같다.

### 3.5 공유 링크 [PRD-503, PRD-504, BIZ-212, BIZ-213]

공유는 그 순간의 사본(스냅샷)을 나눈다. 링크를 만든 뒤 대화가 이어지거나 파일이 지워져도 받는 사람은 만든 순간의 것을 본다.

#### 3.5.1 만들기

`POST /api/v1/chat/shares`

```json
{"session_id": "cs-9471-...", "kind": "CONVERSATION"}
{"session_id": "cs-9471-...", "kind": "FILE", "file_name": "3분기 반품 현황.xlsx"}
```

| kind | 사본 |
|---|---|
| CONVERSATION | 3.4 의 대화를 3.1 HTML 로 그린 한 장 |
| FILE | 그 세션 `out/` 의 파일을 복사 |

- 사본은 `{base}/shares/{tenant_id}/{share_id}/` 에 둔다. 작업 폴더 밖이라 24시간 지움(CR-132)과 무관하다.
- 링크 주소 `{공개 주소}/share/{tenant_id}/{token}`. token 은 32바이트 난수를 URL 안전 base64 로(43자). 공개 주소는 런타임 설정 `chat.share.public-base-url`. 한 Aimbase 의 테넌트는 같은 공개 주소를 쓴다(운영 chaws 의 bp_wms, bp_wes, bp_3plgw 모두 `ai.banpoom.co.kr`). 비어 있으면 공유를 만들지 않고 409 `share_not_configured`.
- 기한: 런타임 설정 `chat.share.ttl-days`(기본 7). 요청에 `ttl_days` 를 주면 1 ~ `chat.share.max-ttl-days`(기본 30) 안이어야 하고, 밖이면 400 `share_invalid:ttl_days`.
- 같은 세션, 같은 대상에 살아 있는 링크가 있어도 새로 만든다. 대화는 만든 시점마다 사본이 다르기 때문이다.
- kind 가 둘 중 하나가 아니면 400 `share_invalid:kind`, FILE 인데 이름이 없으면 400 `share_invalid:file_name`.
- 세션 주인이 아니면 404 `session_not_found`, 파일이 없거나 이름에 경로가 섞였으면 404 `file_not_found`. 대화가 비었으면 409 `export_empty`. 사본을 쓰지 못하면 503 `share_write_failed`.
- 응답: `{"share_id", "url", "kind", "file_name", "status", "view_count", "expires_at", "created_at", "revoked_at"}`(3.5.2 목록 행과 같은 모양). 시각은 시간대 오프셋을 붙인 ISO-8601.

#### 3.5.2 목록과 끊기

- `GET /api/v1/chat/shares?session_id=` 그 세션에 내가 만든 링크. 끊긴 것, 기한 지난 것도 상태와 함께 보인다(최근 20개).
- `DELETE /api/v1/chat/shares/{share_id}` 끊기. 주인만, 남의 링크이거나 없으면 404 `share_not_found`. 사본 파일을 바로 지운다. 이미 끊긴 것은 그대로 200.

#### 3.5.3 열기 (받는 사람, 공개 경로)

`GET /share/{tenant_id}/{token}`

- 로그인, 토큰 없이 연다. 테넌트 머리글을 받지 않고 경로의 tenant_id 로 그 테넌트 DB 를 고른다. 테넌트가 없거나 꺼져 있으면 404.
- 대화: 사본 HTML 을 그대로 보인다. 머리글 `Content-Security-Policy: sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex`, `Cache-Control: no-store`. 스크립트가 돌지 않고 이 주소의 다른 화면과 저장값에 닿지 못한다. 사본 맨 위에 「공유한 대화」와 기한을 적는다. 사본 안 시각은 받는 사람 시간대를 알 수 없어 `chat.export.default-timezone` 으로 적는다.
- 파일: attachment 로 내려준다(이름, 형식은 3.5.1 사본 그대로). HTML 파일도 attachment 다.
- 없는 token, 끊긴 링크, 기한 지난 링크는 모두 같은 404 화면 「링크가 없거나 끝났습니다」. 무엇 때문인지 밝히지 않는다.
- 열 때마다 `view_count` 를 하나 올리고 `last_viewed_at` 을 적는다.
- 같은 주소에서 분당 열기 한도 런타임 설정 `chat.share.open-rate-per-minute`(기본 60). 넘으면 429 와 같은 화면. 주소는 운영 nginx 가 싣는 `X-Real-IP`, 없으면 바로 붙은 주소. 기존 토큰 버킷(Redis)을 같이 쓰고, Redis 가 안 되면 막지 않는다.

#### 3.5.4 지우기

- 매 1시간 기한이 지난 링크의 사본 파일을 지운다(행은 남긴다, `files_purged_at`).
- 세션을 지우면 그 세션의 살아 있는 링크를 끊는다.

## 4. 위젯

위젯 코드는 CR-177(위젯 틀 나누기)이 dev 에 들어간 뒤 그 틀의 더보기, 응답 아래 줄 자리에만 붙인다. 화면은 T3-3 컨셉(2026-11-13 승인, 목업 없이 진행)을 따른다.

| 순번 | 자리 | 들어가는 것 |
|---|---|---|
| 1 | 응답 아래 줄 | 「저장」 단추. 누르면 PDF, 워드 두 줄 메뉴. 고르면 3.3 을 받아 저장한다. 받는 동안 단추에 도는 표시, 실패하면 「저장하지 못했습니다」 |
| 2 | 머리줄 더보기 | 「대화 내보내기」(PDF, 워드, 마크다운), 「공유 링크 만들기」. 대화가 비었으면 둘 다 흐리게 |
| 3 | 파일 칩 | 지금처럼 누르면 다운로드. 칩 끝에 「공유」 작은 단추(틀 자리 `ctx.ui.answer.addArtifactAction`, 틀 가이드 1.1 의 3절) |
| 4 | 공유 창 | 위젯 안 작은 창. 무엇을 공유하는지(대화 제목 또는 파일 이름), 「링크를 가진 사람은 누구나 볼 수 있습니다. 기한 N일」, 「링크 만들기」. 만든 뒤 링크 칸, 「복사」, 기한, 「링크 끊기」. 이 세션에서 만든 링크 목록(상태, 기한, 열린 수) |

- 위젯 설정의 `share_enabled` 가 거짓이면 공유 단추를 두지 않는다. `file_create_enabled` 가 참이면 대화 요청에 `file_create: true` 를 싣는다.
- 새 문구는 CR-177 문구표에 넣는다.
- 붙이는 앱 옵션은 더하지 않는다.
