## 3. 서버

### 3.1 첨부 종류 [PRD-520, BIZ-220]

| 순번 | 종류 | 확장자 | 판정 | 저장 media_type | 크기 상한 설정 |
|---|---|---|---|---|---|
| 1 | 이미지 | png, jpg, jpeg, gif, webp | 지금과 같다 | 지금과 같다 | `widget.attachment.max-image-bytes` |
| 2 | PDF | pdf | 지금과 같다 | `application/pdf` | `widget.attachment.max-pdf-bytes` |
| 3 | 엑셀 | xlsx | zip 머리(50 4B 03 04)이고 안에 `xl/workbook.xml` 이 있다 | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | `widget.attachment.max-data-bytes` |
| 4 | 엑셀 옛 형식 | xls | OLE 머리(D0 CF 11 E0)이고 POI 가 통합 문서로 연다 | `application/vnd.ms-excel` | `widget.attachment.max-data-bytes` |
| 5 | CSV | csv | 글 파일 판정 | `text/csv` | `widget.attachment.max-data-bytes` |
| 6 | TSV | tsv | 글 파일 판정 | `text/tab-separated-values` | `widget.attachment.max-data-bytes` |
| 7 | 워드 | docx | zip 머리이고 안에 `word/document.xml` 이 있다 | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | `widget.attachment.max-text-bytes` |
| 8 | 텍스트 | txt, md | 글 파일 판정 | `text/plain`, `text/markdown` | `widget.attachment.max-text-bytes` |

- 3 ~ 6 을 이 문서에서 데이터 파일이라 한다(원본 37번의 말).
- 글 파일 판정: 앞 8KB 에 NUL 바이트가 없어야 한다. UTF-8(BOM 허용)로 해석되면 UTF-8, 아니면 CP949 로 해석되면 CP949 로 읽는다. 둘 다 아니면 거절한다. 엑셀에서 저장한 한글 CSV 가 CP949 다.
- 3 ~ 8 은 확장자로 종류를 정하고 내용이 그 종류인지 확인한다. 브라우저와 운영체제마다 보내는 Content-Type 이 달라(윈도우는 CSV 를 `application/vnd.ms-excel` 로 보낸다) 머리글 대조는 하지 않는다. 이미지, PDF 는 지금처럼 머리글을 대조한다.
- 받지 않는 확장자는 400 `FG-ATT-4001`, 확장자와 내용이 다르면 422 `FG-ATT-4221`(지금 코드 체계, CR-061).
- 엑셀, 워드는 올릴 때 한 번 열어 본다. 암호가 설정된 파일 400 `FG-ATT-4003`, 열리지 않는 파일 400 `FG-ATT-4004`. 데이터 파일은 표마다 행, 열 수를 세어 상한을 넘으면 400 `FG-ATT-4005`(행), `FG-ATT-4006`(열).
- 첨부 오류는 전용 처리기로 `{"success": false, "error": "<사유 글>", "code": "FG-ATT-....", "limit": N}` 을 돌려준다. `limit` 은 크기(`FG-ATT-4002`), 행, 열 상한으로 거절했을 때만 싣는다. 위젯은 `code` 로 문구를 고르고 「최대 N」 을 보인다.
- 저장은 지금 chat_attachments 그대로다. 원본 바이트를 두고, 읽을 때마다 같은 규칙으로 판정한다. 세션당 첨부 개수 상한(`widget.attachment.max-per-session`)과 보관 기간(`widget.attachment.ttl-seconds`)은 종류와 상관없이 지금과 같다.

### 3.2 모델에 보내는 모양 [PRD-520, PRD-521, BIZ-221]

위젯은 이미지가 아닌 첨부를 모두 `document` 블록(`attachment_id`)으로 보낸다. 서버는 저장된 종류로 나눈다.

| 순번 | 종류 | 모델에 가는 것 |
|---|---|---|
| 1 | PDF | 지금과 같다(비전, 페이지 이미지, 글 폴백) |
| 2 | 워드, 텍스트 | 글 블록 하나. 첫 줄 `[첨부 문서: <이름>]`, 다음 줄부터 본문. 워드는 문단 순서대로 읽고 표는 마크다운 표로 바꾼다. `widget.attachment.max-text-chars` 를 넘으면 앞부분만 싣고 끝에 `[앞 N자만 보냄, 전체 M자]` |
| 3 | 데이터 파일 | 글 블록 하나(데이터 요약). 아래 |

데이터 요약:

```
[첨부 데이터 파일: 11월_매출.xlsx, file_id 3f2a9c1e-...]
표 t1 (시트 "서울"): 1,240행
  열: "일자" 날짜, "지점" 글, "매출액" 숫자, "건수" 숫자
  앞 20행:
  | 일자 | 지점 | 매출액 | 건수 |
  | --- | --- | --- | --- |
  | 2026-11-01 | 강남 | 1250000 | 31 |
표 t2 (시트 "부산"): 830행
  ...
(widget.data.guide 틀 본문)
```

- 모든 표의 행 합이 `widget.data.inline-rows` 이하면 표마다 전체 행을, 넘으면 표마다 앞 `widget.data.preview-rows` 행을 싣는다.
- `widget.data.guide` 는 테넌트 프롬프트 틀이다. 합계, 평균, 건수, 순위 같은 값은 반드시 `data_query` 로 계산하고 계산한 값만 응답에 쓰라는 안내, SQL 방언(H2, PostgreSQL 호환 모드), 표와 열 이름을 큰따옴표로 감싸라는 안내다. 그 연결이 도구를 받지 않는 어댑터면 틀을 붙이지 않는다.
- 이 요약은 그 질문 메시지의 일부로 대화 기록에 남는다. 다음 질문에서도 모델이 같은 file_id 로 계산한다(보관 기간 안).

### 3.3 표로 읽는 규칙 [BIZ-221]

| 순번 | 항목 | 규칙 |
|---|---|---|
| 1 | 표 | 비지 않은 시트 하나가 표 하나다. 이름은 시트 순서대로 t1, t2. CSV, TSV 는 t1 하나다 |
| 2 | 머리 행 | 시트의 첫 번째 비지 않은 행이다. 빈 머리 칸은 `c<열 순번>`, 같은 이름이 또 나오면 뒤에 `_2`, `_3` |
| 3 | 행 | 머리 행 다음부터 마지막 값이 있는 행까지. 모든 칸이 빈 행은 넣지 않는다 |
| 4 | 칸 값 | 수식 칸은 엑셀이 저장해 둔 결과 값이다. 병합된 칸은 왼쪽 위 칸에만 값이 있다. 날짜 서식 숫자는 날짜다 |
| 5 | 열 형 | 빈 칸을 제외한 값이 모두 숫자면 숫자(DECFLOAT, 정확한 십진수), 모두 날짜면 날짜(시각이 있으면 TIMESTAMP), 그 밖은 글이다. 천 단위 쉼표만 있는 숫자 글("1,234")은 숫자로 본다. 퍼센트 글("12%")은 글이다 |
| 6 | 시각 | 날짜는 시간대 없는 값이다(엑셀 값 그대로). 시간대를 붙이지 않는다 |
| 7 | 상한 | 표 하나 `widget.data.max-rows` 행, `widget.data.max-columns` 열 |

### 3.4 data_query 도구 [PRD-521, BIZ-222]

| 항목 | 내용 |
|---|---|
| 이름 | `data_query` |
| 입력 | `file_id`(첨부 id), `sql`(SELECT 또는 WITH 로 시작하는 한 문장) |
| 출력 | `columns`([{name, type}]), `rows`, `truncated`, `elapsed_ms` |
| 오류 | 문장 오류, 없는 표나 열, 시간 초과는 도구 결과의 오류 글로 돌려준다. 모델이 고쳐 다시 부른다 |

실행 순서:

1. ToolContext 의 세션으로 첨부 소유를 확인한다(AttachmentService.loadOwned). 세션이 없거나, 다른 세션 파일이거나, 보관 기간이 지났거나, 데이터 파일이 아니면 `file not found`.
2. 3.3 규칙으로 표를 만든다.
3. 이 호출만을 위한 메모리 DB(H2, 이름은 임의 UUID, PostgreSQL 호환 모드)를 열고 관리 계정으로 표를 만들어 행을 넣는다.
4. 관리 권한이 없는 조회 계정을 만들어 표에 SELECT 권한만 주고 그 계정 연결로 문장을 실행한다. 관리 권한이 없으면 파일 읽고 쓰기(FILE_READ, FILE_WRITE, CSVREAD, CSVWRITE), 다른 DB 연결(LINK_SCHEMA), 함수 만들기(CREATE ALIAS), 스크립트 실행(RUNSCRIPT, SCRIPT)이 막힌다.
5. 문장 검사: 앞뒤 빈칸과 끝 세미콜론 하나를 제외하고 SELECT 또는 WITH 로 시작하지 않거나 세미콜론이 더 있으면 실행하지 않는다. 실행은 결과 집합만 받는 호출(executeQuery)이라 결과가 없는 문장은 DB 가 거절한다.
6. 시간 상한 `widget.data.query-timeout-seconds`(문장 시간 제한). 결과는 `widget.data.max-result-rows` + 1 행까지만 읽어 넘으면 `truncated` 다. 칸 글은 200자에서 자른다. 결과 JSON 이 `widget.data.max-result-bytes` 를 넘으면 행을 줄여 맞추고 `truncated`.
7. DB 를 닫아 메모리에서 지운다.

- 도구 호출은 지금 도구 실행 기록 경로에 남는다(BIZ-020).
- 계산 엔진으로 H2 를 쓴다. 순수 자바 2.6MB, 메모리 DB 이고 계정 권한으로 파일과 바깥 접근을 막는다. DuckDB 는 분석 SQL 이 더 넓지만 jar 가 73MB 이고 플랫폼별 네이티브 라이브러리를 싣는다. 파이썬 실행은 2절 3번 때문에 두지 않는다(실행 컨테이너가 운영 chaws 에 없고 표 계산 패키지가 없다).

### 3.5 도구를 붙이는 곳 [BIZ-222]

| 순번 | 연결 | 붙는 조건 | 길 |
|---|---|---|---|
| 1 | API(Anthropic, OpenAI, Ollama) | 그 세션에 보관 중인 데이터 파일이 있을 때 도구 목록에 넣는다. 요청 `tool_filter.exclude_tools` 에 있으면 넣지 않고, `allowed_tools` 와 세션 활성 목록에 없어도 더한다(도구 고르기 맥락의 붙이는 도구 `attachedTools`) | 도구 정의(getToolDefs) |
| 2 | CLI NATIVE, AIMBASE, HYBRID | 대화 API 에서 온 요청이면 붙인다 | 신규 통로 aimbase-data(`/mcp-data`). `data_query` 하나만 싣는다. 허용 도구 목록이 있으면 `mcp__aimbase-data__data_query` 를 더한다 |

- 구현 보정(2026-11-13): 처음 설계는 AIMBASE, HYBRID 를 기존 `/mcp` 허용 목록에 더하는 길이었다. `/mcp` 는 노출 등급이 없는 도구를 걸러 내고 세션 번호가 없어 계산 도구를 부를 수 없으므로 세 방식 모두 `/mcp-data` 로 붙인다.
- `actions_enabled=false` 인 대화도 데이터 파일이 있으면 `data_query` 하나만 실은 도구 반복으로 답한다. 도구를 끈 대화에서 계산이 막히면 그래프 숫자를 모델이 지어낸다.

- CLI 작업자는 세션마다 하나이고 기동할 때의 MCP 설정을 계속 사용한다. 대화 중간에 데이터 파일을 올려도 도구가 있어야 하므로 CLI 는 파일이 있는지 보지 않고 대화 요청이면 붙인다. 워크플로우 단계 요청에는 붙이지 않는다.
- 세션 번호는 실행기가 MCP 항목 머리글 `X-Aimbase-Session-Id` 로 싣는다(스킬 지정 머리글 `X-Aimbase-Skill-Set` 과 같은 자리, T3-17 3.8). 서버 필터가 RequestContext 에 두고 ServerMcpToolDispatcher 가 ToolContext.sessionId 로 채운다.
- `/mcp-data` 인증, 요청 스레드 실행(`immediateExecution(true)`)은 `/mcp-skills` 와 같다.
- 데이터 파일이 없는 세션에서 부르면 `no data file in this conversation`.

### 3.6 화면이 그릴 수 있는 형식 [PRD-525, BIZ-223]

- 대화 요청 칸 `render_features`(글 배열, 선택). 위젯 틀이 응답 손질 등록의 `renderFeatures` 를 모아 싣는다(틀 사용법 3.5). 서버 대화 요청 객체에 이 칸을 이 CR 에서 더한다. 이번 CR 값은 `chart`, `math` 다.
- 서버는 값마다 테넌트 프롬프트 틀 `widget.render.<값>` 을 찾아, 있고 활성이면 시스템 안내 끝에 덧붙인다. 없는 값과 중복은 무시한다.
- 값은 영문 소문자, 숫자, 하이픈만, 최대 10개. 어기면 400 `render_features_invalid`.
- 관리자가 틀을 비활성으로 두면 그 형식 안내가 모델에 가지 않는다.
- CLI 연결은 지금처럼 시스템 안내가 첫 사용자 메시지 앞에 붙는다.
- 다른 CR 이 형식을 추가할 때는 틀 하나와 위젯 등록 값만 추가한다. 서버 코드는 바꾸지 않는다.

틀 본문 요지(영문, CR-036 규칙):

| 키 | 요지 |
|---|---|
| `widget.render.chart` | 숫자를 비교하거나 추이를 보일 때 3.7 형식의 chart 코드 블록을 쓴다. 블록 앞뒤에 한두 문장 설명. 단위가 다른 값은 한 그래프에 섞지 않고 그래프를 나눈다 |
| `widget.render.math` | 수식은 줄 안 `$...$`, 따로 줄 `$$...$$`. 돈 표시 `$` 는 `\$` 로 쓴다 |

### 3.7 그래프 블록 형식 [PRD-522, BIZ-224]

````
```chart
{"type": "bar", "title": "지점별 11월 매출", "x_label": "지점", "y_label": "매출액(원)",
 "labels": ["서울", "부산", "대구"],
 "series": [{"name": "11월", "data": [1250000, 830000, 610000]}]}
```
````

| 칸 | 필수 | 뜻 |
|---|---|---|
| type | 예 | `bar`(막대), `line`(선) |
| title | 아니오 | 그래프 제목 |
| x_label, y_label | 아니오 | 축 이름 |
| labels | 예 | 가로축 항목, 1 ~ 200개 |
| series | 예 | 계열 1 ~ 6개. `name`(글), `data`(labels 와 같은 개수의 숫자 또는 null) |

- 형식에 맞지 않으면 위젯은 코드 블록을 그대로 두고 아래에 「그래프를 그리지 못했습니다」 를 보인다.
- 항목 200, 계열 6 은 위젯 상수다. 계열 색을 6개 두었고, 항목이 더 많으면 막대와 눈금이 읽히지 않는다.

### 4.2 동작

| 순번 | 기능 | 동작 |
|---|---|---|
| 1 | 파일 선택과 검사 | 받는 확장자와 종류별 크기 상한은 위젯 설정 조회 응답의 `attachments` 에서 가져온다. 위젯 코드에 따로 두지 않는다. 상한을 넘으면 칩에 「파일이 너무 큽니다(최대 N MB)」, 받지 않는 종류면 「이 종류의 파일은 첨부할 수 없습니다」. 서버가 거절하면 오류 코드별 문구: `FG-ATT-4001`, `FG-ATT-4221` 「이 종류의 파일은 첨부할 수 없습니다」, `FG-ATT-4002` 「파일이 너무 큽니다(최대 N MB)」, `FG-ATT-4003` 「암호가 설정된 파일은 열 수 없습니다」, `FG-ATT-4004` 「파일을 열 수 없습니다」, `FG-ATT-4005` 「행이 너무 많습니다(최대 N행)」, `FG-ATT-4006` 「열이 너무 많습니다(최대 N열)」, 그 밖은 지금처럼 서버 사유 글 |
| 2 | 요청 블록 | 이미지는 image, 그 밖은 document 블록 |
| 3 | 그래프 | 응답이 끝나 그려진 뒤 chart 코드 블록을 그래프로 바꾼다(SVG). 막대는 계열이 여럿이면 항목마다 나란히 둔다. 선은 점과 선. 세로축 눈금은 보기 좋은 간격으로 나누고 큰 수는 화면 언어로 줄여 쓴다(한국어 1.2만, 영어 12K). 계열이 둘 이상이면 범례. 막대나 점에 마우스를 올리거나 누르면 항목, 계열, 값(천 단위 쉼표). 계열 색 6개는 순서로 고정하고 어두운 화면 색을 따로 둔다(T3-3 컨셉). 제목, 축 이름. 위젯 폭에 맞춰 줄고 항목이 많으면 가로로 스크롤한다. 머리줄 「그래프 | 표」 로 같은 데이터를 표로 보고 CR-131 표 단추(복사, CSV, 엑셀)를 쓴다 |
| 4 | 수식 | `$...$`, `\(...\)` 는 줄 안 수식, `$$...$$`, `\[...\]` 는 따로 줄 수식. 마크다운 해석 단계에서 수식 자리를 표시 요소로 지키고, 응답이 그려진 뒤 KaTeX 를 그때 불러 MathML 로 그린다(글꼴 파일 없이 브라우저가 그린다). 코드 블록과 줄 안 코드는 건드리지 않는다. 돈 표시와 헷갈리지 않게 여는 `$` 바로 뒤와 닫는 `$` 바로 앞이 빈칸이 아니고 닫는 `$` 바로 뒤가 숫자가 아닐 때만 수식으로 본다. 틀린 수식은 원문 그대로 둔다 |
| 5 | 이 화면 캡처 | 누르면 브라우저 화면 공유 선택 창이 열린다(지금 탭을 먼저 권한다). 선택하면 한 장면을 PNG 로 만들어 「화면 캡처 MMDD-HHmm.png」 이름으로 첨부 칩에 넣고(`ctx.chat.attach`) 공유를 바로 멈춘다. 취소하면 아무것도 하지 않는다. 긴 변이 2000px 을 넘으면 줄인다(모델이 읽는 해상도). 화면 공유를 지원하지 않는 브라우저(모바일 등)나 보안 연결이 아닌 화면에서는 항목을 숨긴다. 권한이 거부되면 「화면을 캡처할 수 없습니다」 |

- 화면 문구는 모두 기능 파일의 문구표(ko, en)에 둔다(CR-177 3.6).
- 기능 파일: `src/features/data-chart.ts`(그래프), `src/features/math.ts`(수식), `src/features/screen-capture.ts`(이 화면 캡처). 첨부 종류와 요청 블록은 위젯 본체 변경이라 고치기 전에 컨타에 알린다(CR-177 4절).
