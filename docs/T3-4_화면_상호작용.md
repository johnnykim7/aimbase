| 상황 | 동작 |
|------|------|

| 응답이 끝나 대화가 처음 저장됨, 서버가 제목을 만듦 | 최근 대화 맨 위에 그 줄을 더하거나 이름을 바꾼다 |

### 대화 열기

| 상황 | 동작 |
|------|------|
| 대화 줄 누름 | 응답이 돌면 먼저 멈춘다. 내용을 읽어 대화 칸을 다시 그리고 머리줄 제목과 프로젝트 표시를 바꾼다. 좁은 화면이면 왼쪽 칸을 닫는다 |

## 위젯 옆 창 문서 고치기 [v3.7, CR-181]

설계 상세 [CR-181_위젯_옆_창_문서를_대화로_고치기.md](CR-181_위젯_옆_창_문서를_대화로_고치기.md) 4.2절. 옆 창 자체는 CR-180, 자리는 CR-177 틀 안내서를 따른다.

### 고치기 입력칸

| 상황 | 동작 |
|------|------|
| 옆 창에 코드 블록, 원본 있는 파일, 실행기 연결의 파일이 열림 | 옆 창 아래 줄에 고치기 입력칸이 보인다 |
| 그 밖의 문서(원본 없는 파일을 API 연결에서 엶) | 아래 줄이 비어 있다 |
| 빈 칸 보내기 | 막는다 |
| 답이 도는 중 | 보내기 단추를 막는다 |
| Enter / Shift+Enter / 한글 조합 중 Enter | 보내기 / 줄바꿈 / 보내지 않음 |
| 보냄 | 글은 대화 칸에 내 질문으로 보이고, 옆 창 본문에 「문서를 고치는 중입니다」 덮개, 판 선택과 되돌리기 잠금 |

### 결과

| `document.status` | 동작 |
|------|------|
| `UPDATED` | 옆 창이 새 판을 연다. 답 아래 그 판의 문서 카드 |
| `UNCHANGED` | 판 그대로. 답 아래 「문서가 바뀌지 않았습니다」 |
| `FAILED` 또는 이벤트 없이 끝남 | 판 그대로. 「문서를 고치지 못했습니다」 |
| 400, 404, 410 거절 | 대화 칸 오류 줄에 거절 이유. `document_source_gone` 은 「원본 파일이 정리되어 고칠 수 없습니다」 |

### 판 선택

| 상황 | 동작 |
|------|------|
| 판이 하나 | 판 선택이 보이지 않는다 |
| 판이 둘 이상 | 머리줄에 앞 버전, 「n/m」, 다음 버전 단추. 첫 판에서 앞 버전, 마지막 판에서 다음 버전 단추는 흐리게 |
| 앞 판을 보는 중 고치기 | 보는 판이 바탕 판이고, 결과는 마지막 판 다음 번호로 열린다 |
| 다시 생성으로 고친 답을 지움 | 판 목록을 다시 읽어 지운 판이 빠진다. 되돌려 만든 판은 남는다 |

### 선택한 부분 고치기 [PRD-483]

| 상황 | 동작 |
|------|------|
| HTML(실행, 코드), MARKDOWN, TEXT, SHEET 보기에서 글을 선택 | 아래 줄 입력칸 위에 「선택한 부분: "…"」 칩(한 줄을 넘으면 말줄임)과 지우기 단추. 입력칸 안내가 「선택한 부분을 어떻게 고칠까요?」 |
| PAGES, SVG, IMAGE 보기에서 선택 | 칩이 붙지 않는다(BIZ-205) |
| 입력칸을 누름 | 문서의 선택 표시는 사라져도 칩은 남는다 |
| 다른 글을 다시 선택 | 칩 글이 바뀐다 |
| 지우기 단추 / 보냄 / 다른 문서, 다른 판을 엶 | 칩이 없어지고 입력칸 안내가 「이 문서를 어떻게 고칠까요?」 |
| 칩이 있는 채 보냄 | 요청에 `document_edit.selection` 을 싣는다. 결과는 위 「결과」와 같다 |

### 앞 판으로 되돌리기 [PRD-484]

| 상황 | 동작 |
|------|------|
| 마지막 판을 봄 | 앞 판 안내 줄이 없다 |
| 마지막 판이 아닌 판을 봄 | 아래 줄 맨 위에 「버전 n 을 보고 있습니다」, 「이 버전으로 되돌리기」, 「마지막 버전 보기」 |
| 「이 버전으로 되돌리기」 | 덮개 「문서를 고치는 중입니다」. `UPDATED` 면 새 판을 연다. `UNCHANGED` 면 「마지막 버전과 같습니다」를 잠깐 보이고 마지막 판을 연다 |
| 답이 도는 중 | 「이 버전으로 되돌리기」를 막는다 |
| 403 / 404 / 409 | 아래 줄에 「되돌리지 못했습니다」와 이유. 404 는 판 목록을 다시 읽는다 |
| 「마지막 버전 보기」 | 마지막 판을 연다 |

| 단계 | 사용자 행동 | 시스템 반응 | API |
|------|-----------|-----------|-----|

| 8 | (듣는 중 120초 동안 말 없음) | 7번처럼 끝내고 「음성 대화를 마쳤습니다」 | - |

| 고른 파일이 받지 않는 확장자 | 칩에 「이 종류의 파일은 첨부할 수 없습니다」, 올리지 않는다 |
| 종류별 크기 상한 초과 | 칩에 「파일이 너무 큽니다(최대 N MB)」, 올리지 않는다 |
| 올리는 중 | 칩에 지금 진행 표시 |
| 서버 거절 | `FG-ATT-4001`, `FG-ATT-4221` 「이 종류의 파일은 첨부할 수 없습니다」, `FG-ATT-4002` 「파일이 너무 큽니다(최대 N MB)」, `FG-ATT-4003` 「암호가 설정된 파일은 열 수 없습니다」, `FG-ATT-4004` 「파일을 열 수 없습니다」, `FG-ATT-4005` 「행이 너무 많습니다(최대 N행)」, `FG-ATT-4006` 「열이 너무 많습니다(최대 N열)」, 그 밖은 서버 사유 글 |
| 보내기 | 이미지는 image 블록, 그 밖은 document 블록 |

### 이 화면 캡처

| 상황 | 동작 |
|------|------|
| 누름 | 브라우저 화면 공유 선택 창(지금 탭을 먼저 권함) |
| 고름 | 한 장면을 PNG 로 만들고 공유를 멈춘다. 긴 변 2000px 초과면 줄인다. 「화면 캡처 MMDD-HHmm.png」 칩이 생기고 올린다 |

| 권한 거부, 실패 | 알림 「화면을 캡처할 수 없습니다」 |

## 위젯 이미지 생성 [v3.11, CR-184]

설계 상세: [CR-184_위젯_이미지_생성.md](CR-184_위젯_이미지_생성.md) 4.2절, 7절. 화면 구성은 T3-3 「위젯 이미지 생성」.

### 그림 만들기 메뉴와 입력칸 모드

| 상황 | 동작 |
|------|------|
| 위젯 설정 `image_generation.enabled` 참 | + 메뉴에 「그림 만들기」 줄 |
| 거짓, 설정을 아직 못 받음 | 줄이 없다. 설정을 받으면 다시 본다 |
| 「그림 만들기」 고름 | 입력칸 모드 「그림 만들기 ×」. 글 칸에 커서 |
| 모드에서 보냄 | 질문마다 `image: {action: "create"}`. 보낸 뒤에도 모드가 남는다 |
| 이 그림 고치기 누름 | 입력칸 모드 「그림 고치기 ×」, 그 그림이 바탕. 글 칸에 커서 |
| 그림 고치기 모드에서 새 그림이 옴 | 바탕이 새 그림으로 옮겨 간다 |
| × 누름, 새 대화 | 모드가 풀린다 |
| 그림을 붙이고 보냄 | 붙인 그림도 바탕 그림이 된다 |

### 그림 답

| 상황 | 동작 |
|------|------|
| 기다리는 중 | 위젯 본체 기다림 표시 그대로 |
| 답 글에 `aimbase-image:<id>` 참조 | 그 자리를 회색 그림 자리로 바꾸고 그림 받기로 받아 그린다. 위젯 폭에 맞춰 줄인다 |
| 그림을 못 받음(404, 403, 네트워크) | 「그림을 불러오지 못했습니다」 |
| 지난 대화 다시 열기 | 답 글이 같아 같은 방식으로 그린다 |
| 그림, 크게 보기 누름 | 위젯 판 위에 덮개. 판 안에 맞춘 원래 비율 |
| 덮개에서 Esc, 바깥 누름, 닫기 | 덮개를 닫는다 |
| 내려받기 | `image-<YYYYMMDD-HHmmss>.png` 로 받는다 |
| 다시 생성, 질문 수정 | 위젯 본체가 같은 `image` 칸을 다시 실어 그림을 다시 만든다 |

### 그림 오류 문구

| 코드 | 문구(ko) |
|------|---------|
| image_not_configured | 이 연결에는 그림 만들기가 설정되어 있지 않습니다 |
| image_prompt_empty | 그림 설명을 적어 주세요 |
| image_prompt_too_long | 그림 설명은 N자까지 쓸 수 있습니다 |
| image_too_many_sources | 바탕 그림은 N장까지 붙일 수 있습니다 |
| image_source_invalid | 그림 모드에는 그림 파일만 붙일 수 있습니다 |
| image_not_found | 고칠 그림을 찾지 못했습니다 |
| image_provider_auth, image_provider_quota | 그림 서비스 사용 한도를 넘었습니다. 관리자에게 알려 주세요 |
| image_rejected | 요청한 내용으로는 그림을 만들 수 없습니다 |
| image_timeout | 그림을 만드는 데 시간이 너무 걸려 멈췄습니다 |
| image_failed, image_invalid | 그림을 만들지 못했습니다 |

- 문구는 기능 문구표(ko, en)에 두고 `ctx.ui.addErrorTexts` 로 등록한다. 오류 뒤에도 질문을 다시 보낼 수 있다
- N 은 위젯 설정 `image_generation.max_prompt_chars`, `max_source_images` 값이다

### 연결 편집 그림 칸

| 상황 | 동작 |
|------|------|
| 어댑터 OpenAI | 그림 모델 칸이 보인다 |

## 위젯 안 승인과 거절 [v3.13, CR-185]

설계 상세 [CR-185_위젯_안_승인과_거절.md](CR-185_위젯_안_승인과_거절.md) 4.2절, 5절. 화면 구조는 T3-3 「위젯 안 승인과 거절」.

### 도구 실행 승인 요청 카드

| 상황 | 동작 |
|------|------|
| `approval_required` 받음 | 답 안 그 자리에 카드. 남은 시간은 `expires_at` 기준으로 1초마다 줄인다 |
| 입력이 3줄을 넘음 | 3줄만 보이고 「입력 전체 보기」로 펼친다 |
| 승인, 거절 누름 | 두 단추를 잠그고 결정 API 를 부른다 |
| 결정 성공 | 결과 줄 「승인했습니다」 또는 「거절했습니다」와 시각 |
| 409 | 응답의 지금 상태로 결과 줄 |
| 403, 404, 망 오류 | 단추를 풀고 카드 아래 「승인 결과를 보내지 못했습니다」 |
| `approval_resolved` 받음 | 같은 카드를 결과 줄로 바꾼다. timeout 은 「시간이 지나 실행하지 않았습니다」 |
| 카드가 기다리는 채 응답 중지, 오류 | 「응답을 중지해 실행하지 않았습니다」 |
| 키보드 | 단추는 Tab 으로 가고 Enter, Space 로 누른다. Esc 는 위젯의 응답 중지 |

### 워크플로우 승인 요청 카드

| 상황 | 동작 |
|------|------|
| `workflowApproval` 받음 | 워크플로우 진행 칸에 카드 |
| 토큰에 `workflow:approve` 없음, 승인자 목록 밖, `allowApproval` false | 단추 대신 「승인자만 정할 수 있습니다」 |
| 승인, 거절 누름 | 두 단추를 잠그고 워크플로우 승인 API 를 부른다 |
| 403 | 「승인자만 정할 수 있습니다」 |
| 409 | 「이미 다른 사람이 정했습니다」 |
| 진행 칸 끝남 | 기다리던 카드를 결과 줄로 닫는다. 마감이 지나 실패면 「마감이 지나 실패했습니다」 |

### 관리 화면 Policies 「도구 실행 전 승인」

| 상황 | 동작 |
|------|------|
| 규칙 타입 고름 | 대상 도구(여러 개 고르기, `GET /api/v1/tools` 이름과 설명), 안내 문구 칸이 나온다 |
| 대상 도구 없이 저장 | 칸 아래 「도구를 하나 이상 고르세요」, 저장하지 않는다 |
| 서버 400 `policy_tools_empty` | 같은 칸 오류 |
| 저장 성공 | 목록 행에 「대상 도구: a, b」 |
