# CR-050 담당자 업무 지시서 (확정판)

## 📌 과제
**Claude CLI → LLM 어댑터 승격**
Claude Code CLI를 LLM_CALL 경로의 새 어댑터로 구현. Max/Pro 구독 정액제를 워크플로우 LLM_CALL에서 활용 가능하게.

## 🎯 목표 수치
- Node.js 기동 오버헤드: 500ms × N호출 → 500ms × 1(run 단위 상주)
- 10 LLM_CALL 워크플로우: 5초 → 0.5초 (실측 기준)
- 병렬 브랜치 비용: $0.07 → $0.007 (`--fork-session` prompt prefix 캐시)

## 🛠 환경 (사용자 확정)
- **테스트 계정**: 기존 제거(OAuth 풀) 계정 사용. `AgentAccountPoolManager` `CLAUDE_CONFIG_DIR` 격리 로직 그대로 재활용
- **테스트 환경**: 로컬 (macOS, `claude` CLI 바이너리가 PATH에 있다고 가정)
- **Sprint**: 담당자 자율 배정

## ⚠️ Phase 0 필수: 사용자 승인 7종
구현 착수 전 반드시 사용자 확인 받을 것. `CR_변경_이력.md` CR-050 "결정 필요" 항목:

1. run당 최대 워커 수 기본값 (초안: 5)
2. 피처 플래그 대상 테넌트 범위 (상용 외부 테넌트는 ToS 경계상 비활성 유지)
3. CLI 바이너리 경로 (시스템 PATH vs 고정 경로) — 로컬 환경 기준 PATH 우선 검토

5. stderr drain 실패 시 복구 정책
6. 워커 크래시 시 run 실패 처리 여부 (vs 재시작)
7. Connection type 이름 (`anthropic-cli` 확정)

→ 나머지 항목은 원본 문서 직접 확인

## 🔨 Phase별 구현 순서

### Phase 1: ClaudeCliWorker (단일 프로세스 래퍼) — PRD-306
**파일**: `backend/platform-core/src/main/java/com/platform/llm/claudecli/ClaudeCliWorker.java`

- `ProcessBuilder`로 `claude -p --input-format stream-json --output-format stream-json --tools ""` 기동
- stdin NDJSON 주입 / stdout 라인 단위 파싱
- 🚨 **stderr drain 스레드 필수** (버퍼 차면 프로세스 멈춤)
- API: `ChatResponse turn(List<UnifiedMessage>)` — 내부 뮤텍스로 동시 호출 직렬화
- 프로세스 생존 확인, 크래시 감지, 세션 파일 경로 추적 (fork-session용 필수)
- `CLAUDE_CONFIG_DIR` 격리 — `AgentAccountPoolManager`에서 할당받은 디렉토리 사용

**테스트**: `ClaudeCliWorkerTest` — 프로세스 기동/종료/stdin/stdout

### Phase 2: ClaudeCliWorkerPool (Run 단위 풀 + fork-session) — PRD-307
**파일**: `llm/claudecli/ClaudeCliWorkerPool.java`

- `ConcurrentHashMap<String, RunWorkers>` (key: `workflowRunId`)
- `getOrCreateMain(runId)`: lazy spawn
- `spawnForkedWorker(runId, parentSessionId)`: `--resume <sid> --fork-session`으로 분기 (캐시 재사용)
- `shutdownForRun(runId)`: 모든 워커 프로세스 종료
- 워커 크래시 시 재기동 + 현재 run 실패 처리

**테스트**: `ClaudeCliWorkerPoolTest` — 동시성/lazy spawn/shutdown

### Phase 3: ClaudeCliLlmAdapter + Factory 통합 — PRD-308
**신규**:
- `llm/adapter/ClaudeCliLlmAdapter.java` (LLMAdapter 구현)
- `llm/claudecli/ClaudeCliAdapterConfig.java` (`platform.llm.anthropic-cli` 섹션: enabled/timeout/max-workers-per-run/cli-binary-path/allowed-tenants)

**수정**: `ConnectionAdapterFactory`
- `normalizeAdapterType()`에 `"anthropic-cli"` 매핑
- `createAdapter()`에 `case "anthropic-cli"` 추가

**핵심 동작**:
- 첫 턴: 전체 messages NDJSON 주입
- 이후 턴: 마지막 user 메시지만 주입 (CLI가 맥락 기억)
- `transformToolDefs()`: 빈 구현
- `chatStream()`: stdout 이벤트를 StreamEvent로 변환

### Phase 4: WorkflowEngine 수명 훅 + 병렬 브랜치 통합 — PRD-309
**수정**:
- `workflow/WorkflowEngine.java` — Run 종료(정상/예외 모두) 시 `try/finally`로 `claudeCliWorkerPool.shutdownForRun(runId)` 호출
- `workflow/step/ParallelStepExecutor.java` — 병렬 브랜치 시작 시 fork 워커 확보, 종료 시 해제

🚨 **프로세스 누수 방지가 핵심** — `try/finally` 누락 시 서버 터짐

**테스트**: `ClaudeCliLlmAdapterIT` (실제 CLI) + E2E 4시나리오
