## 발행 이벤트 (내부)

### SessionMessageAppended (v1)
- **트리거 조건**: 채팅 완료 시 세션에 사용자/어시스턴트 메시지 저장
- **주요 포함 데이터**: sessionId, tenantId, role, contentBlocks[], timestamp
- **소비 주체**: SessionStore (Redis 저장)
- **관련 기능 ID**: PRD-089

### LLMCallCompleted (v1)
- **트리거 조건**: LLM 어댑터가 응답을 반환한 시점
- **주요 포함 데이터**: requestId, model, provider, inputTokens, outputTokens, costUsd, latencyMs, finishReason
- **소비 주체**: UsageLogRepository (사용량 기록), PlatformMetrics (Prometheus), AuditLogger (감사 로그)
- **관련 기능 ID**: PRD-001, PRD-002

### ToolCallExecuted (v1)
- **트리거 조건**: ToolCallHandler에서 도구 실행 완료
- **주요 포함 데이터**: toolName, input, output, durationMs, success, iterationNumber
- **소비 주체**: AuditLogger
- **관련 기능 ID**: PRD-092

### ActionExecuted (v1)
- **트리거 조건**: Write/Notify 액션 실행 완료
- **주요 포함 데이터**: actionId, type(WRITE/NOTIFY), adapter, destination, status, resultSummary
- **소비 주체**: ActionLogRepository, AuditLogger
- **관련 기능 ID**: PRD-093, PRD-094

### PolicyEvaluated (v1)
- **트리거 조건**: PolicyEngine에서 정책 평가 완료
- **주요 포함 데이터**: policyIds[], action(ALLOW/DENY/REQUIRE_APPROVAL), intent, triggeredRules[], transforms
- **소비 주체**: AuditLogger
- **관련 기능 ID**: PRD-095

### ApprovalRequested (v1)
- **트리거 조건**: HUMAN_INPUT 스텝 도달 또는 REQUIRE_APPROVAL 정책 트리거
- **주요 포함 데이터**: approvalId, workflowRunId/actionId, approvers[], channel, requestedAt, timeoutAt
- **소비 주체**: PendingApprovalRepository, WebSocketAdapter (실시간 알림)
- **관련 기능 ID**: PRD-046, PRD-095

### ApprovalResolved (v1)
- **트리거 조건**: 관리자가 승인 또는 거부 처리
- **주요 포함 데이터**: approvalId, status(approved/rejected), approvedBy, reason, resolvedAt
- **소비 주체**: WorkflowEngine.resume() (워크플로우 재개)
- **관련 기능 ID**: PRD-064, PRD-065

### WorkflowRunStarted (v1)
- **트리거 조건**: POST /workflows/{id}/run 호출 시
- **주요 포함 데이터**: workflowId, runId, sessionId, inputData, startedAt
- **소비 주체**: WorkflowRunRepository
- **관련 기능 ID**: PRD-043

### WorkflowRunCompleted (v1)
- **트리거 조건**: 모든 스텝 정상 완료
- **주요 포함 데이터**: workflowId, runId, stepResults, completedAt, durationMs
- **소비 주체**: WorkflowRunRepository
- **관련 기능 ID**: PRD-043

### WorkflowRunFailed (v1)
- **트리거 조건**: 스텝 실패 (재시도 소진) 또는 승인 거부
- **주요 포함 데이터**: workflowId, runId, failedStep, error, failedAt
- **소비 주체**: WorkflowRunRepository
- **관련 기능 ID**: PRD-043

### 실행 종료 신호 구현 [CR-164]
- 코드의 실행 종료 신호는 `WorkflowEvents.RunCompleted`(status completed, failed, cancelled) 하나로 위 WorkflowRunCompleted, WorkflowRunFailed 를 함께 낸다
- 승인 거절로 실패한 run, 단계 없이 끝난 run 에서도 낸다(CR-164 전에는 빠져 있었다)
- 소비 주체: 실행 실시간 구독(SSE), 개발 작업 잇기(PRD-351)

### DevWorkItemStatusChanged (v1) [CR-164]
- **트리거 조건**: 개발 작업 변경 한 줄이 생길 때(BIZ-129)
- **주요 포함 데이터**: workItemId, featureName, stage, status, evidenceUrl, changedAt, changeId, source, sourceRunId
- **소비 주체**: 이벤트 트리거 워크플로우 실행(PRD-352)
- **관련 기능 ID**: PRD-350, PRD-352
- **정합성 전략**: 같은 스레드에서 동기로 받아 알림 워크플로우를 비동기로 시작한다. 시작에 실패한 워크플로우는 기록만 남기고 다음 워크플로우로 간다

### TenantProvisioned (v1)
- **트리거 조건**: 테넌트 프로비저닝 6단계 완료
- **주요 포함 데이터**: tenantId, name, dbName, plan, adminEmail, provisionedAt
- **소비 주체**: TenantDataSourceManager (DataSource 캐시 등록)
- **관련 기능 ID**: PRD-080

### IngestionCompleted (v1)
- **트리거 조건**: 인제스션 파이프라인 정상 완료
- **주요 포함 데이터**: sourceId, documentCount, chunkCount, durationMs, completedAt
- **소비 주체**: KnowledgeSourceRepository (status=completed, counts 갱신), IngestionLogRepository
- **관련 기능 ID**: PRD-052

### MCPToolsDiscovered (v1)
- **트리거 조건**: MCP 서버 도구 탐색 완료
- **주요 포함 데이터**: serverId, toolCount, tools[{name, description, inputSchema}]
- **소비 주체**: ToolRegistry (동적 등록), MCPServerRepository (toolsCache 갱신)
- **관련 기능 ID**: PRD-013

## 발행 이벤트 (외부)

### WebSocketNotification (v1)
- **트리거 조건**: NOTIFY 액션에서 WebSocket 어댑터 호출
- **주요 포함 데이터**: topic, message, metadata, timestamp
- **소비 주체**: 프론트엔드 WebSocket 클라이언트
- **관련 기능 ID**: PRD-094

### SlackNotification (v1)
- **트리거 조건**: NOTIFY 액션에서 Slack 어댑터 호출
- **주요 포함 데이터**: channel, text, blocks[], botToken
- **소비 주체**: Slack API (외부 서비스)
- **관련 기능 ID**: PRD-094
- **정합성 전략**: fire-and-forget (재시도 미지원)

### 개발 작업 상태 알림 (v1) [CR-164]
- **트리거 조건**: DevWorkItemStatusChanged 로 실행된 알림 워크플로우의 http_request 단계
- **주요 포함 데이터**: 워크플로우가 정한 본문. bp-office 는 workItemId, featureName, stage, status, evidenceUrl, reportedAt(bp-office CR-037 요청서 2절)
- **소비 주체**: bp-office `POST /api/v1/inbound/dev-agent-status`
- **관련 기능 ID**: PRD-352
- **정합성 전략**: 워크플로우 error_handling 재시도, 그래도 실패하면 알림 run 재실행. 재실행은 같은 reported_at 을 보내고 받는 쪽이 같은 workItemId, reportedAt 을 한 번만 처리한다

### 실행 종료 회신 (v1) [CR-174]
- **트리거 조건**: 실행 입력에 `_callback` 이 있는 run 의 RunCompleted(completed, failed, cancelled). 승인 거절, 승인 시한 초과, 단계 실패, 중지가 모두 포함된다(BIZ-143)
- **주요 포함 데이터**: run_id, workflow_id, status, error{reason, detail}, result(`result_step` 단계 output), completed_at(UTC ISO-8601), duration_ms
- **소비 주체**: `_callback.connection_id` HTTP 연결의 `baseUrl` + `_callback.path`. 품고 수리는 bp-3plgw 회신 수신 API
- **관련 기능 ID**: PRD-363, PRD-366
- **정합성 전략**: 2xx 가 아니면 설정 횟수까지 다시 보낸다. 같은 run_id 가 두 번 갈 수 있어 받는 쪽이 한 번만 처리한다. 끝내 실패하면 run 이벤트 `CALLBACK_FAILED` 만 남기고 run 상태는 바꾸지 않는다

### 수리 제안 제출 (v1) [CR-174]
- **트리거 조건**: 워크플로우 `poomgo-change-repair` 의 submit 단계(http_request). repair 단계가 끝난 직후
- **주요 포함 데이터**: run_id, change_id, proposal{result_kind(CONTRACT, CODE, NONE), summary, changed[], contract_proposal, pr{number, url, branch}, tests, failure_reason}
- **소비 주체**: bp-3plgw 「제안 제출」 API(3PLGW 가 정한다). 검증, 등록, 사람 통보(BO2 푸시, 문자)를 한다
- **관련 기능 ID**: PRD-366
- **정합성 전략**: 검증 실패는 4xx 라 단계가 실패하고 run 이 failed 로 끝나 실행 종료 회신이 간다. 재시도 없음(BIZ-146)

## 수신 이벤트 (외부)

### 품고 변경 수리 요청 (v1) [CR-174]
- **트리거 조건**: bp-3plgw 감지기가 품고 API, 화면 변경을 잡았을 때 `POST /api/v1/workflows/poomgo-change-repair/run`(소비앱 키)
- **주요 포함 데이터**: schema_version, change_id, change_kind(FORMAT, VALUE, SCREEN), source, detected_at, repo{url, base_branch, commit}, contract{version, url}, samples{broken_url, last_good_url, dom_dump_url}, summary, pr_labels, _callback. 정본 `협업/계약_CR-174_품고_변경_수리_요청_웹훅.md`
- **발행 주체**: bp-3plgw
- **소비 주체**: WorkflowEngine(run 생성, 비동기 실행)
- **관련 기능 ID**: PRD-366
- **정합성 전략**: 응답 `data.id`(run_id)를 3PLGW 가 보관한다. 같은 change_id 는 3PLGW 가 한 번만 보낸다(BIZ-146)

### 승인 전달 (v1) [CR-174]
- **트리거 조건**: BO2 「연동 수리 승인」 화면에서 사람이 승인, 거절했을 때 bp-3plgw 가 `POST /api/v1/workflows/runs/{run_id}/approve`
- **주요 포함 데이터**: approved, reason
- **발행 주체**: bp-3plgw
- **소비 주체**: WorkflowEngine.resume
- **관련 기능 ID**: PRD-046, PRD-366
- **정합성 전략**: 승인 대기가 아니면 409. 시한이 지나 감시기가 먼저 닫았으면 409 이고 회신은 이미 갔다(BIZ-144)

### MCPToolCall / MCPToolResult (v1)
- **트리거 조건**: MCP 프로토콜을 통한 도구 호출 요청/응답
- **주요 포함 데이터**: toolName, input/output, callId
- **발행 주체**: MCP Server (외부)
- **소비 주체**: MCPServerClient → MCPToolExecutor
- **관련 기능 ID**: PRD-013

### LLMProviderResponse (v1)
- **트리거 조건**: LLM 프로바이더(Anthropic/OpenAI/Ollama)로부터 응답 수신
- **주요 포함 데이터**: provider-specific response (messages, tool_calls, usage)
- **발행 주체**: Anthropic API / OpenAI API / Ollama API
- **소비 주체**: LLMAdapter (변환 → LLMResponse)
- **관련 기능 ID**: PRD-001, PRD-002
- **멱등 키**: requestId (LLM 요청별 고유 ID)

## 설계 철학

1. **동기 우선 아키텍처**: 현재 시스템은 REST 동기 호출 중심. 비동기 이벤트 버스(Kafka/RabbitMQ)는 미도입. 내부 이벤트는 메서드 호출로 처리.
2. **감사 로깅 의무화**: LLM 호출, 도구 사용, 액션 실행, 정책 평가 모든 주요 이벤트에 AuditLogger가 관여하여 추적성 보장.
3. **확장 대비**: 향후 이벤트 버스 도입 시 현재의 내부 이벤트를 메시지 큐로 전환 가능한 구조. ActionExecuted, WorkflowRunCompleted 등은 이벤트 계약이 이미 정의됨.
