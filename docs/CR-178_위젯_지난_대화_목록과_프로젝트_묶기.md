## 3. 서버

모든 위젯용 API 는 `/api/v1/chat` 아래에 두고 `chat:stream` 위젯 토큰 또는 로그인으로 부른다. 주인은 위젯 토큰 user_ref, 로그인은 사용자 id 다(BIZ-170). 남의 대화와 프로젝트는 없는 것으로 보고 404 를 돌려준다.

user_ref 가 없는 위젯 토큰으로 3.1 ~ 3.5 를 부르면 403 `widget_user_required` 다. 이런 토큰은 주인이 `widget` 하나로 모여 남의 대화가 보이기 때문이다(2절 8번). 위젯은 3.9 의 `history_enabled` 로 이를 알고 해당 단추와 메뉴를 숨긴다.

### 3.1 대화 목록 [PRD-420, BIZ-170]

`GET /api/v1/chat/sessions?chat_project_id=&query=&page=&size=`

| 조건 | 뜻 |
|---|---|
| chat_project_id | 프로젝트 id 면 그 프로젝트 대화만. `none` 이면 프로젝트에 없는 대화만. 비우면 전부 |
| query | 제목 부분 일치(대소문자 무시). 주면 chat_project_id 를 보지 않고 전부에서 찾는다 |
| page, size | 0 부터. size 기본은 런타임 설정 `widget.history-page-size`, 최대 100 |

- 대상은 주인이 요청자이고, 지우지 않았고, `scope_type = chat` 이고, 메시지가 하나 이상인 세션이다. 마지막 활동 시각(`updated_at`) 내림차순
- 행: `session_id`, `title`, `chat_project_id`, `updated_at`(시간대 오프셋을 붙인 ISO-8601)
- 응답은 기존 쪽 형식(`ApiResponse.page`)

### 3.2 이어보기 [PRD-421, BIZ-174]

`GET /api/v1/chat/sessions/{session_id}/messages`

```json
{"session_id": "8f1e...", "title": "11/7 박스 파손 회신", "chat_project_id": "3c2a...", "truncated": false,
 "turns": [
   {"turn_id": "0b6f...", "user_seq": 4,
    "question": {"text": "파손 건 회신문 써줘", "created_at": "2026-11-07T14:20:03+09:00",
                 "attachments": [{"attachment_id": "a1...", "filename": "사진1.jpg", "media_type": "image/jpeg", "available": true}]},
    "answer": {"text": "회신문 초안입니다 ...", "model": "claude-sonnet-5-5", "created_at": "2026-11-07T14:20:31+09:00",
               "stopped": false, "tool_uses": [{"name": "wes_order_lookup"}]},
    "feedback": {"rating": "DOWN", "reason_codes": ["NO_LOOKUP"], "comment": "출고 이력을 안 봤어요"}}
 ]}
```

- 지우지 않은 메시지만 순번 순으로 읽는다. `system` 메시지(붙이는 앱의 화면 맥락), 압축 경계는 보이지 않는다
- 질문 하나(사용자 글 메시지)부터 다음 질문 앞까지가 한 묶음이다. 응답 글은 그 사이 assistant 글 블록을 이어 붙인다. 도구 사용은 이름 목록만 담는다. 도구 결과 본문은 돌려주지 않는다
- 질문 글은 질문 줄의 화면용 값(5.3 `display.text`)이 있으면 그것, 없으면(CR-178 전 메시지) 저장된 본문이다. 저장된 본문에는 서버가 덧붙인 안내 글(PDF 추출본 등)이 섞여 있어 사용자가 보낸 글과 다르다
- 도구 이름은 답 줄의 화면용 값(`display.tool_uses`)과 도구 호출 줄(`TOOL_USE`)에서 모은다. 대화 요청은 도구 호출 줄을 저장하지 않으므로 답을 저장할 때 그 답에서 쓴 도구 이름을 남긴다
- `turn_id` 가 있으면 `user_seq` 는 그 답 번호를 가진 메시지 중 가장 작은 순번이다. 화면 맥락까지 한 묶음으로 되감기 위해서다(CR-175 BIZ-148). `turn_id` 가 없는 예전 메시지는 `turn_id`, `user_seq` 를 비운다. 위젯은 이때 다시 생성, 질문 수정, 평가 단추를 숨긴다(CR-175 T3-4 「다시 생성과 질문 수정」 6단계)
- 응답 본문이 멈춤 표시 글로 시작하면 떼고 `stopped = true`. 멈춤 표시 글은 쓰는 곳과 읽는 곳이 같은 상수 하나를 쓴다(2절 7번)
- 첨부는 질문 줄의 화면용 값(`display.attachments`)에 남긴 `attachment_id` 로 첨부 행을 찾는다. 저장된 질문 블록에는 첨부 번호가 없다. 만료로 지워졌으면 `available = false` 이고, 파일 이름과 종류는 질문 때 남긴 값을 그대로 보인다(무엇을 올렸는지는 알 수 있게)
- 평가는 요청자가 그 답 번호에 남긴 것만 싣는다(CR-175 BIZ-149)
- 질문 묶음이 런타임 설정 `widget.history-turns-max` 보다 많으면 마지막 그만큼만 싣고 `truncated = true`

| 오류 | 경우 |
|---|---|
| 404 `session_not_found` | 없거나, 지웠거나, 요청자의 세션이 아님 |

### 3.3 대화 이름 바꾸기, 옮기기, 삭제 [PRD-422, PRD-424]

`PATCH /api/v1/chat/sessions/{session_id}`

```json
{"title": "11/7 박스 파손 회신"}
{"chat_project_id": "3c2a..."}
{"chat_project_id": null}
```

- 준 칸만 바꾼다. 제목을 바꾸면 `title_source = USER` 로 적어 자동 제목이 덮지 않게 한다(CR-175 BIZ-151)
- `chat_project_id` 는 요청자의 프로젝트여야 한다. `null` 이면 프로젝트에서 뺀다(BIZ-171)

`DELETE /api/v1/chat/sessions/{session_id}`

- 기존 관리용 세션 삭제와 같은 일을 한다. 답이 돌면 멈추고, 세션과 메시지에 지운 표시(`delete_reason = SESSION_DELETE`)를 하고, Redis 대화 기록을 비운다. 두 경로가 한 서비스를 쓴다

| 오류 | 경우 |
|---|---|
| 404 `session_not_found` | 없거나, 지웠거나, 요청자의 세션이 아님 |
| 404 `project_not_found` | 옮길 프로젝트가 없거나 요청자의 것이 아님 |
| 400 `session_invalid:title` | 앞뒤 공백을 뺀 제목이 비었거나 500자를 넘음 |

### 3.4 프로젝트 [PRD-423, BIZ-171]

| 방법 | 경로 | 뜻 |
|---|---|---|
| GET | /api/v1/chat/projects | 내 프로젝트 목록 |
| POST | /api/v1/chat/projects | 만들기 `{name, instructions}` |
| GET | /api/v1/chat/projects/{project_id} | 설정 창용 한 건(지시문 전문, 자료 목록) |
| PATCH | /api/v1/chat/projects/{project_id} | 준 칸만 바꾸기 `{name}`, `{instructions}` |
| DELETE | /api/v1/chat/projects/{project_id} | 삭제 |

- 목록 행: `id`, `name`, `has_instructions`, `file_count`, `session_count`, `last_active_at`. 정렬은 `last_active_at` 내림차순이다. 이 값은 프로젝트를 고친 시각과 그 안 대화의 마지막 활동 시각 중 늦은 것이다
- 이름은 앞뒤 공백을 빼고 1 ~ 100자. 지시문은 비워도 되고 최대 런타임 설정 `widget.project-instructions-max-chars` 자
- 삭제하면 그 프로젝트의 대화는 지우지 않고 프로젝트에서 빠져 최근 대화로 돌아간다. 자료는 저장소 파일과 행을 함께 지운다

| 오류 | 경우 |
|---|---|
| 400 `project_invalid:name` | 이름이 비었거나 100자를 넘음 |
| 400 `project_invalid:instructions` | 지시문이 최대 글자 수를 넘음 |
| 404 `project_not_found` | 없거나 요청자의 것이 아님 |

### 3.5 프로젝트 자료 [PRD-425, BIZ-173]

| 방법 | 경로 | 뜻 |
|---|---|---|
| GET | /api/v1/chat/projects/{project_id}/files | 자료 목록 |
| POST | /api/v1/chat/projects/{project_id}/files | 올리기(multipart `file`). `chat:upload` 필요 |
| DELETE | /api/v1/chat/projects/{project_id}/files/{file_id} | 삭제 |
| POST | /api/v1/chat/projects/{project_id}/files/{file_id}/attach | 이 대화의 첨부로 붙이기 `{session_id}`. `chat:upload` 필요 |

- 올릴 수 있는 종류와 크기는 채팅 첨부와 같다(첨부 검사를 함께 쓴다). 자료는 만료되지 않는다
- 자료 행: `file_id`, `filename`, `media_type`, `size_bytes`, `pages`, `created_at`
- 붙이기는 자료 파일을 복사해 그 세션의 새 첨부를 만들고 첨부 올리기와 같은 응답을 돌려준다. 그 첨부는 첨부 규칙(만료 포함)을 따르고 자료 원본은 그대로 남는다. 세션이 아직 없으면(새 대화의 첫 질문 전) 그대로 붙인다. 세션이 있는데 요청자의 것이 아니면 404

| 오류 | 경우 |
|---|---|
| 409 `project_files_full` | 자료가 런타임 설정 `widget.project-files-max-count` 개 있음 |
| 400, 413 | 첨부 올리기와 같은 종류, 크기 오류 |
| 404 `project_not_found`, `file_not_found`, `session_not_found` | 없거나 요청자의 것이 아님 |

### 3.6 프로젝트 지시문 적용 [PRD-426, BIZ-172]

- 대화 요청의 세션이 프로젝트에 있고 그 프로젝트에 지시문이 있으면, 서버가 그 요청의 시스템 지시 끝에 지시문을 붙인다. 붙이는 글의 틀은 테넌트 프롬프트 틀 `widget.project-instructions` 이고 입력 칸은 `{{project_name}}`, `{{instructions}}` 다
- 대화 기록(Redis, conversation_messages)에는 넣지 않는다. 지시문을 고치면 다음 질문부터 바뀐다. 되감기, 압축과 상관이 없다

#### 3.6.1 질문마다 붙는 시스템 지시

CLI 연결에서도 지시문이 모든 질문에 닿게 하려고(2절 9번) 시스템 지시를 둘로 나눈다.

| 구분 | 무엇 | API 연결 | Claude CLI 연결 |
|---|---|---|---|
| 기본 시스템 지시 | 그 연결의 시스템 프롬프트(조립한 기본 지시) | 지금처럼 매 요청 시스템 지시로 보낸다 | 지금처럼 작업자의 첫 질문에만 붙이고, 대체값이 있으면 대체값이 대신한다 |
| 질문마다 붙는 지시 | 이번 질문의 화면 맥락, 검색 자료, 기억(CR-179), 프로젝트 지시문 | 지금처럼 시스템 지시로 보낸다 | 작업자가 이어 쓰는 중이어도, 대체값이 있어도 이번 질문 앞에 붙인다 |

- 오케스트레이터가 맥락을 조립할 때 이번 질문 몫의 시스템 메시지에 이번 질문 몫이라는 표시(turn_scoped)를 단다. 대화 기록에서 읽은 지난 시스템 메시지에는 달지 않는다(지난 질문의 화면 맥락은 이미 지난 질문과 함께 갔다)
- 표시는 서버가 실행기에 보내는 메시지 칸 `turn_scoped: true` 로 넘긴다. 이 칸을 모르는 옛 실행기는 무시하고 지금처럼 동작한다
- 순서는 화면 맥락, 검색 자료, 기억, 프로젝트 지시문이다. 기억 다음 프로젝트 지시문은 CR-179 와 맞춘 것이다
- 표시와 실행기 쪽 처리는 CR-178 이 만들고 CR-179 는 기억을 같은 표시로 넣는다(11/13 CR-179 동의). 표시를 넣은 커밋은 컨타에 알린다
- 이 표시로 지금 CLI 연결에서 두 번째 질문부터 화면 맥락과 검색 자료가 빠지던 것도 같이 고쳐진다. 지난 대화를 다른 문의 화면에서 이어 물을 때 지금 화면의 맥락이 실려야 하므로(4.2 끝) 이번에 함께 고친다

## 4. 위젯

CR-177 이 만드는 왼쪽 칸 자리, + 메뉴와 더 보기 메뉴의 항목 등록 방식, 화면 문구표에 붙인다. 왼쪽 칸이 대화 칸 위에 겹쳐 보이는지 나란히 보이는지는 CR-177 의 자리 규칙을 따른다. 기능 파일은 `src/features/history.ts` 하나이고 위젯 본체와 틀은 고치지 않는다.

CR-178 이 요청해 틀에 들어간 자리(틀 사용법 3.7, dev 25b69c4):

| 순번 | 자리 | 쓰는 곳 |
|---|---|---|
| 1 | `ctx.chat.open(view)` | 대화 열기. 3.2 응답을 `ConversationView` 로 바꿔 넘긴다. user_seq 는 turnSeq, created_at 은 Date, tool_uses 는 이름 목록, truncated 면 notice 에 「앞의 대화는 보이지 않습니다」 |
| 2 | `ctx.chat.attachUploaded(meta)` | 「프로젝트 자료에서」로 서버가 만든 첨부를 입력칸 칩으로 더한다 |
| 3 | `ctx.chat.addRequestFields(fn)` | 이 프로젝트에서 새 대화의 첫 질문에 `chat_project_id` 를 싣는다 |
| 4 | `ctx.ui.header.setTitleTag(spec)` | 머리줄 프로젝트 표시 |
| 5 | `ctx.chat.setTitle(text)` | 지금 대화 이름을 바꾸면 머리줄 제목도 바꾼다 |

- 화면 문구는 CR-177 문구표에 넣는다

### 4.2 동작

| 순번 | 기능 | 동작 |
|---|---|---|
| 1 | 대화 목록 열기 | 처음 열 때 프로젝트 목록과 최근 대화 첫 쪽을 읽는다. 날짜 묶음은 보는 사람 시간대로 나눈다 |

| 3 | 대화 열기 | 응답이 돌면 먼저 멈춘다. 대화 내용을 읽어 화면을 다시 그리고 머리줄 제목과 프로젝트 표시를 바꾼다. 다음 질문부터 그 session_id 로 묻는다. 마지막 응답에 다시 생성과 평가 상태가 그대로 보인다. `truncated` 면 맨 위에 「앞의 대화는 보이지 않습니다」 |

| 5 | 이 프로젝트에서 새 대화 | 새 session_id 로 화면을 비우고 머리줄에 프로젝트를 표시한다. 첫 질문 요청에 `chat_project_id` 를 싣는다 |
| 6 | 이름 바꾸기 | 그 줄이 글 칸으로 바뀐다. Enter 저장, Esc 취소. 비우고 Enter 면 저장하지 않고 되돌린다 |
| 7 | 프로젝트로 옮기기 | 프로젝트로 옮기기 창에서 선택하면 저장하고 목록 위치와 머리줄 표시를 바꾼다. 지시문은 다음 질문부터 적용된다 |
| 8 | 대화 삭제 | 「이 대화를 삭제할까요?」 확인 뒤 삭제한다. 지금 보는 대화면 새 대화 첫 화면으로 간다 |
| 9 | 새 프로젝트, 프로젝트 설정 | 설정 창에서 저장한다. 오류는 그 칸 아래에 보인다. 새 프로젝트를 프로젝트로 옮기기 창에서 만들었으면 만든 뒤 지금 대화를 그 프로젝트로 옮긴다 |
| 10 | 자료 올리기 | 첨부와 같은 파일 선택. 개수가 다 찼으면 올리기 단추를 막고 「자료는 n개까지 올릴 수 있습니다」 |
| 11 | 프로젝트 자료에서 | 프로젝트 자료에서 창에서 선택하면 서버가 첨부로 복사하고 입력칸에 첨부 칩이 붙는다. 그 뒤는 첨부와 같다 |
| 12 | 프로젝트 삭제 | 「프로젝트를 삭제합니다. 대화는 최근 대화로 옮겨지고 자료는 삭제됩니다」 확인 뒤 삭제한다 |
| 13 | 위젯이 뜰 때 | 붙이는 앱이 `sessionId` 를 주었고 `history_enabled` 이며 그 대화가 요청자의 것으로 있으면 내용을 읽어 보인다. 없으면(404) 지금처럼 첫 화면이다 |
| 14 | 실패 | 목록, 내용 읽기 실패는 그 자리에 「불러오지 못했습니다」와 다시 시도 단추. 저장 실패는 화면을 원래대로 두고 「저장하지 못했습니다」 |

- 다른 문의 화면에서 만든 지난 대화를 열어 이어 물으면, 그 질문에는 지금 화면의 맥락이 실린다(맥락은 붙이는 앱이 질문마다 준다)

### 4.3 붙이는 앱이 주는 옵션

- 새 옵션은 없다. 기존 `sessionId` 옵션에 4.2 13번 동작이 붙는다

## 12. 설계 보정 (구현 중, v1.1)

| 번호 | 처음 설계 | 바뀐 것 | 이유 |
|---|---|---|---|
| 1 | 첨부는 질문 블록의 `attachment_id` 로 찾는다 | 질문 줄 화면용 값 `display` 칸을 두고 거기 남긴 번호로 찾는다(5.3.1) | 저장된 질문 블록에는 첨부 번호가 없고 서버가 덧붙인 안내 글이 섞인다 |

| 4 | 로그인 대화의 주인은 사용자 id | 그대로 두되, CR-178 전에 이메일로 저장한 로그인 세션도 그 사용자 것으로 본다 | 관리용 삭제, 세션 이어가기가 예전 세션에서 거절되지 않게 |
