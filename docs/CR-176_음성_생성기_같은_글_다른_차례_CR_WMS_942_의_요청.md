## 1. 배경

운영 음성 표본 100개를 들은 사용자가 바구니 이름 「에스 34번」, 「에스 72번」, 「에스 82번」 의 「에스」 가 「에즈」 로 들린다고 했다. 바라는 것은 읽는 말은 그대로 두고 그 파일의 소리만 다시 만드는 것이다.

## 2. 원인

| 순번 | 어디 | 무엇 |
|---|---|---|
| 1 | 생성기 씨앗(BIZ-134) | 시도마다 `voice.seed + attempt - 1` 을 쓴다(`tts-sidecar/server.py` `Engine.synthesize`). 같은 음색, 같은 글은 몇 번을 만들어도 같은 소리다 |
| 2 | 재사용 `TtsJobStore.findReusable` | 같은 음색, 같은 글의 끝난 작업을 보관 기간 7일 동안 돌려준다. 같은 글을 다시 맡겨도 생성기에 닿지 않는다 |
| 3 | 요청 모양 `SubmitRequest(voice, text)` | 글을 바꾸면(부호를 더하는 등) 소리는 달라지지만 읽는 말이 바뀐다. 글을 그대로 두고 소리만 다시 뽑을 칸이 없다 |

## 3. 변경

1. 맡기기 요청에 차례 `take`(0 이상의 정수)를 받는다. 빠지면 0 이다. 상한은 설정 `aimbase.tts.max-take`(기본 10)이고 벗어나면 400 `take_out_of_range:max=10` 이며 행을 만들지 않는다.
2. 생성기는 시도마다 씨앗 `voice.seed + take * voice.attempts + attempt - 1` 을 쓴다. 차례마다 시도 씨앗 묶음이 겹치지 않는다. field-voice-07(씨앗 20261031, 시도 3회)은 차례 0 이 20261031 부터 33, 차례 1 이 34 부터 36, 차례 2 가 37 부터 39 다.
3. 재사용 열쇠에 차례를 넣는다. 같은 음색, 같은 글, 같은 차례일 때만 앞 작업을 돌려준다.
4. `tts_jobs` 에 `take INTEGER NOT NULL DEFAULT 0` 을 더한다. 쌓인 행은 모두 차례 0 이 된다.
5. 맡기기와 조회 응답에 `take` 를 싣는다. 있던 칸은 그대로다.

## 4. 값을 정한 까닭

| 값 | 판단 |
|---|---|
| 씨앗 `seed + take * attempts + attempt - 1` | 차례 0 은 지금 식과 같다. 한 차례의 시도 씨앗이 다른 차례와 겹치면 차례 1 의 2번째 시도가 차례 0 의 3번째 시도와 같은 소리가 될 수 있다. 시도 횟수만큼 건너뛰면 겹치지 않는다. bp-wms 맥 시험(원본 3절)이 이 식이다 |
| 상한 10 | bp-wms 는 사람이 다시 만들라고 한 문장에만 1 씩 올린다. 한 문장을 열 번 넘게 다시 듣고 고르는 일은 없다고 본다. 넘으면 글을 바꾸는 것이 맞다. 설정으로 바꾼다 |
| 상한을 api 에만 둠 | 생성기는 api 만 부른다(CR-166 3.2). 생성기는 음수만 막는다 |

## 5. 바뀌지 않는 것

- `take` 가 빠지거나 0 이면 지금과 같은 씨앗이라 같은 소리이고, 쌓인 저장분(차례 0)을 그대로 재사용한다. 59 와 운영에 쌓인 저장분은 다시 만들지 않는다
- 맡기기와 조회 창구의 나머지 요청, 응답 칸, 실패 코드, 무음 기준(CR-171), 짧은 소리 재사용 막기(CR-171), 대기 순서와 한 번에 하나(BIZ-133), 보관 기간(BIZ-135)
- 같은 음색, 같은 글, 같은 차례면 같은 소리(BIZ-134)

## 6. 반영 순서

생성기를 먼저, api 를 다음에 올린다. api 만 먼저 나가면 옛 생성기는 모르는 칸 `take` 를 버리고 차례 0 씨앗으로 만든다. 그 소리가 차례 1 작업으로 저장되어 보관 기간 동안 돌아온다. 59 는 `./deploy.sh tts` 뒤 `./deploy.sh be`, 운영은 `chaws-tts` 뒤 `chaws-be` 다.

bp-wms 는 Aimbase 가 나간 뒤에만 `take` 를 1 이상으로 보낸다(원본 5절).
