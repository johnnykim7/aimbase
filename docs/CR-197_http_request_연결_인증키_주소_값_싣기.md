## 1. 배경

- lexflow 가 법제처 국가법령정보 공동활용 Open API 를 부른다. 이 API 는 인증키를 요청 주소의 값 `OC` 로만 받는다. 머리값으로는 받지 않는다
- 지금 HTTP 연결은 인증키를 머리값으로만 싣는다. 주소 값 방식으로 등록하면 키 없이 나간다

| 2 | 경고가 안내하는 자리 | `Connection.config.defaultQuery` 는 읽는 코드가 없다. 주소는 입력 `query` 로만 만든다 | `HttpRequestTool.java:171`, `:267-288` |

## 3. 바꾸는 것

### 3-1. 주소 값으로 인증키 싣기

- `auth.type=API_KEY`, `in=query` 이고 값이 있으면 `name=value` 를 요청 주소 값에 싣는다. 값은 `value_env` 가 가리키는 환경변수가 먼저고, 없으면 `value` 다(기존 `resolveAuthValue` 그대로)
- 이름과 값은 다른 주소 값과 같이 URL 인코딩한다
- 이름이 없으면 머리값 방식과 같은 기본 이름 `X-Api-Key` 를 쓴다
- 입력 `query` 에 같은 이름이 있으면 지우고 연결 값을 싣는다. 이름은 대소문자를 가리지 않고 같다고 본다. 받는 쪽이 대소문자를 가리지 않으면 `oc` 로 보낸 값이 `OC` 를 덮을 수 있어서다
- 값이 비어 있으면(환경변수 미설정 등) 싣지 않는다. 입력 `query` 의 같은 이름 값은 그대로 나가되 기록에서는 가린다(4절)
- 쓰이지 않던 `defaultQuery` 안내 경고는 없앤다. `defaultQuery` 자체는 만들지 않는다(지금 쓰는 곳 없음)

### 3-2. 기록에서 값 가리기

연결 인증 이름이 주소 값 방식이면 그 이름의 주소 값을 `***` 로 바꾼 주소를 따로 만들어 아래에 쓴다. 실제 호출은 원래 주소로 한다.

| 순번 | 자리 | 가리는 것 |
|---|---|---|
| 1 | 감사 기록 `auditPayload.uri` (성공, 실패 모두) | 주소 값 |
| 2 | 도구 결과 요약 `summary` (성공, 실패 모두) | 주소 값 |
| 3 | 주소가 잘못됐을 때의 오류 문구 | 주소 값 |
| 4 | 알 수 없는 인증 방식 경고 로그 | 주소 |

도구 결과 `output` 에는 요청 주소가 없다(상태, 응답 머리값, 본문, 시간, 오류만).

### 3-2-1. 응답에 되돌아온 인증값 가리기 (컨타 요청 2026-11-16 06:22)

59 실측에서 법제처 판례 목록 응답의 「판례상세링크」 에 `OC=<키>` 가 그대로 되돌아왔다. 단계 결과는 실행 조회 API 로 바깥 앱에도 보이므로 응답에서도 가린다.

- 대상 인증 방식: `API_KEY`(머리값, 주소 값 모두), `BEARER`, `BASIC`. `NONE` 은 값을 싣지 않으므로 뺀다
- 찾는 글자: 연결 인증값 그대로, 그 값의 URL 인코딩 꼴, `BASIC` 은 Base64 꼴도. 긴 것부터 바꾼다
- 가리는 자리: 도구 결과의 응답 머리값 값, 본문, 감사 기록 `responseSummary`
- JSON 본문은 읽은 뒤 값(과 이름)마다 가린다. 받는 쪽이 `/` 를 `\/` 로 내보내면 원문 글자로는 찾지 못해서다. 감사 요약은 가린 결과를 다시 JSON 으로 쓴 것이다
- 값이 짧아도 가린다. 가린 탓에 본문 다른 글자가 `***` 로 바뀔 수 있으나 키가 나가는 쪽보다 낫다

### 3-3. 연결 조회 응답에서 값 가리기

- 목록(`GET /api/v1/connections`, `type` 거름 포함), 상세, 생성, 수정 응답에서 `config.auth.value` 를 `***` 로 바꾼 사본을 돌려준다. 저장된 값은 건드리지 않는다
- `value_env` 는 환경변수 이름이라 그대로 둔다
- 수정(`PUT`) 요청의 `config.auth.value` 가 `***` 이면 저장된 값을 그대로 둔다. 조회한 응답을 고쳐 다시 보내도 키가 `***` 로 바뀌지 않게 하기 위해서다
- 관리 도구(MCP) 연결 목록은 원래 이름, 종류, 상태만 돌려준다. 바꿀 것 없음(`AdminToolService.java:64-74`)
- 커넥션 그룹 응답은 연결 설정을 싣지 않는다. 바꿀 것 없음

### 3-4. 그대로 두는 것

- `in=header` 의 `API_KEY`, `BEARER`, `BASIC`, `NONE` 동작과 머리값 가림(CR-164 BIZ-132)

## 4. 범위 밖

- LLM 연결의 `apiKey`, CLI 연결의 `runner_api_key` 등 다른 설정 값도 연결 조회 응답에 평문으로 실린다. 「연결 관리」 화면이 이 값을 받아 편집 칸에 채우고 저장 때 다시 보내므로, 가리려면 화면과 수정 API 를 함께 바꿔야 한다. 이 건은 요청대로 `auth.value` 만 다룬다. 별건으로 남긴다
