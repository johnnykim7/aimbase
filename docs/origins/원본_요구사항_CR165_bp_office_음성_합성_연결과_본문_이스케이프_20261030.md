## 브리핑 요지

bp-office 가 음성 브리핑(OFC-REPORT-005)을 Aimbase 음성 합성 창구 `POST /api/v1/speech/tts` 로 만들려 한다. 창구는 있는데 bp-office 테넌트에 OpenAI 연결이 없어 503 이고, 본문 이스케이프가 큰따옴표와 줄바꿈뿐이라 역슬래시, 탭, 캐리지 리턴이 들어가면 OpenAI 로 가는 JSON 이 깨진다. 이를 고치는 CR 을 연다.

요청서 3절 2, 3, 4번이 이 건이다. 3절 1번(브리핑 요약 워크플로우)은 bp-office 가 스스로 정의해 등록하므로 이 건이 아니다(컨타 10/30 06:03). 고친 요청서(24fabce)는 음성 합성 세 건만 남겼다.

## 할 일

1. 이 레포 CR 문서를 만들어 선점한다
2. 요청서 3절 2번(고친 판 표의 2번): 음성 합성 창구 본문을 JSON 직렬화기로 만들고, 역슬래시, 탭, 캐리지 리턴, 따옴표가 든 글로 시험한다
3. 요청서 3절 1번(고친 판 표의 1번): 개발기 bp-office 테넌트에 OpenAI 연결을 어떻게 둘지 본다(다른 테넌트의 연결 방식, 플랫폼 공용 키가 있는지). 키를 새로 받아야 하면 컨타에 `[승인요청]` 으로 무엇이 필요한지 올린다. 키 값은 어디에도 쓰지 않는다
4. 요청서 3절 3번(고친 판 표의 3번): 한국어에 맞는 목소리와 모델 이름을 정해 회신한다
5. 회신 문서를 bp-office `docs/협업/REPLY_CR-042_음성_합성.md` 로 써서 컨타에 경로를 알린다

## 실행 위치와 지킬 것

- 고치는 서버는 로컬에서 먼저 돌린다. 개발기는 반영과 마지막 확인만
- 개발기 배포, 개발기 DB 쓰기, 테넌트 연결 등록은 치기 직전에 컨타에 `[승인요청]`. 운영 반영은 범위 밖
- 실제 OpenAI 음성 합성 호출은 비용이 드는 외부 발신이라 몇 번 부를지 `[승인요청]` 뒤에 한다
- 키, 토큰 값은 메시지, 문서, 커밋, 로그에 쓰지 않는다. 연결 설정에는 환경변수 이름만 둔다
- bp-office 소스는 고치지 않는다
- 다른 소비처의 음성 합성과 연결이 지금처럼 도는 것을 시험으로 지킨다
