## 1. 핵심 요구사항 (사용자 원문)

> "테넌트별로 키값을 분리해서 사용하거나 옵션에 따라 공통 계정을 같이 사용. 각 키값을 하나가 문제생기면 다른 하나를 사용할 수 있게."

**3가지 운영 패턴**:
1. 테넌트별 전용 OAuth 토큰 (격리)
2. 공통 라운드로빈 풀 폴백 (공용)
3. 한 계정 실패 시 다음 후보 자동 사용 (페일오버)

---

## 2. 현재 인프라 상태 (95% 충족)

### 이미 있는 것 (추가 코드 불필요)
- **DB 테이블**
  - `agent_accounts` — OAuth 토큰 저장
  - `agent_account_assignments` — 테넌트↔계정 매핑, specificity 레벨
- **AgentAccountPoolManager.resolveAccount()**
  - specificity 정렬 (테넌트 전용 > 공통 풀)
  - GenericCircuitBreaker 기반 페일오버
  - 선택 시점에서 실패 계정 스킵 동작함

### 갭 (신규 구현 필요)
- **호출중 자동 재시도 부재**: resolveAccount로 계정을 골라 ClaudeCodeTool을 호출한 뒤, 그 호출이 **토큰 만료 / Rate Limit / 일시 장애**로 실패하면 **그 호출 자체는 실패 반환**됨
- 즉 "선택 시점 페일오버"는 되지만 "호출 중 페일오버"는 안 됨

---

## 3. 구현 범위 (PRD 2개 예상, 번호 미정)

### PRD-A: ClaudeCodeTool 호출중 자동 재시도

**파일**:
- `backend/platform-core/src/main/java/com/platform/tool/builtin/ClaudeCodeTool.java` (수정)
- `backend/platform-core/src/main/java/com/platform/agent/account/AgentAccountPoolManager.java` (콜백 추가)

**로직**:
```
1. 실행 중 RuntimeException 또는 HTTP 4xx/5xx 감지
2. 실패 사유 분류:
   - 401/403 (토큰 만료/권한) → 재시도 대상
   - 429 (Rate Limit) → 재시도 대상
   - 5xx (서버 일시 장애) → 재시도 대상
   - 기타 (사용자 오류, 4xx) → 재시도 안 함, 즉시 반환
3. 현재 계정을 GenericCircuitBreaker에 실패 기록
4. resolveAccount() 재호출 → 다음 후보 계정 획득
5. 동일 요청을 새 계정으로 재실행
6. 설정값 `platform.claudecode.max-retry` (기본 2회) 도달 시 최종 실패 반환
7. 재시도 이력을 trace/audit log에 남김 (계정ID·실패사유·재시도횟수)
```

**설정 키 (global_config 또는 application.yml)**:
- `platform.claudecode.max-retry` = 2 (기본)
- `platform.claudecode.retry-on-http-codes` = [401, 403, 429, 500, 502, 503, 504]

### PRD-B: 운영 패턴 문서화

**파일**: `docs/guides/aimbase-ops-guide.md`

**추가 섹션**: "§ N. ClaudeCode 다중계정 운영"
- 테넌트 6개 + 공통 풀 운영 시나리오
- 계정 등록 방법 (agent_accounts INSERT, assignments 매핑)
- Circuit Breaker 임계값·리셋 시간 튜닝
- 장애 발생 시 대응 runbook
