# 원본 요구사항: CR-172 CS 상세 AI 질문 칸 위젯 파일 브라우저 허용

- 공통 규칙: `3PLcore/docs/40_브리핑/CS화면AI초안_공통규칙.md`

## 브리핑 원문

배포는 59번 서버(개발기) 하나다. AWS 는 이 건에 없다. 운영 반영도 하지 않는다.

### 문제

BO2 59 CS 상세(문의 9431)의 AI 질문 칸이 「AI 질문 칸을 불러오지 못했습니다.」 로 멈춘다.

- BO2 는 안내서대로 `aimbase-chat.umd.global.js` 를 `<script>` 로 읽는다. 이 진입 로더가 같은 폴더의 `aimbase-chat.esm.js` 와 청크를 실행 중에 읽어 오는데, 이 요청은 브라우저 교차 출처 규칙을 받는다.
- 컨타 실측(11-08 23:49, 59번 8280 포트, Origin `http://59.8.160.12:3201`):
  - `/api/v1/chat` 사전 요청: 200, 허용 머리글 있음
  - `/widget/v1/aimbase-chat.esm.js` GET: 200, 허용 머리글 없음
  - 같은 파일 사전 요청: 403
- 까닭: `backend/platform-core/src/main/java/com/platform/config/CorsConfig.java` 의 `WIDGET_PATHS` 에 `/widget/**` 가 없다. 허용 목록 `widget.allowed-origins` 에는 3201 이 이미 들어 있다(CR-WES-367).

### 할 것

1. `WIDGET_PATHS` 에 `/widget/**` 를 더한다. 허용 판정은 지금처럼 `widget.allowed-origins` 를 따른다. 관리 API 는 범위 밖 그대로다.
2. 시험으로 확인한다. 허용 주소는 머리글을 받는다. 허용하지 않은 주소는 받지 않는다. Origin 없는 `<script>` 요청은 지금처럼 200 이다.
3. 위 원인이 다르면 고치기 전에 `[이슈]` 로 올린다.

### 지킬 것

- 메인 폴더는 다른 팀 작업이 있고 로컬 dev 가 origin/dev 와 갈려 있다. origin/dev 기준 임시 작업 폴더에서 고치고, 내 커밋만 dev 로 올린다.
- 59 배포는 `./deploy.sh be`. 실행 전에 스크립트를 본다. 다른 창이 Aimbase 를 배포 중인지 먼저 보고 겹치면 끝난 뒤에 한다. 재기동 동안 다른 팀 AI 호출이 잠깐 끊긴다.
- 배포 승인: 컨타가 사용자 23:12 권장 승인 위임으로 이미 승인했다. 다시 묻지 않는다.

### 완료

59 에서 위 세 경우를 다시 재 본 값과 배포 커밋을 컨타에게 `[완료 보고]` 로 올린다. 화면 재확인은 컨타가 BO2 창에 시킨다. 운영 반영 전이므로 스스로 완 처리하지 않는다.
