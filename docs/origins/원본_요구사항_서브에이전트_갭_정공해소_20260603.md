## 잔여 갭 3건 (CR-093 범위)

### 갭 ① AgentType 도구 필터가 ChatRequest로 안 넘어감 🔴 (코드 갭, 패치 필요)

**현상**:
- `AgentType.PLAN`이 `allowedToolsCsv = "read,search,glob,grep"` 들고 있음 (AgentType.java:20)
- `AgentType.PLAN.isReadOnly() = true` 정의됨
- 하지만 `SubagentRunner.executeAgent`가 `ChatRequest` 생성 시 `toolFilter` 필드를 채우지 않음 (SubagentRunner.java:258-267)
- grep 결과: SubagentRunner 안에 `allowedTools`/`toolFilter`/`ToolFilter` 0회

**결과**:
- PLAN 에이전트도 BashTool/FileWriteTool 호출 가능
- V57 시스템 프롬프트가 "READ-ONLY — no writes, edits, commits or shell commands with side effects" 강제하지만 코드 레벨 보장 아님
- 모델이 프롬프트 무시하면 뚫림

**수정 방향**:
- `SubagentRunner.executeAgent`에서 `agentTypeRegistry.getConfig(req.agentType()).allowedTools()` 조회
- `ChatRequest.toolFilter` 또는 동등한 `ToolFilterContext` 필드에 주입
- `OrchestratorEngine`이 이를 받아 `ToolCallHandler` 도구 루프에서 필터링

**수정 난이도**: 수 줄. 코드 위치·필드 모두 명확.

### 갭 ② Plan FSM 자동 진입이 PLAN 에이전트에 없음 🟡 (설계 판단 필요)

**현상**:
- `PlanService` + `PlanStateMachine`(DRAFT/EXECUTING/VERIFYING/ABANDONED FSM)이 존재 (PlanService.java:73, 87, 136)
- `PlanStateMachine.validateTransition`이 상태 전이 검증
- `EnterPlanModeTool` / `ExitPlanModeTool` 도구 등록되어 있음
- 하지만 SubagentRunner가 `agentType == PLAN`인 자식 띄울 때 `PlanService.createPlan`을 자동 호출하지 않음

**결과**:
- PLAN 에이전트가 V57 프롬프트로 Plan **구조**(Goal/Steps/Risks/Rollback)는 강제 출력
- 하지만 FSM 상태 전이(DRAFT→EXECUTING→VERIFYING)는 모델이 자발적으로 EnterPlanModeTool 호출해야 작동
- 안 부르면 일반 에이전트처럼 동작 — Plan 검증 단계가 누락될 가능성

**수정 방향 (2안)**:
- **A안**: SubagentRunner가 `agentType == PLAN`일 때 `PlanService.createPlan(sessionId)`을 자동 호출하고 자식 컨텍스트에 plan_id 주입. ExitPlanMode 자동 호출
- **B안**: 현 상태 유지 — V57 프롬프트 구조 강제로 충분 판단. FSM은 선택적

**설계 판단 필요**:
- Plan FSM이 정말 PLAN 자식에 강제될 가치가 있는가?
- 프롬프트 구조 강제 vs FSM 강제의 실제 품질 차이 측정 필요
- 사용자 결정 후 진행

### 갭 ③ Nesting 깊이 보호 미확인 🟡 (실측 미완)

**현상**:
- SubagentRunner에 재귀 깊이 카운터·런어웨이 방지 코드 grep 0회
- `subagent.*subagent`, `recursion`, `depth`, `nesting` 키워드 모두 코드 0회
- 자식이 자기 안에서 또 AgentTool(`Agent`/`Task`)을 호출 가능한지 확인 안 함
- ToolFilter/세션 등록 정책에 따라 막혀있을 수도 있고 안 막혀있을 수도 있음

**위험 시나리오**:
- 자식이 무한 재귀로 자기 자식 spawn → 토큰·예산 폭발
- 깊이 카운터 없으면 정책 차단 불가

**수정 방향**:
1. 먼저 **실측 확인** — 자식 세션의 ToolRegistry에 AgentTool이 노출되는지 코드 추적
2. 노출되면 → SubagentContext에 `depth` 필드 추가 + 임계값(예: 3) 초과 시 차단
3. 노출 안 되면 갭 아님 — 메모리 정정만

**수정 난이도**:
- 확인 단계: 짧음 (코드 추적 30분 내)
- 차단 추가: 중간 (SubagentContext + ToolFilter 연동)
