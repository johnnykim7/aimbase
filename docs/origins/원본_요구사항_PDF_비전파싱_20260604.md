## 4. openclaude 분석 결과 (실측)

PDF가 LLM에 들어가는 단일 경로 = FileReadTool.callInner() (첨부/at-mention/AGENT 도구 호출 공유).

| 조건 | 처리 | LLM 형식 |
|---|---|---|
| ≤3MB & 지원 모델 | readPDF() base64 통째 | document block (application/pdf) |
| >3MB or 미지원(haiku) | pdftoppm 페이지→JPEG(100 DPI) | image block 배열 (image/jpeg) |

상수 (apiLimits.ts):
- PDF_EXTRACT_SIZE_THRESHOLD = 3MB
- PDF_MAX_PAGES_PER_READ = 20
- PDF_AT_MENTION_INLINE_THRESHOLD = 10
- PDF_TARGET_RAW_SIZE = 20MB (document block 최대)

핵심 메커니즘:
- isPDFSupported() = haiku 제외 (pdfUtils.ts:59)
- tool_result 에는 메타데이터 텍스트만, 실제 PDF/이미지는 newMessages 의 별도 user 메시지(isMeta:true)로 컨텍스트 스트림에 주입.

## 5. Aimbase 현황 실측

- ✅ ChatController.resolveDocumentBlock — supportsPdf 면 base64 통째 (크기 게이트 없음)
- ✅ AnthropicAdapter.toDocumentBlockParam — application/pdf base64 document block 생성
- ✅ 사이드카 poppler-utils + pdf2image 설치됨 (CR-092)
- ✅ OllamaAdapter IMAGE_ONLY + images base64 배열 경로 (로컬 비전 입력)
- ❌ 3MB 크기 게이트 (>3MB 페이지 이미지화 분기) 없음
- ❌ ToolResult.newMessages — 도구가 멀티모달 블록을 컨텍스트에 주입하는 경로 없음 (content=String만)
- ❌ ContentBlock.ToolResult content = String (멀티모달 불가)
- ❌ 로컬 비전 모델 (Ollama 텍스트 모델 6개뿐)

## 6. 확정 설계 방향

1. **방식**: openclaude 1:1 — ≤3MB document block / >3MB poppler 이미지화 → image blocks
2. **범위**: 두 경로 모두 (ChatController 첨부 + ParseDocumentTool 도구 경로)
3. **>3MB**: openclaude 동일 — poppler 이미지화 (사이드카 텍스트 추출 경로 안 씀)
4. **비전 주체**: 모델 비전 (Anthropic 기본 + 로컬 Ollama 비전 옵션)
