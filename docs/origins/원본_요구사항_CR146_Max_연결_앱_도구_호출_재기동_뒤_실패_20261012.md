# 원본 요구사항 CR-146: Max 연결 앱 도구 호출이 앱 재기동 뒤 옛 연결로 실패하는 결함

- 접수: 2026-10-12
- 요청: 입찰대행 플랫폼(bidding-agency-platform) CR-150 창. 결재는 사용자, 운영 반영은 사용자 07:23 "1"(AWS 반영)

## 원문 요지

> WJbid 운영이 AWS(54.116.150.247)로 옮겨졌다. Anthropic API 키 연결은 크레딧이 없어 bidding_system 테넌트의 AI 작업을 우진 Max 구독 CLI 연결로 옮기는 중이다.
> 앱 MCP 도구를 써야 하는 제안서 작업 5개와 관리자 수정 채팅은 tool_mode AIMBASE 로 켠 cli-runner-bidding-tools-001 로 옮겨야 하는데 도구 호출이 실패해 막혀 있다.

## 증상(AWS 실측 10/12)

- cli-runner-bidding-tools-001 로 채팅하면 CLI 에 mcp__aimbase-server__get_opportunity 등 앱 도구가 보인다
- 실제 호출은 "Client failed to initialize by explicit API call" 로 실패한다
- 앱(bidding-agency, 8183)이 재기동한 뒤부터 그렇다. REST 재연결(POST /api/v1/mcp-servers/2176f92d-a167-476d-8ced-9687eb598e76/reconnect)과 헬스체크 재연결로도 풀리지 않고, Aimbase api 를 재기동하면 풀린다
- 워크플로우 TOOL_CALL 경로와 API 연결 채팅 경로는 영향 없음

## 요청자가 짚은 원인(확인 요청)

1. ServerMcpConfig.syncOnce 가 도구를 처음 노출할 때 핸들러가 그 순간의 실행기를 잡는다. 이름이 이미 있으면 다시 등록하지 않아, 외부 MCP 재연결로 ToolRegistry 의 실행기가 바뀌어도 /mcp 는 옛 실행기를 부른다
2. 옛 실행기의 호출 중 재연결은 boundedElastic 스레드에서 돌아 테넌트 정보가 없고, JDBC 조회가 master DB 로 가서 "relation does not exist" 로 실패한다

## 요구

- /mcp 핸들러가 호출 시점에 이름으로 지금 실행기를 찾게 한다
- 재연결 경로가 테넌트 정보를 잃지 않게 한다(필요한지는 1번 수정 뒤 재현으로 판단)
- 반영 대상은 AWS Aimbase api 컨테이너 하나. 지금 이미지를 롤백용 태그로 남긴다. 남의 미완성 작업이 운영에 섞이지 않게 한다
- 옛 서버(59.8.160.12) 반영은 따로 승인요청
- 상용 앱 /api/mcp 는 10/12 00:46 부터 X-API-Key 머리글이 있어야 열린다(앱 CR-144). 재연결 경로에서 머리글이 빠지지 않게 함께 본다(요청자 알림 10/12)
