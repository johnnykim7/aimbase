## 3. 구현 범위

### PRD-A: 병렬 도구 실행
1. `ToolCallHandler.executeLoop():264-285` 리팩터링
2. `safeCalls` 리스트를 `CompletableFuture.allOf(...)`로 병렬 디스패치
3. Virtual Threads 이미 활성화되어 있으므로 `Executors.newVirtualThreadPerTaskExecutor()` 사용
4. `unsafeCalls`는 기존 순차 유지
5. 예외 처리: 한 도구 실패가 다른 도구 실행 차단하지 않도록 `exceptionally()` 체인
6. 순서 보존: 결과 취합 시 원래 tool_use 순서대로 재정렬
7. 테스트: safeCalls 3개 병렬 디스패치 시간 측정 (단순 sum < max * N 확인)

### PRD-B: Memory/Skill Prefetch
1. `OrchestratorEngine.chat()` 진입 직후 prefetch 시작
2. `CompletableFuture<MemoryContext> memoryFuture = CompletableFuture.supplyAsync(...)` 
3. `CompletableFuture<List<Skill>> skillFuture = CompletableFuture.supplyAsync(...)`
4. ContextAssembly 이전 단계에서 둘 다 kick off, assembly에서 `.get()` 합류
5. LLM 호출 직전 시점까지 이미 완료되어 있을 가능성 높음 → 체감 지연 감소
6. 실패 시 폴백: 빈 컨텍스트로 진행 (에러로 LLM 호출 차단 금지)

### PRD-C: Prompt Cache TTL 소스별 분기
1. `AnthropicAdapter.java` 의 cache_control 포인트 분리:
   - System prompt: 1h TTL (cache_control.ttl = "1h", long-lived)
   - Tool schemas: 5m TTL (tool 추가/제거 시 invalidation)
   - Recent messages: cache 미적용 또는 5m
2. `CacheControlStrategy` 인터페이스 신설 (source별 정책 주입)
3. 측정: Anthropic 응답 `cache_creation_input_tokens`, `cache_read_input_tokens` 로 hit율 추적
4. `UsageLog`에 cache hit 비율 기록

### PRD-D: Hook 백그라운드 실행
1. `HookEvent` enum에 `synchronous: boolean` 속성 추가
2. 게이팅 hook (PRE_TOOL_USE, PERMISSION_REQUEST 등) → 동기 유지
3. 감사/로그 hook (POST_TOOL_USE, SESSION_END 등) → `@Async` 또는 `CompletableFuture.runAsync(..., virtualExecutor)`
4. `HookDispatcher.executeAndAggregate()` 분기 처리
5. 비동기 hook 실패는 로그만 남기고 메인 플로우 차단 금지

## 4. 측정 지표 (KPI)

구현 전후 비교 필수:
- **첫 토큰 지연 (TTFT)**: prefetch 적용 전후
- **Tool 병렬 처리 시간**: N개 safeCalls 동시 실행 vs 순차
- **Cache hit 비율**: source별 분기 적용 전후
- **턴 총 지연 시간**: hook 비동기화 전후

---

## 5. 결정 필요 사항

1. **병렬 도구 최대 동시 실행 수**: 제한 둘지 (기본 무제한 vs 10개 캡)?
2. **Cache TTL 분기 정책**: system 1h / tools 5m / messages 미적용 — 맞나?
3. **어느 Hook을 비동기로**: 게이팅 vs 로그성 분류 기준 — 전체 26종 중 어떤 것을?
4. **Prefetch 실패 시**: 전체 요청 실패 vs 폴백 진행 — 폴백 권장?
