# 원본 요구사항 CR-189 서버 도구 통로 테넌트 누락으로 cron_list 실패

- 받은 때: 2026-11-14 01:06 (컨타 aimbase-56899 브리핑)
- 사용자 승인: 2026-11-14 01:00 /전승 「CR-185 cron_list 결함 별건 CR 발번해 고침」
- 실행맵: `docs/기록/실행맵_채팅_위젯_고도화.md` 14번 행(갈래 추가)

## 브리핑 원문

### 주제
- 위젯 대화(CLI 실행기)에서 서버 도구 통로로 cron_list 를 부르면 테넌트가 실리지 않아 실패한다. 이번 CR 들 전부터 있던 결함이다.
- CR-185(위젯 안 승인과 거절)가 59 확인 중 찾았다(2026-11-13). 원인을 처음 본 창은 CR-185(컨타를 거쳐 물을 수 있다).
- 같은 통로를 쓰는 다른 서버 도구도 테넌트가 빠지는지 전수로 본다. cron_list 하나만 고치고 닫지 않는다.

### 원천
- CR-185 보고 원문: "서버 도구 통로가 테넌트를 전달하지 않아 cron_list 가 실패하는 기존 결함".

### 참고 위치
- `docs/CR-185_위젯_안_승인과_거절.md` 59 확인 절.
- 앞 CR: CR-121(원격 에이전트 도구가 MCP 에 노출되지 않던 누락), CR-125(관리 MCP 테넌트 교차 오염), CR-142(사이드카 테넌트 DB 라우팅), CR-182(실행기 통로 channel_tools, X-Aimbase-Channel-Tools).
- 테넌트 식별은 `TenantContext.getCurrentTenantId()`. 마스터 전용은 `/api/v1/platform/**` 뿐이다.

## 고칠 방향 결정

- 2026-11-14 컨타 [승인] ①: 같은 통로의 테넌트와 대화 세션 누락 전부 + cron_delete 자기 테넌트만 + remote_trigger 테넌트 되돌리기 (사용자 권장안 승인을 컨타에 위임)
