```
R3  삭제 API를 제공해 주세요 — ① 사용자별( user_ref ) ② 사건 대화별( share_key ) ③ 사무소 전체
    (사무소 단위 묶음 기준 협의). 첨부 파일 포함. 그리고 기본 보관 기간을 알려 주세요.      (관련 이슈 I2)
```

```
     · 2차: 전체 사무소 확대, 사무소 관리자가 AI 채팅을 끌 수 있는 설정 추가
```

## AI 파트 답변 초안 (2026-11-27, 아직 보내지 않음) 중 이 CR 에 걸리는 줄

- R3: 제공 중은 대화 1건 삭제 `DELETE /api/v1/conversations/{sessionId}`(소유자, 삭제 표시). 추가 개발로 사용자별, 사건 대화별, 사무소 전체 일괄 삭제 API 와 완전 삭제(물리 삭제). 기본 보관 기간은 대화는 삭제 전까지, 첨부 24시간, 음성 응답 파일 7일.
- Q4: 동의. 형식 제안 user_ref 는 `(사무소 ID):(사용자 ID)`, share_key 는 `lexflow:case:(사무소 ID):/case/[id]:(사건 ID)`. 삭제 API 는 이 접두어 기준으로 동작하도록 설계한다. (확정 아님)
- Q9: 특정 질문·답변만 삭제하는 기능은 없다. 질문 수정과 다시 만들기는 그 질문부터 이후 기록을 삭제하는 되감기 방식. 개별 질문·답변 삭제는 추가 개발 항목으로 검토.
- 4장 추가 개발 표 4번: 일괄 삭제 API(사용자별, 사건별, 사무소별)와 완전 삭제. R3, Q4, Q9. 규모 중. 3차(첨부) 전 적용 목표. 개별 질문·답변 삭제 포함 여부 검토.

## 컨타 브리핑이 정한 이번 CR 범위 (2026-11-27)

- 소비앱 서버가 연동키로 호출하는 삭제 API: 사용자별(user_ref), 사건 대화별(share_key), 사무소 전체(user_ref·share_key 접두어 등 묶음 기준). 대화·턴·첨부·음성 파일 등 물리 삭제 범위.
- 개별 질문·답변 삭제를 이 CR 에 넣을지(Q9) 판단과 그 근거.
- 기본 보관 기간 정리(현재 값과 바꿀지).
- API 규격은 docs/guides 에.
