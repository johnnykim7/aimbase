## 1. 배경

OpenClaude 전수 대조 결과, Aimbase는 **장기 세션 복원**과 **테넌트 커스텀 지침 주입** 메커니즘이 부재함. 특히 #8은 사용자 요구(테넌트 관리자가 UI로 시스템 지침 편집)와 직결되는데, 기존 CR-036(프롬프트 외부화)이 **글로벌 스코프만** 지원하고 테넌트·프로젝트 스코프를 설계에서 누락했음.

## 2. 코드 검증 결과

### 2-1. Session Resume + Compact Boundary (#4) — 🔴 MISSING
- **현재**: grep 결과 `resume`, `CompactBoundary`, `compact_boundary` 전체 Java 소스 0건
- `/sessions/{id}/resume` 엔드포인트 없음 (SessionPlanController에 GET만 있음)
- `SystemCompactBoundaryMessage` 같은 메시지 타입 마커 없음
- ContextWindowManager는 circuit breaker 카운터만 있고 **메시지 레벨 마커 부재**
- **OpenClaude**: `sessionStorage.ts` JSONL + `--resume sessionId`, `message.ts`의 `SystemCompactBoundaryMessage` 타입

### 2-2. Stop Hooks 재시도 강제 (#5) — 🔴 MISSING
- **현재**: `HookDispatcher.java:75-100` BLOCK/APPROVE/PASSTHROUGH 집계만
- `ToolCallHandler` iteration 로직(:219-234)은 **finishReason만 체크**, STOP hook의 재진입 강제 없음
- STOP 이벤트는 발행되지만 루프 재진입 없음
- **OpenClaude**: `query/stopHooks.ts` — 턴 종료 후 실행, todo 미완료·검증 실패면 **재질의 강제**

### 2-3. 테넌트/프로젝트 커스텀 지침 (#8) — 🔴 MISSING (Aimbase식 재정의됨)
원래 "CLAUDE.md 파일 주입"으로 제안했으나 Aimbase가 SaaS이므로 **테넌트/프로젝트 DB 필드 + UI 편집** 방식으로 재설계.

**코드 검증**:
| 위치 | 상태 |
|---|---|
| `prompt_templates` 테이블 (CR-036) | 글로벌만, tenant_id/project_id/scope 컬럼 **없음** |
| `TenantEntity` (Master DB) | DB 접속 정보만, custom_instructions 컬럼 **없음** |
| `ProjectEntity` (Tenant DB) | id/name/description만, 지침 필드 **없음** |
| `ContextAssemblyEngine.assembleSystemPrompt():346-394` | 글로벌 key(`core.system.prefix`)만 조회, 테넌트 필터 **0** |
| `PromptTemplateService.getTemplate(key)` | tenant-agnostic |
| `global_config` (CR-040) | 오케스트레이터 튜닝값만, 지침 키 **없음** |

**증거**: `prompt_templates` 테이블 Flyway V46에 scope 컬럼 자체가 없음 — 설계 누락 확정.

## 3. 구현 범위

### PRD-A: Session Resume + Compact Boundary
1. **메시지 타입 확장**
   - `ConversationMessageEntity`에 `message_type` enum 추가:
     - USER, ASSISTANT, TOOL_USE, TOOL_RESULT (기존)
     - **COMPACT_BOUNDARY** (신규) — 압축 경계 마커
2. **압축 시 boundary 메시지 삽입**
   - `ContextWindowManager.trimWithState():86-150` 에서 compact 수행 시
   - 압축된 메시지 그룹 뒤에 `[COMPACT_BOUNDARY {summary, compacted_count, tokens_saved}]` 메시지 append
3. **Resume 엔드포인트**
   - `POST /api/v1/sessions/{sessionId}/resume`
   - 응답: 압축 경계 이후 메시지 체인 + 보존 context
   - 장시간 중단된 세션 재개 시 전체 재조립 가능
4. **프론트 연동 (optional)**
   - 대화방 목록에서 "재개" 버튼
   - 압축 경계 UI 표시 (접을 수 있는 구분선)

### PRD-B: Stop Hooks 재시도 강제
1. **HookEvent.STOP 타입 강화**
   - 현재: 단순 이벤트 발행
   - 신규: BLOCK 결정 시 **루프 재진입 강제**
2. **ToolCallHandler.executeLoop() 수정**
   - 턴 종료 직전 STOP hook 호출
   - decision == BLOCK이면:
     - BLOCK 사유를 새 user 메시지로 삽입 ("다음을 확인해주세요: TODO 미완료...")
     - 루프 재진입 (max_iterations 내)
3. **사용 사례**
   - TodoWrite 모두 미완료인데 turn 종료 시도 → BLOCK으로 재질의
   - 테스트 실행 tool 결과가 FAIL인데 종료 시도 → BLOCK으로 재질의
   - 사용자 정의 검증 hook

### PRD-C: 테넌트/프로젝트 커스텀 지침

#### C-1. DB 스키마 변경 (Flyway)
**옵션 1 (권장)**: `prompt_templates` 테이블 확장
```sql
-- V48__cr049_prompt_scope.sql (tenant DB)
ALTER TABLE prompt_templates
  ADD COLUMN scope VARCHAR(20) NOT NULL DEFAULT 'GLOBAL',
  ADD COLUMN project_id VARCHAR(100) NULL;
-- scope: GLOBAL | TENANT | PROJECT
-- tenant_id는 tenant DB이므로 자동 스코프됨

CREATE INDEX idx_prompt_templates_scope ON prompt_templates(scope, project_id);
```

**옵션 2**: TenantEntity·ProjectEntity에 `custom_instructions TEXT` 직접 추가 — 간단하지만 버저닝 불가

**권장 옵션 1** (prompt_templates 확장) — CR-036 기반 재활용, 버저닝·활성화 플래그 재사용

#### C-2. PromptTemplateService 확장
```java
public String getTemplate(String key, String tenantId, String projectId);
```
- 우선순위: PROJECT > TENANT > GLOBAL
- 없으면 상위 스코프로 폴백

#### C-3. ContextAssemblyEngine 수정
- `assembleSystemPrompt()` 에서:
  1. GLOBAL `core.system.prefix` 로드 (기존)
  2. TENANT override 있으면 append
  3. PROJECT override 있으면 append
- 최종 system prompt = GLOBAL + TENANT + PROJECT 순서

#### C-4. API 신설
- `GET /api/v1/prompt-templates?scope=TENANT` — 테넌트 지침 조회
- `PUT /api/v1/prompt-templates` — 테넌트 관리자가 편집
- `GET /api/v1/projects/{id}/instructions` — 프로젝트 지침
- `PUT /api/v1/projects/{id}/instructions` — 편집

#### C-5. FE 설정 화면
- **테넌트 설정 페이지**: "시스템 지침" 편집 필드 (TextArea, monaco editor)
- **프로젝트 상세 페이지**: "프로젝트 지침" 편집 필드
- 미리보기: "최종 system prompt = GLOBAL + TENANT + PROJECT" 시각화

## 4. 결정 필요 사항

1. **Resume 동작 범위**: 세션 TTL(24h) 지난 세션도 복원? 아니면 active만?
2. **Compact Boundary 메시지 UI 표시**: 사용자에게 보여줄지 숨길지?
3. **Stop Hook BLOCK 표현 방식**: 새 user 메시지로 주입 vs 시스템 reminder vs 에러 throw?
4. **Stop Hook 무한루프 방지**: 같은 BLOCK이 반복되면 어떻게? (N회 초과 강제 종료?)
5. **지침 스코프 병합 방식**: append (cascade) vs override (replace)?
6. **지침 버저닝**: 편집 이력 보관? CR-036 템플릿처럼 version 관리?
7. **지침 권한**: 테넌트 관리자만 편집? 슈퍼어드민도 글로벌 편집?
