# 원본 요구사항 — 채팅 UI + 워크스페이스 컨텍스트 + 실시간 도구 이벤트

- **대상 CR**: CR-045
- **요청일**: 2026-04-15
- **요청자**: sykim
- **배경**: FlowGuard 시나리오 추출 작업을 Claude Code CLI와 Aimbase Chat API로 각각 수행하여 품질·비용·시간을 비교하는 벤치마크 실험 준비 중, Aimbase 측 환경이 Claude Code와 비대칭임이 드러남.

## 1. 발단 — 벤치마크 실험 지시서 (사용자 작성)

사용자가 다른 세션용 실험 지시서를 제시:

- **목적**: FlowGuard 시나리오 추출을 Claude Code(VS Code) vs Aimbase Chat API로 동일 태스크 수행 후 품질/비용/시간 비교
- **Claude Code 경로**: CLAUDE.md를 읽어서 FlowGuard 사용법 숙지 → FlowGuard에서 가이드 다운로드 → OMS 소스 검색하며 시나리오 생성 → 사용자와 5~6회 상호작용
- **Aimbase 경로**: `POST /api/v1/chat/completions`를 세션ID 유지하며 호출, MCP 도구 자동 활용
- **판단 기준**: 품질 동등 시 ClaudeCliLlmAdapter 작업 불필요

사용자 제기 핵심 의문: "CLAUDE.md에 해당하는 시스템 프롬프트를 Aimbase에 어떻게 동등하게 주입할 것인가?"

## 2. 1차 검토 — 공정 비교 블로커 3개 식별

에이전트가 3가지 환경 불일치 지적:
1. **시스템 프롬프트/지침 전달** — Aimbase는 CLAUDE.md 자동 로드 없음
2. **파일시스템 접근 (working_directory)** — OMS 소스 경로를 도구에 전달할 수단
3. **FlowGuard MCP 연결** — Connection에 MCP 서버 등록 필요

사용자 지시:
- working_directory 메커니즘 존재 여부 **우선 조사** ("예 확인해보세요 제가 위에 적은 시나리오대로 동작되는지 먼저 확인해주세요. 하다 못해 fe에 채팅창이 있는지도 봐야하고, 없으면 어떻게 할지 검토해야하고")
- 시스템 프롬프트는 "알아서 판단", 임시 테스트니 system_prompt로도 OK

## 3. 조사 결과 — 블로커 확정

### 3.1 working_directory 파이프라인 단절
- **도구 레이어**: BashTool/FileReadTool/GrepTool/GlobTool 모두 `WorkspaceResolver.resolve(ctx, path)` 기반으로 정상 동작 준비 완료
- **Orchestrator**: `OrchestratorEngine.chat()`에서 `ToolContext.workspacePath = "/"` **하드코딩** (OrchestratorEngine.java:220-224)
- **ChatRequest**: `workingDirectory` 필드 **부재** (ChatRequest.java:15-27)
- **결론**: 도구는 준비됐으나 Chat API → Orchestrator → ToolContext 경로에서 값이 끊겨 OMS 소스 폴더 지정 불가

### 3.2 FE 채팅 UI 부재
- `frontend/src/pages/` 아래 Chat/Playground 페이지 없음
- `components/chat/` 디렉토리는 빈 폴더
- `SessionDetail.tsx`에 "대화 탭 (예정)"만 표시, 조회 전용
- `api/` 아래 chat 전용 클라이언트 없음 (sessionsApi만 존재)

### 3.3 Chat API 자체는 준비됨
- `POST /api/v1/chat/completions` (ChatController.java:25-248) — SSE 스트리밍 지원 (`delta`/`done` 이벤트)
- 세션 재개: Redis + DB 듀얼 저장, TTL 24h, session_id 재사용 시 자동 복원
- `GET /api/v1/conversations/{sessionId}` — 메시지 히스토리 조회 API 존재
- 도구 호출: `content` 블록에 `tool_use`/`tool_result`/`text`/`thinking` 타입 구분
- **단점**: SSE 이벤트 타입이 `delta`/`done` 두 개뿐 — 도구 호출 실시간 표시 불가
- **단점**: thinking 블록이 스트림에서 필터링됨 (OrchestratorEngine.java:471)
