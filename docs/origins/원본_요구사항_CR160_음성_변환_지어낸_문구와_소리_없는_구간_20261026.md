# 원본 요구사항: CR-160 음성 변환이 지어낸 문구와 소리 없는 구간 거르기

- 받은 날: 2026-10-26 22:50
- 보낸 곳: 컨타 bp-office-39431 브리핑(bp-office 실행맵 `docs/기록/실행맵_Sprint4_7_9.md` 15번 행)
- 사용자 결정: 10/26 22:35 /전승 ①「aimbase 에 CR 을 따로 두어 소리 없는 구간과 흔한 지어낸 문구를 걸러 점검으로 올리기」

## 브리핑 원문

### 무엇

음성 변환(stt_local)이 알아듣지 못한 녹음에서 실제로 하지 않은 말을 지어내는 것을 걸러, 소비처가 사람 확인 대상으로 올릴 수 있게 한다. bp-office 확인에서 4초 녹취(원문 45)가 「자막제공자」 한 마디로 변환됐고, 의심 구간 찾기도 그 한 마디만 봐서 0건으로 끝나 인식 오류 점검이 오르지 않았다.

### 이 건의 자리

- 컨타: bp-office-39431. bp-office 실행맵 15번 행.
- 앞 건: aimbase CR-158(음성 변환 연결 bp_office 테넌트 stt_local, 맥 전사 사이드카 자동 상주).
- 관찰 원문: bp-office CR-014 문서의 관찰 줄. 원문 45 는 개발기 bp_office DB 에 있다(읽기만).
- bp-office 쪽 결과 읽기와 의심 구간 워크플로우(bp-office-suspect-segments)는 CR-015 창(bp-office-41170)이 안다. 결과 모양을 바꿔야 하면 그 창과 `[질의]` `[회신]` 으로 맞추고, 직접 전송이 훅에 막히면 컨타로 보낸다.

### 할 일

1. 지금 stt_local 변환 결과에 소리 없음 판단 값(무음 확률, 구간별 신뢰도 등)이 있는지, 사이드카와 aimbase 어디서 버려지는지 소스로 확인한다.
2. 소리 없는 구간과 흔한 지어낸 문구를 결과에서 표시한다. 문구 목록과 기준값은 코드에 박지 않고 설정(DB 설정이나 환경설정)으로 둔다.
3. 표시된 결과가 소비처에서 의심 구간이나 인식 오류 점검으로 오르게 한다. bp-office 쪽 수정이 필요하면 코드 전에 컨타에 `[알림]` 으로 알린다(bp-office 소스는 그 레포 CR 로 고친다).
4. 다른 테넌트의 음성 변환 결과가 바뀌는지 확인하고, 바뀌면 코드 전에 컨타에 ①(권장) ② 를 붙여 묻는다.
5. 단위시험을 더하고, 개발기 반영 뒤 원문 45 와 같은 짧은 녹음 한 개, 정상 녹음 한 개로 실제 확인한다.

### 지켜야 할 것

- 원격 재기동, 개발기 DB 쓰기 직전에 컨타에 `[승인요청]` 을 올린다. 우진비드 AWS 는 건드리지 않는다.
- 키 값은 화면, 기록, 메시지에 찍지 않는다.

### 완료 보고

`[완료]` 에 CR 번호, dev 커밋, 개발기 반영 여부, 시험 건수, 짧은 녹음과 정상 녹음의 실제 확인 결과, 시험항목 줄을 적는다.
