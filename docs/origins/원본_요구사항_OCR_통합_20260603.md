## 사용자 발언 (원본)

> 부분 지원 (반쪽짜리). 완성된 OCR 기능은 없음.
>
> 실측 내역
> 1. python-sidecar read_pdf MCP 툴에 ocr_enabled 파라미터는 있지만, 실제 호출 안 됨
>
> server.py:848-863: MCP 툴 시그니처에 ocr_enabled: bool = False 노출
> document_reader.py:403-423: read_pdf() 함수가 파라미터를 받음
> document_reader.py:440-472: 그런데 _read_pdf_pdfplumber 내부에서 ocr_enabled 변수가 한 번도 사용되지 않음 — pdfplumber extract_text()만 호출. 파라미터를 받아놓고 안 씀.
> pytesseract import 0건, 호출 0건
>
> 2. Dockerfile에 tesseract-ocr 바이너리는 설치됨
>
> python-sidecar/Dockerfile:7,15: tesseract-ocr apt 설치. 주석에 "스캔 PDF OCR (read_pdf ocr_enabled, unstructured hi_res)" 명시
> 즉 인프라(바이너리)는 준비됐는데 Python 코드에서 활용 안 함
>
> 3. Backend PdfTextExtractor는 PDFBox 텍스트 추출만
>
> OCR 호출 없음. 텍스트가 박힌 PDF만 처리. 스캔 이미지 PDF는 빈 텍스트로 처리됨
>
> 4. 이미지/사진 OCR은 없음
>
> 이미지 파일을 받아서 텍스트 뽑는 별도 API/툴 0건
> 단, Vision 모델(Claude/GPT-4o)로 이미지 첨부 → 본문 텍스트 읽기는 CR-061에서 구현됨 (chat_attachments) — 이건 LLM Vision이지 전통적 OCR 아님
>
> 한 줄 답
> "전통적 OCR(Tesseract)은 인프라만 깔려 있고 코드에서 미연결. 실질 OCR이 필요하면 (a) Vision 모델 우회로 충분하면 CR-061 이미지 첨부 사용, (b) 진짜 Tesseract OCR이 필요하면 _read_pdf_pdfplumber에 pytesseract 연결 작업 필요(소규모 CR)."
>
> 위와 같이 제대로된 온전한 ocr기능을 구현하고 싶습니다.
>
> CR번호 및 제목 확정해주시고 진행 부탁합니다. 설계 케스케이드는 몰아서

## 확정 사항

- **CR 번호**: CR-092
- **제목**: 전통적 OCR 통합 (Tesseract) — 스캔 PDF / 이미지 텍스트 추출
- **범위 (사용자 결정)**: Full (sidecar + BE + MCP + 가이드) — 4가지 모두 포함
- **설계서**: `docs/T3-15_CR-092_OCR_설계서.md`
- **추정**: 4.2 MD (P1~P5)
- **버전**: v8.15.0 (예약)

## 분리 원칙

Vision 모델(CR-061) 과 자동 라우팅하지 않는다. 호출자가 명시 선택.
- RAG 인제스션: OCR 기본
- 위젯 채팅: Vision 기본
- BE `PdfTextExtractor` 만 텍스트 0자 fallback 으로 OCR 자동 시도 (BIZ-107)

## Non-Goals 확정

- 수식/표 OCR
- 손글씨 OCR
- 다국어 자동감지
- OCR 진행률 SSE 스트리밍
- KnowledgeSource OCR strategy 선택 UI
