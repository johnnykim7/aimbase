## 1. 배경

Claude Code 사용 중 "Agent로 정밀 검색합니다" 같은 서브에이전트 위임 UX를 경험한 사용자가
"이게 우리 Aimbase에도 되는가?"를 질문. 3개 영역 병렬 점검 결과:

| 영역 | 상태 | 근거 |
|------|------|------|
| 코어 인프라 | ✅ 거의 완성 | SubagentRunner/WorktreeManager/AgentOrchestrator + Task 6종 + SendMessage 모두 완성, 테스트 존재 |
| Built-in Agent 프롬프트 | 🔴 빈약 | 5타입 평균 118B/16단어, 한 줄 선언문 수준. 심도/전략/요약 지침 전무 |
| FE/SSE UX | 🔴 부재 | StreamEvent 5종만 존재(subagent_* 없음), ToolUseBlock 분기 없음, 사전 안내 미주입 |

즉 **엔진은 있는데 사용자 눈에 안 보이는** 상태. Claude Code 수준의 자연스러운 위임 UX로 끌어올린다.

## 4. 목표 (Outcome)

사용자가 챗 UI에서 자연스럽게 서브에이전트 위임 흐름을 경험한다:

1. 메인 에이전트가 대규모 탐색 필요 판단 → Task/Agent 도구 호출
2. 챗에 **사전 안내 라인** 표시 ("Explore 서브에이전트로 정밀 탐색을 시작합니다")
3. **전용 Task 블록**이 실행 중 상태로 렌더 (아이콘/배지/진행바)
4. 서브에이전트 완료 시 블록이 **완료 상태로 전환** + 요약 결과 표시
5. 메인 컨텍스트는 요약만 받아 토큰 효율 유지

## 5. 범위 (Phase 구성)

### Phase 0. 선행 확인 (0.5d)
- TaskCreateTool과 SubagentRunner 연결 실태 확인
- 누락이면 Phase 1에 통합, 정상이면 문서만 갱신

### Phase 1. Built-in Agent 프롬프트 고도화 (1.5d)
- EXPLORE: 심도 3단계(quick/medium/thorough) + 탐색 전략(병렬 Grep/Glob, 파일 우선순위) + 결과 요약 규격(절대경로:줄번호, 스니펫, 200단어 이내)
- PLAN: 산출물 구조(단계 목록, 위험, 롤백), 코드 수정 금지 명시
- GENERAL: 도구 선택 기준, 위임 판단 가이드
- GUIDE/VERIFICATION: 도메인 체크리스트 템플릿
- DB UPDATE + Flyway 마이그레이션 동시 생성 (CLAUDE.md 규칙)
- 참고 소스: Claude Code 시스템 프롬프트 구조, OpenClaude 포트 흔적

### Phase 2. BE SSE 라이프사이클 이벤트 추가 (1d)
- `StreamEvent` 서브타입 2종 추가: `SubagentStart`, `SubagentDone`
  - 필드: `subagentRunId`, `agentType`, `description`, `parentToolUseId`, (Done) `summary`, `tokensUsed`, `status`
- `SubagentRunner` 실행 경로에서 이벤트 발행 (SSE 퍼블리셔 주입)
- `ChatController` switch 확장
- 테스트: `SubagentRunnerTest`에 이벤트 발행 검증 추가

### Phase 3. 사전 안내 자동 주입 (0.5d)
- `OrchestratorEngine`이 Task/Agent 계열 도구 호출 감지 → TextDelta로 한 줄 주입 ("{agentType} 서브에이전트로 {description} 시작합니다")
- 문구 자체는 `prompt_templates`에 외부화 (DB 수정으로 문구 튜닝 가능)

### Phase 4. FE Task 블록 렌더 (1.5d)
- `ToolUseBlock`에서 `name.startsWith("task_")` 또는 서브에이전트 관련 도구 분기 → 전용 `SubagentBlock` 컴포넌트
- `useChatStream`에 `subagent_start/done` 이벤트 핸들러 추가, 블록 상태 RUNNING→COMPLETED/FAILED 전환
- 디자인: Lucide 아이콘(Bot/Search/CheckCircle), Metronic 뱃지 + 진행 애니메이션, 완료 시 요약 접기/펼치기

### Phase 5. 통합 검증 (0.5d)
- 시나리오: "이 리포의 LLM 어댑터 관련 파일을 모두 찾아줘" → EXPLORE 위임 → FE에서 블록 표시 확인
- 토큰 절감 효과 측정 (메인 컨텍스트 vs 서브에이전트 요약)
- 벤치마크 3자 비교에 추가 고려

## 8. 위험 / 주의

- **TaskCreate↔Runner 연결 이슈** (Phase 0에서 해소): 현재 구조가 의도된 분리인지 미완성인지 판단 후 범위 재조정 필요
- **이벤트 순서 보장**: `subagent_start`가 `tool_use_start` 사이에 끼어드는 순서 — CR-045의 SSE race 해소 패턴(커밋 `a19b7e2`) 참고
- **프롬프트 토큰 증가**: 5타입 모두 500B+ 되면 루트 시스템 프롬프트가 커질 수 있음 — built-in agent는 호출 시점에만 로드되므로 영향 제한적
- **Hook 이벤트와 중복**: CR-034의 SUBAGENT_START/STOP 훅이 이미 존재 — SSE 이벤트는 별도 경로(사용자 가시성용), 훅은 정책/감사용으로 분리 유지
