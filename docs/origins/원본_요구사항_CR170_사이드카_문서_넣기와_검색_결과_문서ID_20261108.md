## 결함
- 사이드카 ingest_document 가 첫 단계에서 delete_embeddings_by_source(source_id) 를 불러 그 지식소스의 임베딩을 모두 지운다(python-sidecar/src/rag_pipeline/tools/ingestor.py 63~67행 근처, db.py 104~114행 근처)
- Aimbase BE 의 ingest-text 는 같은 문서 ID 의 임베딩만 지우는 문서 단위 갱신을 의도했다(backend/platform-core/.../api/KnowledgeController.java 222~259행, 문서 단위 삭제 238행 근처). 사이드카의 전체 삭제가 그 의도를 덮는다
- 운영 사이드카 로그에 최근 7일 「Deleted N existing embeddings for source ...」 가 513회 찍혔고, AXOPM 지식소스에는 마지막에 들어간 1건만 남아 있다
- 파일 동기화(IngestionPipeline.java 262~271행 근처)도 문서마다 같은 전체 삭제를 부른다. 문서가 여럿인 파일 지식소스도 마지막 문서만 남는 같은 결함이다
- 줄 번호는 조사 시점 기준이다. 지금 dev 에서 달라졌을 수 있다

## 고칠 방향 (IR-002 4.1 1번, 확인 뒤 CR 에 확정)
- ingest_document 가 document_id 를 받으면 그 문서의 임베딩만 지운다. 지식소스 전체 삭제는 전체 재동기화 때만 한다
- 파일 동기화 경로는 문서별 호출 전에 한 번만 전체 삭제하도록 맞춘다
- 다른 테넌트와 다른 소비 앱(bp_office 등)도 같은 사이드카를 쓴다. 바뀐 동작이 그쪽 동기화를 깨지 않는지 호출처를 전부 찾아 확인하고 CR 에 적는다
