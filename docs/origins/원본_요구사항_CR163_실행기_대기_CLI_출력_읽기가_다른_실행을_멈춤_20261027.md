# 실행기가 대기 중인 CLI 출력을 읽다 다른 실행까지 멈추는 문제

이 건의 설계 주인은 aimbase 다. 사용자 10/27 14:55 결정(/전승 ①): aimbase 에 별도 CR 을 내 원인을 재현해 고치고, 운영 설치(CR-162)는 이 건과 별개로 그대로 진행한다.

## 배경

- 59 Aimbase 에서 10/27 14:25 무렵 차수 편성 추천 워크플로우(wms-wave-plan-opinion) 실행 다섯 번이 모두 5분을 넘겼다. 앞 회차는 27초에서 75초였다.

  - [사실] 계정 한도, 재기동, CR-161 반영 때문은 아니다.
  - [사실] 새 CLI 다섯은 답을 다 만들어 두었는데 실행기가 읽지 못하다가, 14:11 회차에서 대기 중이던 CLI 가 정리된 14:30:01 같은 초에 한꺼번에 나왔다.
  - [추정] 대기 중인 CLI 의 출력을 읽는 일이 실행기 JVM 스레드를 붙잡는다(59 는 16코어).

## 이 창이 맡는 것

1. 원인을 재현해 확정한다. 59 실행기 로그와 실행 기록은 읽기만 한다. 재현은 로컬에서 한다.
2. 근본 원인을 고친다. 대기 중인 CLI 하나가 다른 실행의 출력 읽기를 막지 않게 한다. 시간 제한 값을 바꿔 증상을 덮지 않는다.
3. 59 에 반영하고, 컨타를 거쳐 bp-wms 창에 의견 다섯 번을 다시 불러 달라고 요청해 앞 회차 시간대로 돌아오는지 본다.
