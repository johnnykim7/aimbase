## 요청 원문 (bp-wms `docs/협업/요청_CR-WMS-942_to_Aimbase_음성_생성기_같은_글_다른_차례.md`)

### bp-wms CR-WMS-942 이 Aimbase 에 보내는 요청: 음성 생성기 같은 글 다른 차례

사용자 결정 2026-11-10 08:17 /전승(컨타 결정 3 ①). 나가는 순서는 Aimbase 먼저, bp-wms 다음이다.

#### 1. 요청

1. **맡기기 요청에 차례(`take`)를 받는다.** `POST /api/v1/speech/tts-jobs` 의 `{voice, text}` 에 0 이상의 정수 `take` 를 더한다. 빠지면 0 이다. 상한은 Aimbase 가 정한다. bp-wms 는 사람이 들어 보고 다시 만들라고 한 문장에만 1 씩 올려 보낸다.
2. **차례마다 씨앗 시작값을 옮긴다.** 생성기는 지금 시도마다 `voice.seed + attempt - 1` 을 쓴다(`tts-sidecar/server.py` 228줄). 차례가 있으면 `voice.seed + take * attempts + attempt - 1` 처럼 차례끼리 시도 씨앗이 겹치지 않게 한다. 값과 방식은 Aimbase 가 정한다. 맥 시험은 이 식으로 했다(3).
3. **재사용 열쇠에 차례를 넣는다.** 같은 음색 · 같은 글 · 같은 차례일 때만 앞 작업을 돌려준다(`TtsJobStore.findReusable`). 지금은 음색 · 글만 보므로 차례를 올려 맡겨도 보관 기간 7일 동안 앞 작업이 돌아와 생성기에 닿지 않는다.
4. **운영 Aimbase 에도 같게 반영한다.**

#### 2. 왜

운영 음성 표본 100개를 들은 사용자가 바구니 이름 「에스 34번」 · 「에스 72번」 · 「에스 82번」 의 「에스」 가 「에즈」 로 들린다고 지적했다(2026-11-10 지적 2). 바라는 것은 그 파일만 다시 만드는 것이다.

1. 생성기는 씨앗이 고정이라 같은 음색 · 같은 글은 몇 번을 만들어도 같은 소리다(BIZ-134).
2. Aimbase 는 같은 음색 · 같은 글의 완료 작업을 7일 동안 돌려준다. bp-wms 가 같은 글을 다시 맡겨도 생성기에 닿지 않는다.
3. bp-wms 가 글을 바꾸면(부호를 더하는 등) 소리는 달라지지만 읽는 말이 바뀐다. 읽는 말은 그대로 두고 소리만 다시 뽑을 길이 없다.

#### 3. 실측 (맥, 2026-11-10)

생성기 코드는 Aimbase `origin/dev` 의 `tts-sidecar/server.py` 와 같은 파일이다(md5 `9c46057b`). 모델 · 음색 `field-voice-07`(씨앗 20261031, 시도 3회)도 같다. 맥 생성기 소리는 59 · 운영 저장분과 표본 수까지 일치해 왔다. 차례마다 씨앗 시작값만 `seed + take * 3` 으로 옮겼다.

|---|---|---|---|
| 에스, 삼십사번 | `ed486db7` 2.06초 | `4fdc63a5` 2.02초 | `9ef4dad6` 1.97초 |

- 차례 0 은 씨앗을 옮기지 않은 지금 생성기로 앞서 만든 파일과 md5 가 같다. 차례 1 · 2 는 서로 다르고 차례 0 과도 다르다.
- 들어 볼 파일은 bp-wms 듣기 폴더 `8-01` 부터 `8-09` 까지다(사용자 맥 `/Users/sykim/Downloads/CR-WMS-942_후보듣기/`).

#### 4. 바뀌지 않아야 하는 것

- `take` 가 빠지거나 0 이면 지금과 같은 소리이고 같은 작업을 재사용한다. 59 · 운영에 쌓인 저장분은 다시 만들지 않는다.
- 맡기기 · 조회 창구의 나머지 요청 · 응답 모양, 실패 코드, 무음 기준(CR-171)과 짧은 소리 재사용 막기.
- 같은 음색 · 같은 글 · 같은 차례면 같은 소리(BIZ-134).

#### 5. bp-wms 쪽 (CR-WMS-942)

- 저장분과 생성 요청 줄에 차례를 적는다. 운영사가 정책값 `FIELD_VOICE` 의 차례 목록에 문장과 차례 번호를 적으면 그 문장만 그 차례로 다시 맡긴다. 새 소리가 저장될 때까지 화면은 옛 소리를 받는다.
- bp-wms 는 Aimbase 가 나간 뒤에만 `take` 를 1 이상으로 보낸다. 먼저 보내면 Aimbase 는 모르는 칸을 버리고(요청 모양 `SubmitRequest(voice, text)`, 모르는 칸을 막는 설정이 없음) 앞 작업을 돌려주므로 같은 소리가 다시 저장된다.

#### 6. 확인

- 59 에서 「에스, 팔십이번」 을 `take` 0 · 1 · 2 로 맡긴다. 0 은 지금 59 의 같은 글 작업과 같은 소리이고 `reused` 가 참이다. 1 · 2 는 `reused` 가 거짓이고 서로 다른 소리다.
- `take` 1 을 한 번 더 맡기면 `reused` 가 참이고 앞의 `take` 1 작업이 돌아온다.
- 완료되면 컨타 `3plcore-80479` 에 알린다. bp-wms 배포는 그 뒤 회차에 묶는다.
