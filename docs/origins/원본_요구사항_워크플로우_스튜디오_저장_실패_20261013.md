## 2. 실측 (로컬, 2026-10-13)

스튜디오가 기존 워크플로우를 저장할 때 보내는 본문은 `{id, name, description, steps, inputSchema, outputSchema, status}` 다(flowToWorkflow). 같은 워크플로우에 칸을 바꿔 PUT 한 결과:

| 순번 | 본문 | 결과 | 서버 기록 |
|---|---|---|---|
| 1 | 스튜디오와 같음 | 400 | Unrecognized field "description" |
| 2 | description 제외 | 400 | Unrecognized field "status" |
| 3 | description, status 제외 | 400 | triggerConfig 필수 검사 실패 |
| 4 | 3 에 기존 triggerConfig 추가 | 200 | |

원인은 화면 저장 본문과 서버 저장 API 의 칸이 셋 어긋난 것이다.

1. 설명(description): 화면에 입력 칸이 있고 보내지만 테넌트 워크플로우 테이블과 저장 API 에 칸이 없다. 플랫폼 공용 워크플로우에는 있다.
2. 상태(status): 화면이 늘 "draft" 를 보내지만 서버에는 워크플로우 상태 개념이 없다(활성 여부만 있다).
3. 트리거 설정(triggerConfig): 서버 필수 칸인데 화면이 보내지 않는다. 수정(PUT)은 통째로 바꾸는 방식이라 화면이 보내지 않은 오류 처리 설정(errorHandling)도 비워진다.

서버 JSON 해석기는 모르는 칸을 거부한다(AppConfig 의 ObjectMapper 가 기본값 그대로). 이 엄격함은 계약 어긋남을 드러내므로 유지한다.

운영은 api 가 2026-10-12 13:28(UTC) 에 뜬 뒤 같은 거부 기록이 없다. 그 사이 스튜디오 저장이 있었는지는 확인하지 못했다.
