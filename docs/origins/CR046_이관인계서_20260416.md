## 1. 배경

CR-045(대화형 채팅 UI)가 완료되었으나, 코드 레벨 검증 결과 **사용자 노출 UX에서 치명적 결함 3가지**가 확인됨:

1. **중지 허위 구현**: FE AbortController로 fetch만 끊고 BE Virtual Thread는 계속 실행 → LLM 토큰 과금·도구 실행 지속
2. **끼어들기 Race Condition**: 동일 sessionId 동시 요청 시 병렬 실행 → 메시지 순서 비결정, `SessionStore.persistToDb():171-174`의 중복키 재시도 로직이 이미 실전에서 터진 증거
3. **대화방 삭제 UI 부재**: BE 엔드포인트·FE API 클라이언트는 있으나 **UI 버튼 없음**, 게다가 Hard Delete + 고아 로그 생성

추가로 CR-045 완료 문서에 "별도 CR로 분리 권장"이라 남긴 2개 이슈도 본 CR에 통합:
- SSE 완료 후 Spring Security async dispatch AccessDenied 경고
- conversation_sessions 중복키 배치 에러

## 2. 코드 검증 결과 (핵심 증거)

### 2-1. 중지 (Abort)
| 위치 | 상태 | 파일:라인 |
|---|---|---|
| FE AbortController | ✅ 있음 | `frontend/src/hooks/useChatStream.ts:78,80-82,160-161,168` |
| BE /abort 엔드포인트 | 🔴 없음 | `ChatController.java` grep 0건 |
| OrchestratorEngine cancellation token | 🔴 없음 | `OrchestratorEngine.chatStream():430-525` CountDownLatch만 |
| executeLoopStream abort check | 🔴 없음 | `ToolCallHandler.executeLoopStream():324-451` 매 iteration 체크 없음 |

**현재 동작**: FE가 중지 눌러도 BE Virtual Thread(`OrchestratorEngine:109`)가 계속 돌며 LLM 응답 받고 세션에 저장.

### 2-2. 동시성 (Interleave)
| 위치 | 상태 | 파일:라인 |
|---|---|---|
| FE 블록 | ✅ UI에서 `canSend=!isStreaming` | `Chat.tsx:66`, `ChatInput.tsx:15-51` |
| BE sessionLock | 🔴 없음 | grep 0건 |
| BE 409 응답 | 🔴 없음 | ChatController 동시 요청 체크 없음 |
| DB race 흔적 | 🟡 재시도 코드만 존재 | `SessionStore.persistToDb():171-174` "동시 persist 경쟁으로 session UNIQUE 제약 충돌 → 1회 재시도" |

**현재 동작**: curl 두 번 치면 병렬 실행, 마지막 writer wins.

### 2-3. 삭제 (Delete)
| 위치 | 상태 | 파일:라인 |
|---|---|---|
| BE DELETE 엔드포인트 | ✅ 있음 | `ConversationController.java:64-72` |
| FE API 클라이언트 | ✅ 있음 | `frontend/src/api/sessions.ts:70-71` |
| FE UI 버튼 | 🔴 없음 | Sessions.tsx/SessionDetail.tsx/Chat.tsx 모두 미노출 |
| Soft delete 컬럼 | 🔴 없음 | ConversationSessionEntity, ConversationMessageEntity |
| 권한 체크 | 🔴 없음 | ConversationController 소유자 검증 없음 |
| FK cascade | 🟡 부분 | messages는 CASCADE, 그 외 5개 테이블은 FK 없어 고아 발생 |

**고아 발생 테이블**:

- `usage_logs` (`V13__create_usage_logs.sql:4`)

## 3. 구현 범위

### Phase 1: BE 중지·동시성 (PRD-A)
1. **Abort 엔드포인트**: `POST /api/v1/chat/{sessionId}/abort`
2. **Cancellation Registry**: `ConcurrentHashMap<String, CancellationToken>` (세션ID→토큰)
3. **OrchestratorEngine.chatStream()** 에 `AtomicBoolean cancelled` 주입
4. **ToolCallHandler.executeLoopStream()** 루프 매 iteration 시작 시 `if(cancelled.get()) break;`
5. **어댑터 스트림** 중단 — HTTP 커넥션 close (Anthropic SDK AbortSignal 미지원)
6. **부분 메시지 저장**: `[중단됨]` 마커 + 중지 시점까지의 partial 토큰 DB 저장
7. **과금 처리**: 중지 시점까지만 usage_logs 기록

### Phase 2: BE 세션 동시성 (PRD-B)
**정책: 옵션 B (자동 abort + 새 요청)** — ChatGPT 방식, 가장 자연스러움
1. `ConcurrentHashMap<String, ReentrantLock> sessionLocks`
2. `ChatController.completions()` 진입 시:
   - 이미 스트림 중이면 → **이전 스트림 auto abort** → 새 요청 처리
   - 옵션 A(409 거부)·옵션 C(큐잉)은 선택사항으로만 남김

### Phase 3: BE 대화방 삭제 개선 (PRD-C)
1. **Soft Delete 전환**
   - Flyway V47: `ALTER TABLE conversation_sessions ADD COLUMN deleted_at TIMESTAMPTZ`
   - Flyway V47: `ALTER TABLE conversation_messages ADD COLUMN deleted_at TIMESTAMPTZ`
   - 목록/조회 쿼리에 `WHERE deleted_at IS NULL` 추가
2. **`ConversationController.delete()`** — hard → soft 변경
3. **권한 체크** — 세션 소유자(user_id) 일치 또는 관리자 role
4. **삭제 시 active 스트림 자동 abort** (Phase 1과 연동)
5. **복구 엔드포인트** (결정 필요): `POST /conversations/{id}/restore`
6. **벌크 삭제** (결정 필요): `DELETE /conversations?ids=...`
7. **고아 로그 정책**: FK 추가 안 함 (현재 상태 유지), 감사·과금 목적 보존

### Phase 4: FE (PRD-D, FE-xxx)
1. **중지 버튼 API 호출** (현재 fetch만 abort) — `useChatStream.ts:80` 보강
2. **끼어들기 UX** — 스트림 중에도 입력 열기, 전송 시 자동 이전 abort
3. **대화방 목록 사이드바** — Chat.tsx 좌측 (아직 없으면 신규)
4. **삭제 UI** — 항목 호버 시 삭제 아이콘 + 확인 모달
5. **useMutation + 쿼리 invalidate**

### Phase 5: CR-045 잔여 이슈 (PRD-E)
1. **SSE 완료 후 AccessDenied 경고 해소**: Spring Security async dispatch + 가상 스레드 SecurityContext 전파
2. **conversation_sessions 중복키 배치 에러** 근본 수정 (현재는 retry만)
