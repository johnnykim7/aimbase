## 배경 / 문제 정의

소비앱이 워크플로우를 실행(`POST /api/v1/workflows/{id}/run`)할 수는 있으나,
진행 중인 run 을 중지할 API 가 없었다.

실측 결과:
- `WorkflowController` 에 cancel/stop/abort 매핑 0건
- `WorkflowRun` enum 에 `CANCELLED` 값과 조회 필터(`status=cancelled`)는 있으나,
  그 상태로 전이시키는 코드가 워크플로우 패키지 전무 (빈 껍데기)
- 중지 API 가 있는 곳은 `chat/{sessionId}/abort`(CR-046)·`agents/{runId}/cancel`(서브에이전트)뿐

실행 구조: `WorkflowEngine.execute` 가 Virtual Thread fire-and-forget —
runId→Thread 핸들을 보관하지 않아 외부에서 강제 interrupt 불가.
→ 협조적 중지(스텝 경계 체크포인트) 채택.

## 결정 사항

1. **중지 방식 A (협조적)** — 스텝 경계에서만 끊어 DB/CLI 워커 일관성 유지.
   진행 중 한 스텝은 끝까지 수행 후 멈춤(즉시성 없음 트레이드오프 수용).
2. **바로 구현, CR 사후 발번** — CR-105 (CR-103/104 는 이미 점유 — 워크플로우 CLI 라우팅 / cli-runner allowedTools).
3. **재기동·배포 보류** — 사용자 지시.

## 구현 범위

- `WorkflowEngine`: cancel 표식 Set + `cancelRun(UUID)` + DAG/cyclic 체크포인트 + `finishCancelled` + VT finally `clearCancel`
- `WorkflowController`: `POST /api/v1/workflows/runs/{runId}/cancel`
