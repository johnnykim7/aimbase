# 구독 관리 화면과 API 에서 테넌트 분당 요청 한도 바꾸기 - Aimbase

## 배경

- 11-03 운영 chaws 에서 `bp_wms` 테넌트가 분당 요청 한도 60 을 다 써 실행기가 끊김으로 표시됐다(CR-167 문서 7.8절). 18:57 한도를 600 으로 올릴 때 구독 변경 API 가 분당 한도를 받지 않아 운영 DB(`aimbase_master.subscriptions.api_rpm_limit`)를 직접 고쳤다(CR-167 문서 11절 2).
- 구독 변경 API 가 받는 값은 플랜, 월 토큰 한도, 연결 수, 지식 소스 수, 워크플로 수, 저장 용량뿐이다(`PlatformController.java:342` `SubscriptionUpdateRequest`). 분당 요청 한도(`SubscriptionEntity.apiRpmLimit`)는 없다. 한도 필터는 요청마다 이 값을 읽는다(`RateLimitFilter.java:139`).
- 관리 화면 「구독 관리」(`frontend/src/pages/platform/Subscriptions.tsx`)의 수정 창에는 「월간 토큰 한도」 「일일 요청 한도」 「최대 연결 수」 세 칸이 있다. 화면이 보내는 칸 이름이 API 와 맞는 것은 「최대 연결 수」 하나다. 「월간 토큰 한도」는 화면이 `monthlyTokenQuota` 로 보내고 API 는 `llmMonthlyTokenQuota` 를 받는다. 「일일 요청 한도」(`dailyRequestQuota`)는 서버에 없는 값이다. 두 칸은 고쳐도 저장되지 않는다(`frontend/src/types/tenant.ts` `Subscription`).
- 사용자 결정(11-04 06:30 「4=1」): 따로 CR 로 고친다.

## 자료

- CR-167 문서 7.8절, 11절. CR-168 문서(실행기 연결 신호 한도, 설정값 `ratelimit.agent-signal-max-per-minute`).
- 운영 chaws 배포: 레포 루트 `deploy.sh` 의 chaws 대상. 지금 운영 판은 `chaws-cr168` 의 e8b1efd 다.

## 할 일

1. 이 레포 절차대로 설계(CR 문서, 설계서, 시험항목). 요청서와 다르게 가야 할 것은 이유와 함께 컨타에게 ① 권장으로 올린다.
2. 구독 변경 API 가 분당 요청 한도를 받아 저장한다. 1 보다 작은 값처럼 쓸 수 없는 값은 거절한다.
3. 「구독 관리」 화면에서 테넌트마다 분당 요청 한도를 보고 바꿀 수 있게 한다. 서버에 없는 「일일 요청 한도」 칸과 저장되지 않는 「월간 토큰 한도」 칸은 서버 값과 맞춘다. 화면 문구는 컨타에게 승인받는다.
4. 바꾼 한도가 재기동 없이 다음 요청부터 적용되는지 로컬 또는 59 에서 확인한다.
5. 순서: 59 반영과 확인, 사용자 승인, 운영 chaws 반영, 운영 「구독 관리」 화면에 `bp_wms` 분당 한도 600 이 보이는지 읽기만 확인(값은 바꾸지 않는다).

중간 보고 시점: 설계에서 화면 칸 목록이 나왔을 때. 그다음 운영 반영 승인요청 때.

- bp-wms 의 음성 조회 빈도. bp-wms 쪽 일이다.

- 이 프로젝트의 배포는 59 개발기다. 59 배포는 레포 루트 `deploy.sh` 로, 인자를 먼저 보고 컨타에게 [승인요청]한다.
