## 1차 진단(틀림)

## 실측 후 정정(진짜 원인)

소스코드 + 운영 컨테이너 직접 검증:

1. **MCPServerClient.java:39** `HttpClientSseClientTransport.builder(url).build()` 로
   DB url(`http://host.docker.internal:8183/api/mcp`) 통째로 baseUri 전달, sseEndpoint 미지정.
2. **SDK 0.10.0 HttpClientSseClientTransport.java:344** —
   `Utils.resolveUri(baseUri, "/sse")` (DEFAULT_SSE_ENDPOINT="/sse").
   Java URI 표준상 절대 경로(`/sse`) 가 base path 를 덮어써서 결과는
   `http://host.docker.internal:8183/sse` — context path 사라짐.
3. **운영 컨테이너 실측** —
   - `docker exec aimbase-api-1 curl /sse` → **404**
   - `docker exec aimbase-api-1 curl /api/mcp/sse` → **200**
4. **추가 문제** — `MCPServerManager.connectAutoStartServers` 가
   `@EventListener(ApplicationReadyEvent.class)` 로 **단 1회만** 실행.
   재시도 메커니즘 부재 → 한 번 실패하면 영구 dead.

## 합의된 수정 범위

1. **근본 버그 수정** — `MCPServerClient.splitBaseAndSsePath(url)` 로
   DB 의 단일 url 을 `(baseUri=scheme://authority, sseEndpoint=path+"/sse")` 자동 분리.
   DB 마이그레이션 없음 (`config.url` 컬럼 그대로).
2. **재연결 API** — `POST /api/v1/mcp-servers/{id}/reconnect` 신설.
   `MCPServerManager.reconnect(serverId)` 가 기존 연결 close + discover 재실행.
3. **주기 health check** — `@Scheduled(initialDelay=120s, fixedDelay=60s)`.
   `connections` 에 없거나 `isInitialized()==false` 인 autoStart 서버 자동 재연결.
4. **lazy reconnect** — `MCPToolExecutor.execute` 가 호출 실패 시
   manager.reconnect 호출 후 1회 재시도.
