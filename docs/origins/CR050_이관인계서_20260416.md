## 1. 배경 (요약)

### 문제
- **현재 LLM_CALL 경로**: `AnthropicAdapter` (API Key, 토큰 과금) 단일
- **ClaudeCodeTool (Tool 경로)**: 호출마다 Node.js 기동 500ms+ 오버헤드
- **구독자(Pro/Max)는 정액제 자산을 LLM_CALL에서 활용 못 함**

### 해결
- Claude CLI(`claude -p`)를 **LLM 어댑터로 승격** → Anthropic/OpenAI/Ollama/Bedrock/Vertex와 동급
- 워크플로우 run 단위로 워커 풀 상주 → 기동 오버헤드 10배 감소
- Max 구독 정액제로 LLM_CALL 비용 대체

### 효과
- 10 LLM_CALL 워크플로우: **5초 → 0.5초**
- 병렬 브랜치 캐시 재사용: **$0.07 → $0.007** (T4 검증됨)

## 2. 구현 범위 (PRD 8개 예상)

### PRD-A: `ClaudeCliWorker` (단일 프로세스 래퍼)
- **파일**: `backend/platform-core/src/main/java/com/platform/llm/claudecli/ClaudeCliWorker.java` (신규)
- **기능**:
  - ProcessBuilder로 `claude -p --input-format stream-json --output-format stream-json --tools ""` 기동
  - stdin NDJSON 주입 / stdout 라인 단위 파싱
  - **stderr drain 스레드 필수** (버퍼 차면 멈춤)
  - 한 턴 송수신 API: `ChatResponse turn(List<UnifiedMessage> messages)`
  - 내부 뮤텍스로 동시 호출 직렬화
  - 프로세스 생존 확인, 크래시 감지
  - 세션 파일 경로 추적 (fork-session에 필요)

### PRD-B: `ClaudeCliWorkerPool` (Run 단위 풀)
- **파일**: `backend/platform-core/src/main/java/com/platform/llm/claudecli/ClaudeCliWorkerPool.java` (신규)
- **기능**:
  - `ConcurrentHashMap<String, RunWorkers>` — key: workflowRunId
  - `getOrCreateMain(runId)` — lazy spawn, 메인 워커 획득
  - `spawnForkedWorker(runId, parentSessionId)` — `--resume --fork-session` 새 프로세스
  - `shutdownForRun(runId)` — 모든 워커 프로세스 종료
  - 워커 크래시 시 재기동 + 현재 run 실패 처리

### PRD-C: `ClaudeCliLlmAdapter` (어댑터 구현)
- **파일**: `backend/platform-core/src/main/java/com/platform/llm/adapter/ClaudeCliLlmAdapter.java` (신규)
- **기능**:
  - `LLMAdapter` 인터페이스 구현
  - `chat(LLMRequest)`: workerPool에서 워커 획득 → turn 실행 → 응답 변환
  - **첫 턴**: 전체 messages를 NDJSON 주입
  - **이후 턴**: 마지막 user 메시지만 주입 (CLI가 맥락 기억)
  - `transformToolDefs()`: 빈 구현 또는 예외 (도구 미지원)
  - `chatStream()`: stdout 이벤트를 StreamEvent로 변환
  - Usage 정보: stream-json 이벤트에서 추출 시도 (구현 단계 검증)

### PRD-D: `ClaudeCliAdapterConfig` (설정)
- **파일**: `backend/platform-core/src/main/java/com/platform/llm/claudecli/ClaudeCliAdapterConfig.java` (신규)
- **application.yml 섹션**:
  ```yaml
  platform:
    llm:
      anthropic-cli:
        enabled: true
        timeout-seconds: 300
        max-workers-per-run: 5
        cli-binary-path: /usr/local/bin/claude
        allowed-tenants: [tenant-a, tenant-b]  # 피처 플래그
  ```

### PRD-E: `ConnectionAdapterFactory` 통합
- **파일**: `backend/platform-core/src/main/java/com/platform/llm/ConnectionAdapterFactory.java` (수정)
- **변경**:
  - `normalizeAdapterType()`: `"anthropic-cli"` 매핑 추가
  - `createAdapter()`: `anthropic-cli` 케이스 → `ClaudeCliLlmAdapter` 반환
  - `case "anthropic-cli" -> claudeCliLlmAdapter;`

### PRD-F: `WorkflowEngine` 수명 훅
- **파일**: `backend/platform-core/src/main/java/com/platform/workflow/WorkflowEngine.java` (수정)
- **변경**:
  - Run 시작 시: 아무 작업 없음 (pool은 lazy spawn)
  - **Run 종료 시 (정상/예외 모두)**: `claudeCliWorkerPool.shutdownForRun(runId)` 호출
  - try/finally 또는 이벤트 리스너로 누락 방지

### PRD-G: 병렬 브랜치 처리
- **파일**: `backend/platform-core/src/main/java/com/platform/workflow/step/ParallelStepExecutor.java` (수정)
- **변경**:
  - 병렬 브랜치 시작 시 `pool.spawnForkedWorker(runId, parentSessionId)` 호출
  - 브랜치별로 독립 워커 확보
  - 브랜치 종료 시 해당 워커 파기 (pool.releaseForkedWorker)

### PRD-H: 테스트
- **단위**: `ClaudeCliWorkerTest` — 프로세스 기동/종료, stdin/stdout 통신
- **단위**: `ClaudeCliWorkerPoolTest` — 동시성, lazy spawn, shutdown
- **통합**: `ClaudeCliLlmAdapterIT` — 실제 claude CLI 실행 (CI는 skip)
- **E2E**: LLM_CALL 단일 턴 / 멀티 턴 / 병렬 브랜치 / Run 종료 정리 4가지 시나리오

## 3. 결정 필요 사항 (다음 세션 시작 시)

1. **run당 최대 워커 수**: 기본 5개 (병렬 브랜치 고려) — 적절?
2. **Usage 추출 방식**: stream-json에서 추출 vs Redis 감사 로그만
3. **CI 통합 테스트**: 실제 CLI 실행 vs 모킹?
4. **테넌트 피처 플래그**: `allowed-tenants` 리스트 vs `global_config` 테이블 키 vs Connection 테이블 플래그?
5. **첫 턴/이후 턴 구분**: Adapter 내부 상태 vs Worker 내부 상태?
6. **`--model` 전달 방식**: Connection config에서 모델 ID 받아 CLI에 그대로 전달?
7. **타임아웃 실패 시 처리**: 워커 강제 종료 + run 실패 vs 워커 재기동 후 재시도?
