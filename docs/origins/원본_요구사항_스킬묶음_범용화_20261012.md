## 5. 요건

1. 스킬 묶음(.skill zip 또는 같은 모양의 zip)을 그대로 올린다. 맨 위 `SKILL.md` 앞머리의 name, description 을 읽어 등록한다
2. 묶음 안의 하위 폴더 이름과 파일 종류를 정해 두지 않는다. 다른 스킬이 들어와도 그대로 받는다
3. 모델 종류와 무관하게 같은 방식으로 쓴다. Claude Code 처럼 단계적으로 보여준다
   - 쓸 수 있는 스킬의 이름과 설명을 먼저 보여준다
   - 고르면 안내서(SKILL.md) 본문과 파일 목록을 연다
   - 필요할 때 묶음 안 파일 하나를 꺼내 읽는다
   - 스크립트는 모델이 아니라 Aimbase 가 run 작업장에서 돌린다
4. API 연결, CLI 연결(AIMBASE, HYBRID, NATIVE 모드) 어디서든 같은 스킬이 같은 결과를 낸다
5. 워크플로우 단계에서 쓸 스킬을 지정할 수 있다. 도구를 못 쓰는 단계(한 번 묻고 끝나는 단계)도 안내서와 지정 파일을 지시문에 붙여 쓸 수 있어야 한다
6. 여러 앱(테넌트)이 같은 스킬을 같이 쓴다. 지금 지시문형 스킬도 계속 돈다

## 6. Aimbase 설계에서 정할 것

입찰대행 창은 아래를 정하지 않았다. Aimbase 창이 설계하며 정하고 사용자 결재를 받는다.

1. 공용 범위. 플랫폼 공용(모든 테넌트)과 테넌트 전용을 둘 다 둘지, 이름이 겹치면 어느 쪽이 이기는지
2. 판 관리. 올릴 때마다 새 판을 두고 워크플로우 단계가 판을 고정할 수 있게 할지
3. 스크립트 실행 환경. Python 을 본체에 넣을지, 다른 곳에서 돌릴지, 실행 시간과 파일 크기 상한
4. CLI 연결에서 같은 기능을 주는 길. AIMBASE 모드는 내장 Skill 을 막으므로 Aimbase 가 MCP 통로로 같은 도구를 줄지
5. 지금 지시문형 스킬을 묶음형으로 옮길지, 둘을 나란히 둘지

## 7. 입찰대행 쪽 사용 계획

입찰대행은 계기 스킬을 미국 연방 입찰(SAM.gov)판으로 고친 묶음을 올려, 공고 분석과 제안서 생성 워크플로우 단계에서 쓴다.
요구사항 대장, 평가위원 모의 채점, 입찰 여부 판단, 수주 전략, 회사소개서 작성이 이 묶음을 쓴다.
입찰대행 쪽 설계는 입찰대행 레포에서 따로 진행하고, Aimbase 에 바라는 것은 이 문서가 전부다.
