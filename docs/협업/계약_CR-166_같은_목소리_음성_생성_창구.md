# 계약 · CR-166 같은 목소리 음성 생성 창구 (Aimbase 에서 bp-wms 로)

| 항목 | 내용 |
|---|---|
| 정하는 쪽 | Aimbase CR-166 |
| 부르는 쪽 | bp-wms CR-WMS-842 「현장 화면 음성 합성 창구」 |
| 날짜 | 2026-10-31 |
| 설계 | Aimbase `docs/CR-166_현장_화면_음성_생성기_같은_목소리_비동기_생성.md` 3절, `docs/T3-2_API_설계.md` 「같은 목소리 음성 생성 작업」 |
| 상태 | 개발기(59) 반영(2026-10-31 13:17). bp-wms 키와 테넌트로 맡기기, 조회 확인 |

## 1. 부르는 법

- 주소: bp-wms 가 이미 쓰는 Aimbase 주소(`AIMBASE_BASE_URL`) 뒤에 `/api/v1/speech/tts-jobs`
- 인증: 이미 쓰는 테넌트 키와 테넌트 머리글(`X-API-Key: <AIMBASE_API_KEY>`, `X-Tenant-Id: <테넌트>`). 녹음 받아쓰기, 채팅 부르기와 같다. 테넌트 키는 경로별 권한을 걸지 않아 새 키, 새 권한이 없다. 작업은 그 테넌트에 둔다
- 음색 이름: `field-voice-07`(분류대 299개와 같은 견본, 견본 글, 생성값, 씨앗 20261031, 뒤처리)

## 2. 작업 맡기기 `POST /api/v1/speech/tts-jobs`

```json
{ "voice": "field-voice-07", "text": "검수대 3번으로 이동하세요." }
```

| 칸 | 필수 | 설명 |
|---|---|---|
| `voice` | 예 | 음색 이름 |
| `text` | 예 | 1 ~ 200자(유니코드 문자 수). 공백만 있으면 빈 글. 글자를 바꾸지 않고 그대로 읽는다. 숫자로 쓴 날짜, 시각(`2026-10-31 14:00`)은 못 읽으니 읽는 말로 바꿔 보낸다 |

202:

```json
{ "success": true,
  "data": { "job_id": "9f3c1a20-...", "status": "PENDING", "voice": "field-voice-07",
            "reused": false, "created_at": "2026-10-31T01:40:00Z" } }
```

같은 테넌트에 같은 음색, 같은 글의 작업이 이미 있으면(FAILED 제외, 보관 기간 안) 새로 만들지 않고 그 작업을 돌려준다. `reused` true, `status` 는 그 작업의 지금 상태(COMPLETED 일 수 있다).

## 3. 작업 조회 `GET /api/v1/speech/tts-jobs/{job_id}`

```json
{ "success": true,
  "data": { "job_id": "9f3c1a20-...", "status": "COMPLETED", "voice": "field-voice-07",
            "text": "검수대 3번으로 이동하세요.",
            "created_at": "...", "started_at": "...", "finished_at": "...",
            "mime_type": "audio/mpeg", "audio_base64": "SUQzBAAAAA...",
            "duration_sec": 2.21, "elapsed_sec": 21.7 } }
```

- `status`: `PENDING`, `RUNNING`, `COMPLETED`, `FAILED`. COMPLETED, FAILED 는 끝이다
- 시각(`created_at`, `started_at`, `finished_at`)은 UTC 로 싣는다(`2026-10-31T01:40:00Z`)
- `mime_type`, `audio_base64`, `duration_sec` 은 COMPLETED 일 때만. MP3, 24kHz 단일 채널 96k
- `error` 는 FAILED 일 때만: `generation_failed:<까닭>`, `tts_generator_unavailable`, `tts_generator_timeout`. 실패한 글을 다시 맡기면 새 작업이 된다

## 4. 오류

본문 `{ "success": false, "error": "<코드>" }`

| HTTP | 코드 | 때 |
|---|---|---|
| 400 | `voice_required`, `text_required`, `text_too_long:max=200`, `invalid_job_id` | 칸이 비었거나 길거나 작업 번호 모양이 틀림 |
| 404 | `voice_not_found:<이름>` | 없는 음색 |
| 404 | `job_not_found` | 없는 작업, 보관 기간이 지나 지운 작업, 다른 테넌트의 작업 |
| 429 | `tts_queue_full:max=500` | 그 테넌트의 대기, 진행 중 작업이 500개 |
| 503 | `tts_generator_unavailable` | 생성기가 떠 있지 않거나 모델을 올리는 중. 화면은 기기 목소리로 읽고 나중에 다시 맡긴다 |

## 5. 처리 순서, 속도, 보관

- 서버 전체에서 한 번에 하나, 맡긴 시각 순서대로 만든다. 문장마다 약 15 ~ 35초(59 실측). 몰아서 맡기면 뒤의 문장은 앞 것이 끝나야 만든다(299개 약 75분)
- 조회는 5 ~ 10초 간격이면 된다. Aimbase 가 다시 떠도 조회가 오면 남은 작업을 이어 만든다
- 끝난 작업은 7일 둔다. 그 뒤 조회는 404 `job_not_found`

## 6. 요청서 4절과 다른 것

1. 같은 글을 다시 맡기면 그 작업을 돌려준다(`reused`)
2. 429 `tts_queue_full` 을 더한다
3. 오류 본문에 코드를 싣는다
4. 조회 응답에 `text`, `created_at`, `started_at`, `finished_at` 을 더한다
5. 결과 보관 7일, 소리는 조회 응답에만 싣는다(`GET .../audio` 없음)

## 7. bp-wms 에 묻는 것

1. 몰아서 맡길 일이 지금 있는지. 있으면 즉석 문장이 몰아 맡긴 것 뒤에 밀리지 않게 차례 칸(`priority`)을 더한다. 없으면 맡긴 순서대로 둔다
   - 답(bp-wms, 컨타 회신): 지금은 없다. 화면이 처음 보낸 문장을 그때마다 한 건씩 맡긴다(같은 문장은 한 번). 차례 칸은 두지 않는다. 필요해지면 그때 요청한다
