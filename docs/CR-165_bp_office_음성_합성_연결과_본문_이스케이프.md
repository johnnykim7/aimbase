## 1. 문제

bp-office 음성 브리핑(OFC-REPORT-005)이 `POST /api/v1/speech/tts` 를 부르면 두 가지로 막힌다.

1. 503. 개발기 bp_office 테넌트에 OpenAI 연결이 없다
2. 본문 글에 역슬래시, 탭, 캐리지 리턴이 들면 OpenAI 로 가는 JSON 이 깨진다. 창구가 큰따옴표와 줄바꿈만 손으로 바꿔 끼운다(`SpeechController.java:68`)

## 2. 원인

### 2.1 연결을 넣어도 503 이다

창구는 테넌트 연결 중 `type` 이 `openai` 이고 상태가 `connected` 인 것의 `config.api_key` 를 키로 쓴다(`SpeechController.resolveOpenAIKey`). 관리 화면과 연결 API 로 만드는 OpenAI 연결은 모양이 다르다.

| 항목 | 창구가 찾는 모양 | 관리 화면이 만드는 모양 |
|---|---|---|
| 종류 | `type=openai` | `type=llm`, `adapter=OpenAI`(어댑터 이름은 `ConnectionAdapterFactory.normalizeAdapterType` 이 `openai` 로 맞춘다) |
| 키 | `config.api_key` | `config.apiKey`(`Connections.tsx`, `ConnectionAdapterFactory.createAdapter`) |

그래서 bp_office 에 관리 화면으로 OpenAI 연결을 넣어도 창구는 그 연결을 찾지 못해 503 이다.

### 2.2 본문을 글자 이어 붙이기로 만든다

`String.format` 에 글을 끼우고 `"` 와 줄바꿈만 바꾼다. JSON 이 허용하지 않는 제어 문자(탭, 캐리지 리턴 등)와 역슬래시는 그대로 들어간다. `model`, `voice` 도 이스케이프 없이 들어간다.

## 3. 개발기 연결 조사(2026-10-30, 읽기만)

| 항목 | 본 것 |
|---|---|
| 테넌트 9개의 OpenAI 연결 | 없다. OpenAI 계열은 bp_wes 의 OpenAI 호환 연결 2개(맥 Qwen, 끊김)뿐 |
| bp_office 연결 | CLI 연결 4개(1개 연결됨), 음성 변환 연결 1개 |
| 서버 공용 키 | api 컨테이너에 `OPENAI_API_KEY` 가 들어가 있으나 값이 5자라 실제 키가 아니다(임베딩용 자리) |
| 플랫폼 설정(`global_config`) | OpenAI, 음성 합성 항목 없음 |
| 맥 키 보관 폴더(`~/.claude-secrets`) | OpenAI 키 파일 없음(파일 이름만 봄) |

쓸 수 있는 공용 키가 없어 OpenAI 키를 새로 받아야 한다. 7절 질의 1.

## 4. 바꾸는 것

1. 본문은 JSON 직렬화기(Jackson)로 만든다. `input`, `model`, `voice`, `speed` 를 맵에 담아 직렬화한다
2. 연결 찾기는 지금 모양(`type=openai`, `config.api_key`)을 먼저 보고, 없으면 관리 화면 모양(어댑터가 OpenAI, `config.apiKey`)을 본다. 지금 모양을 쓰는 곳이 있으면 그대로 돈다
3. OpenAI 음성 합성 주소를 설정값(`aimbase.speech.openai-tts-url`, 기본값은 지금 주소)으로 뺀다. 로컬에서 가짜 OpenAI 로 본문을 받아 보기 위해서다
4. 키를 서버 환경변수에 두고 연결 설정에는 이름만 둘 수 있게 한다(컨타 [승인] 06:11, 7절 질의 1 의 1번). `config.apiKey_env` 에 변수 이름을 두면 `apiKey` 가 비었을 때 그 변수 값을 키로 쓴다. 연결 만들기, 연결 시험, 음성 합성이 같은 규칙(`ConnectionApiKeys`)으로 읽는다. 값이 든 `apiKey` 가 먼저라 기존 연결은 그대로다
5. 빈 글은 400 으로 돌려준다(지금은 글이 없으면 500)
6. 관리 화면이 저장하는 어댑터 표시명 `OpenAI Compatible` 이 `contains("openai")` 에 걸려 OpenAI 로 분류되던 것을 OpenAI 호환으로 바로잡는다. 그대로 두면 음성 합성이 OpenAI 호환 연결(DeepSeek 등)의 키를 OpenAI 로 보낼 수 있다. 그 연결은 지금 연결 시험에서 OpenAI 로 핑을 보내 실패하므로 연결됨이 될 수 없었다

음성 변환(STT)의 OpenAI 폴백(`WhisperSpeechService.resolveOpenAIKey`)도 같은 모양만 찾는다. 고치면 OpenAI 연결이 있는 테넌트의 음성 변환이 실패할 때 녹음이 OpenAI 로 나가기 시작하므로 이 건에서 건드리지 않는다. 7절 질의 3.

### 9.2 CR-166 과 나눈 것

CR-166(같은 날 착수)은 같은 모델(Qwen3-TTS 1.7B Base)로 bp-wms 현장 화면의 짧은 문장을 개발기 59 CPU 에서 비동기로 만든다. 사용자가 두 건은 겹치지 않는다고 했다(CR-166 9절 10:35). 둘은 따로 두고 이름과 음색 폴더 모양만 맞춘다.

| 항목 | CR-165 | CR-166 |
|---|---|---|
| 쓰는 곳 | bp-office 음성 브리핑 | bp-wms 현장 화면 |
| 엔진 자리 | 맥(MLX, GPU) | 개발기 59 컨테이너(PyTorch CPU) |
| 속도 | 220자에 27초, 소리 32초(10/31 실측) | 소리 1초에 약 7초 |
| 부르는 모양 | 지금 창구 `POST /speech/tts` 그대로, 응답으로 소리를 바로 받는다 | `POST /speech/tts-jobs` 로 맡기고 조회한다 |
| 글 | 날짜·시각을 읽는 말로 바꾼다. 길이는 지금 창구와 같다 | 1 ~ 200자, 바꾸지 않는다 |
| 실패하면 | OpenAI 로 전환한다 | FAILED |
| 소스 폴더 | `tts-mac-sidecar/` | `tts-sidecar/` |
| 설정 | 플랫폼 설정 `tts.*` | application.yml `aimbase.tts.*` |

음색 하나는 양쪽 모두 `voices/<이름>/` 폴더 하나(`voice.json`, `ref.wav`)다. 한 음색을 다른 쪽으로 옮길 때 폴더를 그대로 옮긴다.

### 9.3 창구 동작

`POST /api/v1/speech/tts` 의 요청 모양(`text`, `model`, `voice`, `speed`)과 응답(`audio/mpeg`)은 그대로다. `voice` 값으로 길을 나눈다.

1. `voice` 가 목소리 목록(9.4)에 있으면 목록 길로 간다
   1. 글의 날짜·시각을 읽는 말로 바꾼다(9.5)
   2. 플랫폼 설정 `tts.provider` 가 `local`(기본)이면 맥 엔진에 바꾼 글, 목소리, speed 를 보낸다. 받으면 200
   3. 맥 엔진이 실패하면(맥 엔진 연결이 없다, 닿지 않는다, 시간 초과, 5xx, 엔진이 모르는 목소리) `tts.fallback-to-openai`(기본 `true`)일 때 OpenAI 로 보낸다. 글은 바꾼 글, 목소리는 그 목소리의 `openai_voice`, 모델은 요청의 `model`(없으면 `tts-1`)이다. 꺼져 있으면 503
   4. `tts.provider` 가 `openai` 면 맥 엔진을 부르지 않고 3 의 OpenAI 로 보낸다
2. `voice` 가 목록에 없거나 비었으면 지금처럼 OpenAI 로만 보낸다. 글을 바꾸지 않는다. 다른 소비처와 bp-office 의 지금 설정(`nova`)은 그대로 돈다
3. 응답 머리글 `X-Aimbase-TTS-Engine` 에 소리를 만든 엔진(`local`, `openai`)을 싣는다
4. 목록 길의 `speed` 는 `tts.speed-min` ~ `tts.speed-max`(기본 0.5 ~ 2.0)다. 밖이면 400. 목록 밖 길은 지금처럼 OpenAI 가 정한다

| 상황 | 응답 |
|---|---|
| 빈 글 | 400(1 ~ 6절 그대로) |
| 목록 길 speed 범위 밖 | 400 |
| 맥 엔진 실패, OpenAI 전환 꺼짐 | 503 |
| OpenAI 로 갔는데 쓸 수 있는 OpenAI 연결이 없다 | 503 |
| OpenAI 가 오류를 돌려줌 | 그 상태와 본문 그대로(지금과 같다) |

컨트롤러는 요청 검증과 응답만 맡는다. OpenAI 로 보내는 일은 컨트롤러에서 음성 합성 서비스로 옮기고, 길 나누기는 받아쓰기의 `SpeechServiceRouter` 와 같은 모양의 음성 합성 라우터가 한다.

### 9.4 목소리 목록

플랫폼 설정 `tts.voices` 에 JSON 배열로 둔다. 맥이 꺼져 있어도 목록은 나온다.

| 칸 | 뜻 | 첫 값 |
|---|---|---|
| `id` | 요청 `voice` 에 넣는 값. 맥 엔진 `voices/<id>/` 와 같다 | `ko-female-01` |
| `name` | 선택 화면에 보일 이름 | 「밝은 비서」(7절 질의 5) |
| `description` | 선택 화면 설명 | 20대 여성, 밝고 친근한 말투 |
| `openai_voice` | 맥 엔진이 실패해 OpenAI 로 갈 때 쓰는 OpenAI 목소리. 목록 API 로 내보내지 않는다 | `nova` |
| `default` | 선택하지 않았을 때 쓸 목소리. 하나만 `true` | `true` |

`GET /api/v1/speech/voices`

```json
{
  "success": true,
  "data": {
    "voices": [
      { "id": "ko-female-01", "name": "밝은 비서", "description": "20대 여성, 밝고 친근한 말투", "default": true }
    ],
    "speed": { "min": 0.5, "max": 2.0, "default": 1.0 }
  }
}
```

- 말투(톤): 복제 모델은 말투 지시를 받지 않는다. 말투가 다른 목소리는 목록에 다른 목소리로 넣는다
- 목소리를 늘리려면 맥 엔진 `voices/` 에 폴더를 더해 설치 스크립트를 다시 돌리고, `tts.voices` 에 한 줄을 더한다. 관리 화면은 두지 않는다(받아쓰기 설정 `stt.*` 와 같다)
- 설정 값이 JSON 으로 읽히지 않으면 목록이 빈 것으로 보고 경고를 남긴다. 그때 모든 요청은 2 의 OpenAI 길로 간다

### 9.5 날짜·시각을 읽는 말로 바꾸기

목록 길에서만 바꾼다. 맥 엔진과 OpenAI 로 전환할 때 같은 글을 쓴다.

| 글 | 읽는 말 |
|---|---|
| `2026-10-31`, `2026.10.31`, `2026/10/31` | 2026년 10월 31일 |
| `2026-01-05` | 2026년 1월 5일(앞의 0 을 뺀다) |
| `14:00` | 오후 2시 |
| `09:05`, `9:05` | 오전 9시 5분 |
| `00:30` | 오전 0시 30분 |
| `12:00` | 오후 12시 |
| `14:00:30` | 오후 2시 0분 30초 |
| `14:30:00` | 오후 2시 30분(초가 0 이면 뺀다) |
| `2026-10-31 14:00`, `2026-10-31T14:00` | 2026년 10월 31일 오후 2시 |

바꾸지 않는 것

- 없는 날짜, 시각: `2026-13-01`, `2026-02-30`, `25:00`, `14:60`
- 앞뒤에 숫자가 더 붙은 것: `12026-10-31`, `14:000`
- 분이 한 자리인 것(`16:9` 같은 비율)과 전화번호(`010-1234-5678`)
- 두 자리 연도(`26.10.31`)

그 밖의 숫자(10월 30일, 3건, 12억 4천만 원, 8.5%)는 엔진이 맞게 읽었다(6절 5, 2차 비교).

### 9.10 시험

단위시험

1. 날짜·시각 표(9.5)의 바꾸는 것과 바꾸지 않는 것 전부
2. 목록 목소리: 맥 엔진 성공이면 엔진 머리글 `local`, OpenAI 를 부르지 않는다
3. 목록 목소리: 맥 엔진 연결 없음, 시간 초과, 500, 404 이고 OpenAI 전환이 켜져 있으면 OpenAI 에 바꾼 글과 `openai_voice` 가 간다. 꺼져 있으면 503 이고 OpenAI 를 부르지 않는다
4. `tts.provider=openai` 면 맥 엔진을 부르지 않는다
5. 목록 밖 목소리(`nova`)와 빈 목소리는 지금처럼 OpenAI 로 가고 글이 바뀌지 않는다(다른 소비처 보호). 1 ~ 6절 시험 그대로 통과
6. 목록 길 speed 0.49, 2.01 은 400. 0.5, 2.0 은 통과
7. 목소리 목록 API 에 `openai_voice` 가 없다. 설정이 JSON 이 아니면 빈 목록
8. 맥 엔진(파이썬): 키 없음 401, 모르는 목소리 404, 빈 글 400, 긴 글 나누기, speed 의 ffmpeg 필터, 동시 두 요청이 차례로 처리됨, 같은 글 두 번이 같은 소리

로컬 확인

1. 맥 엔진을 launchd 로 기동하고, 로컬 api 에 `tts_local` 연결을 넣어 bp-office 와 같은 모양(`X-API-Key`)으로 브리핑 글을 만든다. 날짜·시각이 읽는 말로 나오는지 로컬 받아쓰기로 본다
2. 맥 엔진을 내리면 OpenAI 로 전환하는지 가짜 OpenAI 로 본다(실제 OpenAI 는 부르지 않는다)
3. 목록 밖 목소리 요청이 지금처럼 OpenAI(가짜)로 가는지 본다

결과(2026-10-31 11:40, 로컬 api 8181, 맥 엔진 launchd 8391, 가짜 OpenAI 18765, 로컬 테넌트 `tenant_dev`)

- 단위시험: 자바 115건(음성 전체, CR-166 시험 포함), 파이썬 17건 통과. 같은 글 두 번이 같은 소리(TC-TTS-237)는 실제 모델로 통과(46초)
- 마스터 V72 가 기동 때 들어가 `tts.*` 설정 5개가 생겼다. 목소리 목록 API 는 `ko-female-01` 하나와 speed 0.5 ~ 2.0, 기본 1.0 을 주고 `openai_voice` 는 없다
- 1: 브리핑 글(92자)이 200 `audio/mpeg`, 머리글 `local`, 15.7초. 받아쓰기 결과 「주간 회의는 2026년 11월 7일 오후 2시 30분에 시작합니다. 납품기한은 2026년 11월 10일이고 점검은 오전 9시 5분입니다」. 원문은 `2026-11-07 14:30`, `2026.11.10`, `9:05`
- 2: 맥 엔진 연결 주소를 닫힌 포트로 바꾸자 머리글 `openai`. 가짜 OpenAI 가 읽는 말로 바꾼 글과 목소리 `nova`, `tts-1` 을 받았다. 키는 환경변수 값(길이로만 대조). 이때 로그 원인이 `null` 로 남아 연결 거부의 종류 이름을 남기게 고쳤다(TC-TTS-213 에 연결 거부 추가)
- 3: 목소리 `nova` 는 머리글 `openai`, 가짜 OpenAI 에 원문 그대로 갔다
- 목록 목소리 speed 2.01 은 400
- 인증은 로그인 토큰으로 했다. 이번 변경은 인증을 건드리지 않으며, bp-office 키(`X-API-Key`)로 부르는 것은 9.11 의 4 에서 본다
- 시험 연결 둘은 지웠다

통합시험 항목은 `tools/testbook/items/items_06.py`(영역 06, IT-06-001 ~ 006)다. OpenAI 로 가는 IT-06-003, 006 은 크레딧이 있어야 200 이다.
