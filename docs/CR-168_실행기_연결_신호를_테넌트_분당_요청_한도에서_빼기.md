## 1. 배경

- 11-03 14:15 ~ 16:18 운영 chaws 에서 bp-wms 의 음성 조회가 `bp_wms` 테넌트 분당 요청 한도 60을 다 썼다. 실행기 연결 신호도 같은 한도로 세어 93번 거절됐고, 실행기가 두 번 끊김으로 표시됐다(14:20 ~ 15:01, 15:33 ~ 16:12). 14:50 「차수 편성 추천 의견」 1건이 `cli_agent_offline` 으로 실패했다
- 18:57 `bp_wms` 한도를 600 으로 올려 증상은 없앴다(CR-167). 원인은 그대로다. 업무 요청이 한도를 다 쓰면 실행기가 끊김으로 표시되고, 그동안 그 테넌트의 AI 기능이 막힌다
- 사용자 결정(11-03 19:02): 실행기 연결 신호를 한도에서 제외하는 별건 CR 로 고친다

끊김으로 바뀌는 길은 이렇다.

1. 한도는 테넌트마다 분 단위 칸 하나로 센다. 칸은 매 분 0초에 새로 열린다(`TokenBucketRateLimiter.java:90`, 키 `rl:{테넌트}:{분}`)
2. 요청 한도 판정은 인증을 통과한 `/api/v1/**` 요청 전부에 걸린다(`RateLimitFilter.java:28, 46`). 실행기 연결 신호도 같은 칸을 쓴다
3. 그 분의 칸을 업무 요청이 먼저 다 쓰면 그 분의 상태 알림은 429 로 거절된다. 실행기는 429 를 실패로만 남기고 다음 주기(60초)에 다시 보낸다(`AgentLifecycle.java:174`)
4. 상태 알림이 5분 동안 한 번도 닿지 않으면 서버가 끊김(STALE)으로 표시한다(`AgentRegistryService.java:29, 271`). 끊김인 동안 그 실행기로 가는 CLI 호출은 `cli_agent_offline` 으로 실패한다(`ClaudeCliAdapter.java:305, 316`)

## 2. 연결 신호 경로

실행기(`aimbase-agent`)는 서버와의 연결을 `tool-sdk-mcp` 의 `AgentLifecycle` 과 `AimbaseRegistrationClient` 로만 주고받는다(`AgentServiceManager.java:21`). 실행기가 api 로 보내는 요청은 아래 넷이 전부다.

| 순번 | 메서드, 경로 | 언제 보내나 | 근거 | 연결 신호 |
|---|---|---|---|---|
| 1 | `POST /api/v1/agents/{id}/heartbeat` (상태 알림) | 60초마다 | 보냄 `AgentLifecycle.java:152, 174`, `AimbaseRegistrationClient.java:126`. 주기 `AgentProperties.java:48`. 받음 `AgentRegistryController.java:64` | 예 |
| 2 | `POST /api/v1/agents/register` (등록) | 시작 때, 등록 id 가 없거나 상태 알림이 404 일 때 매 주기, TURN 중계 주소를 다시 받았을 때 | 보냄 `AgentLifecycle.java:144, 176, 182, 363`, `AimbaseRegistrationClient.java:71`. 받음 `AgentRegistryController.java:33` | 예 |
| 3 | `DELETE /api/v1/agents/{id}` (등록 해제) | 실행기가 내려갈 때 한 번 | 보냄 `AimbaseRegistrationClient.java:103`. 받음 `AgentRegistryController.java:45` | 아니오 |
| 4 | `POST /api/v1/agents/{agentId}/runs/{runId}/events` (실행 출력 전달) | 지금 부르는 코드가 없다 | `AgentEventPushClient.java:70`. 이 클래스를 쓰는 곳 없음 | 아니오 |

- 등록(2)을 넣는 이유: 상태 알림이 404 면 실행기가 살아나는 길은 다시 등록하는 것뿐이다. 등록 id 가 없는 동안 실행기는 상태 알림을 보내지 않고 등록만 되풀이한다(`AgentLifecycle.java:175`). 등록이 거절되면 한도를 다 쓴 동안 끊김이 그대로 남는다
- 등록 해제(3)를 넣지 않는 이유: 살아 있음을 알리는 요청이 아니다. 거절돼도 5분 뒤 끊김으로 표시되어 정리된다. 관리자도 같은 경로로 실행기를 해제한다
- 실행기 안의 5분 주기 상태 기록(`AgentHealthReporter.java:33`)은 실행기 PC 의 파일에만 쓰고 서버로 보내지 않는다

판정은 메서드와 경로를 함께 본다.

| 순번 | 메서드 | 경로 | 맞추는 방식 |
|---|---|---|---|
| 1 | POST | `/api/v1/agents/{id}/heartbeat` | `{id}` 는 UUID 모양만(8-4-4-4-12 자리 16진수). 등록 id 는 UUID 다(`AgentRegistryController.java:65`) |
| 2 | POST | `/api/v1/agents/register` | 글자 그대로 |

이 밖의 요청은 지금처럼 센다. `GET /api/v1/agents`(목록), `DELETE /api/v1/agents/{id}`, UUID 가 아닌 id 의 상태 알림도 센다.

## 3. 설계

### 3.1 한도 판정에서 연결 신호를 제외

`RateLimitFilter.shouldNotFilter` 가 연결 신호면 한도 판정을 건너뛴다(`RateLimitFilter.java:46`). 요청 수 한도를 세는 곳은 이 필터 하나다. 건너뛴 요청은 칸을 쓰지 않고 `X-RateLimit-*` 머리글도 붙지 않는다. 실행기는 이 머리글을 읽지 않는다.

### 3.2 경로 목록을 코드에 두는 이유

목록은 실행기와 서버 컨트롤러 코드가 정하는 경로라 코드와 같이 바뀐다. 설정값으로 빼면 운영에서 업무 경로까지 한도 밖으로 옮길 수 있게 된다. 그래서 필터 안의 상수로 둔다. 바꿀 때는 이 문서 2절과 BIZ-141 을 같이 고친다.

### 3.3 인증

한도에서 제외해도 인증은 그대로다. `/api/v1/**` 는 인증한 요청만 받고(`SecurityConfig.java:95`), 등록과 상태 알림은 테넌트 키로 인증한다(BIZ-126). 인증 필터 묶음이 요청 한도 판정보다 먼저 돈다. 둘 다 순서값이 -100 이고 인증 쪽이 먼저 등록된다. 로컬에서 키 없는 요청과 틀린 키 요청은 403 을 받고 테넌트 칸 수가 그대로인 것을 봤다(11-03 19:21). `RateLimitFilter` 주석의 「SecurityFilterChain 앞에서 실행」 은 실제와 다르다.

## 4. 한도에서 제외한 연결 신호를 막는 장치

이미 있는 것을 봤다.

| 순번 | 장치 | 있나 | 근거 |
|---|---|---|---|
| 1 | 테넌트 분당 한도 | 이 건 뒤로는 연결 신호에 걸리지 않는다 | `RateLimitFilter.java` |
| 2 | 인증 | 있다. 키가 없거나 틀리면 403. 횟수는 막지 않는다 | `SecurityConfig.java:95`, BIZ-126 |
| 3 | 실행기 쪽 주기 | 상태 알림 60초, 등록은 id 가 없거나 404 일 때만. 정상 실행기는 분당 1 ~ 2번이다. 서버가 강제하는 것은 아니다 | `AgentLifecycle.java:152, 174` |
| 4 | 연결 신호만 세는 한도 | 없다. 다른 한도는 음성 변환(BIZ-104), 원격 트리거(BIZ-067), 서버 MCP(`mcp:{테넌트}`), LLM 호출(`RateLimitedLLMProxy`) 용이다 | 소스 검색 |
| 5 | 앞단 프록시 한도 | Aimbase 의 chaws 구성에는 프록시가 없다 | `docker-compose.chaws.yml` |

막는 장치가 없다. 키를 가진 쪽이 잘못 돌면 막지 못한다. 상태 알림 한 번은 테넌트 DB 조회 1번, 쓰기 1번이다. 등록 한 번은 쓰기와 등록 알림이고, 등록 알림은 그 사용자 연결의 끊김 차단기를 풀어 준다(CR-081). 쉬지 않고 등록하는 실행기는 차단기를 계속 풀어 버린다.

막을 방법(컨타에 올림, 결정 대기):

1. 연결 신호만 세는 칸을 테넌트마다 따로 둔다(권장). 업무 요청의 칸과 나눠, 업무 요청이 한도를 다 써도 연결 신호는 살고, 연결 신호가 넘쳐도 정한 수에서 429 로 막는다. 분당 한도는 설정값(기본 60, 정상 실행기 30대 몫). 이 건에 함께 넣는다
2. 이 건에서는 막지 않고 기록만 남긴다(잃는 것: 잘못 도는 실행기나 새어 나간 키의 반복을 서버가 막지 못한다)

## 5. 요청서와 다른 것

1. 등록(`POST /api/v1/agents/register`)도 연결 신호에 넣는다. 요청서의 「살아 있음을 알리는 요청」 은 상태 알림이지만, 상태 알림이 404 일 때 살아나는 길이 등록뿐이다(2절)
