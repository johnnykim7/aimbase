## 3. 서버

### 3.1 대화 요청 `image` 칸 [PRD-540, PRD-541, BIZ-230, BIZ-231]

`POST /api/v1/chat/completions` 에 칸 하나를 더한다(`ChatCompletionRequest.image`).

```json
{"image": {"action": "create"}}
{"image": {"action": "edit", "source_image_id": "4b1c..."}}
```

| 순번 | 경우 | 동작 |
|---|---|---|
| 1 | `image` 없음 | 지금과 같다 |
| 2 | `action=create` | 마지막 사용자 메시지의 글을 그림 설명으로 그림을 만든다. 그 메시지에 붙인 그림(image 블록)이 있으면 바탕 그림으로 쓴다 |
| 3 | `action=edit` | `source_image_id` 그림과 붙인 그림을 바탕으로 고친다 |
| 4 | `action` 이 그 밖의 값 | 400 `image_invalid` |

- 모델을 부르지 않는다. `model`, `thinking`, `tool_filter`, `rag_source_id`, `response_format` 은 쓰지 않는다.
- `rewind_from_seq` 는 지금처럼 먼저 되감는다. 그래서 위젯 다시 생성과 질문 수정이 그림을 다시 만든다.
- 스트림(`stream=true`)과 한 번에 받기 모두 된다.

요청 검사(스트림을 열기 전, 400 JSON):

| 순번 | 조건 | 오류 |
|---|---|---|
| 1 | `connection_id` 가 없거나 그 연결에 그림 연결이 없다(3.2) | `image_not_configured` |
| 2 | 그림 설명 글이 비었다 | `image_prompt_empty` |
| 3 | 글이 `widget.image.max-prompt-chars` 를 넘는다 | `image_prompt_too_long` |
| 4 | 바탕 그림이 `widget.image.max-source-images` 를 넘는다 | `image_too_many_sources` |
| 5 | 붙인 것 중 그림이 아닌 것(PDF, 문서)이 있다 | `image_source_invalid` |
| 6 | `source_image_id` 가 그 대화에서 만든 그림이 아니거나 지워졌다 | 404 `image_not_found` |
| 7 | 그 대화에 답이 도는 중 | 지금 규칙 그대로(409 `session_busy`, CR-175) |

### 3.2 그림 연결 [PRD-544, BIZ-230]

| 순번 | 연결 | config 칸 | 뜻 |
|---|---|---|---|
| 1 | 대화 연결(위젯이 쓰는 연결, 어댑터 무관) | `image_connection_id` | 이 대화 연결이 그림을 만들 때 쓸 연결 id |
| 2 | 그림 연결(어댑터 OpenAI) | `image_model` | 그림 모델 이름(예: `gpt-image-1`). 있어야 그림 연결이다 |
| 3 | 그림 연결 | `image_quality` | `low`, `medium`, `high`, `auto`. 없으면 `medium`. 그림 한 장 값이 이것으로 갈린다 |
| 4 | 그림 연결 | `apiKey`, `apiKey_env` | 지금 키 규칙 그대로(`ConnectionApiKeys`) |

- 그림 연결은 같은 테넌트 연결이어야 한다. 없거나, 어댑터가 OpenAI 가 아니거나, `image_model` 이 비었거나, 키가 없으면 그림 연결이 없는 것이다(`image_not_configured`).
- 연결 상태(연결됨 여부)는 보지 않는다. OpenAI 연결 시험은 대화 API 로 핑을 보내 크레딧이 없으면 실패로 남는데, 그림 호출은 따로 실패를 알려 주기 때문이다.
- 공급처 주소는 앱 설정 `aimbase.image.openai-base-url`(기본 `https://api.openai.com/v1`)이다. 로컬에서 가짜 OpenAI 로 본문을 받아 보려고 뺀다(CR-165 와 같은 까닭).

### 3.3 공급처 호출 [PRD-540, PRD-541]

| 순번 | 경우 | 호출 |
|---|---|---|
| 1 | 바탕 그림 없음 | `POST {base}/images/generations` JSON `{model, prompt, size: "auto", quality, n: 1}` |
| 2 | 바탕 그림 있음 | `POST {base}/images/edits` multipart `model`, `prompt`, `image[]`(바탕 그림들), `size=auto`, `quality`, `n=1` |

- 응답 `data[0].b64_json` 을 그림 파일로 저장한다(3.4). `usage` 의 토큰은 사용량 기록에 그림 모델 이름으로 남긴다.
- 시간 한도는 `widget.image.timeout-ms`. 넘으면 끊고 `image_timeout`.
- 공급처 실패는 스트림이 열린 뒤에 난다. 스트림이면 `event: error`, `data: {"code": ...}` 를 보내고 닫는다. 한 번에 받기면 같은 코드의 502 다. 대화 기록에는 아무것도 남기지 않는다.

| 순번 | 공급처 응답 | 코드 |
|---|---|---|
| 1 | 401, 403 | `image_provider_auth` |
| 2 | 429(요청 한도, 크레딧 없음) | `image_provider_quota` |
| 3 | 400 중 내용 거절(`moderation_blocked`, `content_policy_violation`) | `image_rejected` |
| 4 | 시간 한도 넘음 | `image_timeout` |
| 5 | 그 밖 | `image_failed` |

- 응답 중지(`POST /api/v1/chat/{sessionId}/abort`)는 공급처 호출을 끊는다. 대화 기록에는 질문과 「[중단됨]」 답을 남기고 끝 이벤트에 `turn_seq` 를 준다(대화 답 중지와 같다, CR-175 4.2). 그림은 남기지 않는다.

### 3.4 저장과 대화 기록 [PRD-540, BIZ-231, BIZ-232]

1. 그림 파일은 `StorageService.save(tenant, "generated-images", "<그림 id>.png", ...)` 로 둔다.
2. `chat_generated_images` 에 한 줄(5.1).
3. 대화 기록에는 한 묶음(turn)으로 질문 메시지와 답 메시지를 넣는다(`SessionStore.appendTurn`). 답 글은 그림 참조 마크다운 한 줄이다.

```
![<그림 설명 앞 100자>](aimbase-image:<그림 id>)
```

- 설명 글의 줄바꿈, `[`, `]` 는 빈칸으로 바꾼다.
- 위젯은 이 글을 마크다운 확장으로 그림 자리로 바꿔 그린다(4.2). 지난 대화를 다시 그릴 때(CR-178)도 같은 글이라 따로 맞출 것이 없다.
- API 연결은 다음 질문에서 이 글을 대화 기록으로 받는다. 그림을 만들었다는 것과 그 설명을 안다.
- 다시 생성, 질문 수정으로 되감긴 묶음의 그림은 그 묶음 메시지와 함께 지운 표시(`deleted_at`)한다. 대화를 지우면 그 대화의 그림도 지운 표시한다. 파일은 지우지 않는다(대화 메시지와 같은 원칙).

스트림 이벤트 순서:

| 순번 | 이벤트 | 데이터 |
|---|---|---|
| 1 | `image_status` | `{"state": "generating"}`. 위젯 본체는 모르는 이벤트라 기능이 받는다 |
| 2 | `delta` | 답 글(그림 참조 마크다운) 한 번 |
| 3 | `done` | 지금 칸(`turn_id`, `turn_seq`, `model`=그림 모델) + `images: [{id, media_type, width, height}]` |

### 3.5 그림 받기 [PRD-542, BIZ-233]

`GET /api/v1/chat/images/{image_id}?session_id={sessionId}`

- 권한은 대화와 같다(`chat:stream` 위젯 토큰 또는 로그인).
- 그 테넌트에 그 그림이 있고, `session_id` 가 그 그림의 대화이고, 지운 표시가 없어야 한다. 아니면 404 `image_not_found`.
- 대화 주인 검사는 대화 지우기와 같다. 대화의 `user_id` 가 있으면 지금 사람과 같아야 한다. 다르면 403.
- 응답은 그림 바이트, `Content-Type` 은 저장한 형식, `Content-Disposition: inline`, `Cache-Control: private, max-age=86400`(그림은 바뀌지 않는다).

### 3.6 위젯 설정 조회에 칸 추가 [PRD-544]

`GET /api/v1/chat/widget-settings?connection_id=` 응답에 더한다.

```json
{"image_generation": {"enabled": true, "max_prompt_chars": 4000, "max_source_images": 4}}
```

- `enabled` 는 3.2 의 그림 연결이 있으면 참. `connection_id` 가 없으면 거짓.
- `max_prompt_chars`, `max_source_images` 는 5.2 설정값이다. 오류 응답(`ApiResponse.error`)은 코드만 주고 틀의 오류 문구 등록도 코드만 받으므로, 위젯은 상한을 여기서 읽어 문구의 N 에 쓴다.

## 4. 위젯 [PRD-543]

`src/features/image-gen.ts` 하나. 등록표(`src/features/index.ts`)에 한 줄.

### 4.1 화면 구성

T3-3 「위젯 이미지 생성」(화면 나무, 자리별 보이는 것과 누를 것), 상황별 동작과 오류 문구는 T3-4 「위젯 이미지 생성」.

### 4.2 동작

| 순번 | 기능 | 동작 |
|---|---|---|
| 1 | + 메뉴 | 「그림 만들기」(group 1, order 10). 위젯 설정 `image_generation.enabled` 일 때만 보인다 |
| 2 | 그림 만들기 모드 | 고르면 입력칸 모드 「그림 만들기」. 보내는 질문마다 `image: {action: "create"}` 를 싣는다. × 나 새 대화로 풀린다. 보낸 뒤에도 남는다 |
| 3 | 그림 답 | 마크다운 확장이 `aimbase-image:<id>` 그림 참조를 그림 자리로 바꾸고, 손질이 3.5 로 그림을 받아 그린다. 받는 중에는 회색 자리, 실패하면 「그림을 불러오지 못했습니다」 |
| 4 | 그림 아래 단추 | 크게 보기(위젯 판 위에 겹쳐 보기, Esc 로 닫기), 다운로드(`image-<날짜시각>.png`), 그림 고치기 |
| 5 | 그림 고치기 | 입력칸 모드 「그림 고치기」. 보내는 질문마다 `image: {action: "edit", source_image_id}` 를 싣는다. 답으로 새 그림이 오면 바탕을 그 그림으로 옮겨 이어 고친다 |
| 6 | 다시 생성, 질문 수정, 평가, 복사 | 위젯 본체 그대로. 본체가 그 질문의 `image` 칸을 다시 싣는다 |
| 7 | 기다리는 동안 | 위젯 본체 기다림 표시 그대로 |
| 8 | 오류 | 3.1, 3.3 의 코드를 `ctx.ui.addErrorTexts` 로 등록한 문구로 보인다. 스트림 중간 `event: error` 는 위젯 본체가 응답 오류로 끝낸다 |
