## 3. 서버

### 3.1 미리보기 종류 [PRD-460]

서버가 확장자로 미리보기 종류를 정하고, 위젯은 그 값만 보고 그린다. 종류는 코드가 보고 갈리므로 Enum `PreviewKind` 다.

| preview_kind | 확장자 | 서버가 하는 일 | 위젯이 하는 일 |
|---|---|---|---|
| PAGES | pptx, docx, pdf | 오피스 파일은 PDF 로 바꾸고, 쪽 수를 알려 주고, 쪽마다 그림을 준다 | 쪽 그림을 보인다 |
| SHEET | xlsx, csv | 시트마다 앞 행과 열을 표 데이터로 준다 | 표를 그린다 |
| HTML | html | 없음 | 내려받기 주소로 원본을 받아 격리 틀에서 실행한다 |
| SVG | svg | 없음 | 원본을 그림으로 보인다 |
| IMAGE | png, jpg, jpeg, gif, webp | 없음 | 원본을 그림으로 보인다 |
| MARKDOWN | md | 없음 | 원본을 기존 리치 렌더링으로 보인다 |
| TEXT | txt, json | 없음 | 원본을 고정폭 글로 보인다 |
| NONE | 위에 없거나 한도를 넘음 | 이유를 준다 | 「미리 볼 수 없는 파일입니다」와 내려받기 단추 |

- 산출물 확장자 목록에 svg, jpg, jpeg, gif, webp 를 더한다.
- 대화 끝 이벤트(스트리밍 done, 비스트리밍 result)의 `artifacts[]` 에 `modified_at`(ISO-8601 UTC), `preview_kind` 를 더한다. 같은 이름의 파일이 다시 만들어지면 `modified_at` 이 바뀐다.

### 3.2 미리보기 정보 [PRD-460, PRD-461, PRD-462]

`GET /api/v1/chat/artifacts/preview?session_id={id}&name={파일 이름}`

```json
{ "name": "제안서.pptx", "size": 482113, "modified_at": "2026-11-13T05:12:40Z",
  "preview_kind": "PAGES", "page_count": 12, "page_width": 1600, "page_height": 900 }
```

```json
{ "name": "매출.xlsx", "preview_kind": "SHEET",
  "sheets": [ { "name": "1월", "rows": [["지점", "매출"], ["강남", "1,200,000"]],
                "row_count": 1200, "col_count": 8, "truncated": true } ] }
```

```json
{ "name": "큰파일.pptx", "preview_kind": "NONE", "reason": "too_large" }
```

- 권한과 격리는 내려받기와 같다(`chat:upload` 또는 로그인, 세션 작업 폴더는 현재 테넌트 DB 에서만, 경로 탈출 차단). 파일 이름에 경로 구분자(`/`, `\`)가 있으면 403 이다. 산출물은 `out/` 바로 아래 파일뿐이어서 내려받기도 같은 검사를 한다. BIZ-194
- PAGES 는 처음 부를 때 변환한다. pptx, docx 는 LibreOffice 로 PDF 를 만들고, 쪽 수는 PDF 에서 센다. 첫 쪽 크기를 `page_width`, `page_height` 로 준다(그림 픽셀 기준).
- SHEET 는 xlsx 를 POI 로 읽는다. 수식 칸은 계산한 값을 보이고(만든 프로그램이 값을 남기지 않은 파일도 있어 서버가 계산한다), 계산이 안 되면 수식 글을 보인다. 날짜와 숫자는 칸에 걸린 표시 형식대로 글로 바꾼다. csv 는 UTF-8(BOM 포함)로 읽고, 깨지면 CP949 로 다시 읽는다. 행과 열은 설정 한도까지만 준다. BIZ-193
- 한도를 넘으면 오류가 아니라 `NONE` 과 이유를 준다. 이유는 `too_large`(파일 크기), `too_many_pages`(쪽 수), `unsupported`(종류). BIZ-191
- 변환이 실패하거나 시간 한도를 넘으면 422 `preview_failed:convert`, `preview_failed:timeout`. 동시 변환 자리를 시간 한도 안에 얻지 못하면 503 `preview_busy`.
- 파일이 없으면 404 `artifact_not_found`, 허용 폴더 밖이나 경로 탈출이면 403 `artifact_access_denied`.

### 3.3 쪽 그림 [PRD-461, PRD-465]

`GET /api/v1/chat/artifacts/preview/page?session_id={id}&name={파일 이름}&page={n}`

- PNG 를 준다. page 는 1부터. 가로 픽셀은 설정 `widget.preview-page-width-px` 다.
- 쪽마다 처음 부를 때 poppler(`pdftoppm -png -singlefile -scale-to-x <가로> -scale-to-y -1`)로 그리고 캐시한다. 변환이 안 된 파일이면 먼저 변환한다.
- 쪽 번호가 범위 밖이면 404 `page_not_found`. 그 밖의 오류는 3.2 와 같다.
- 응답 머리에 `Cache-Control: private, max-age=86400` 을 붙인다. 위젯은 주소에 `modified_at` 을 붙여 부르므로 파일이 바뀌면 새로 받는다.

### 3.4 변환과 캐시 [BIZ-191, BIZ-192]

| 순번 | 무엇 | 정한 것 |
|---|---|---|
| 1 | 변환기 | LibreOffice headless. `soffice --headless --norestore -env:UserInstallation=file://<임시 폴더> --convert-to pdf --outdir <캐시> <원본>`. 변환마다 사용자 프로필 폴더를 따로 써서 동시 변환이 서로 막지 않게 하고 끝나면 지운다 |
| 2 | 변환기 위치 | api 컨테이너. Dockerfile 에 `libreoffice-impress libreoffice-writer libreoffice-calc`(추천 패키지 없이)와 한글 글꼴 `fonts-nanum fonts-noto-cjk` 를 더한다. 실행 파일 경로는 `aimbase.preview.soffice-path`(환경변수 `AIMBASE_PREVIEW_SOFFICE_PATH`, 처음 값 `soffice`) |
| 3 | 동시 변환 | 설정 `widget.preview-convert-concurrency` 만큼만 돈다. 같은 파일을 두 요청이 동시에 부르면 한 번만 변환하고 다른 요청은 그 결과를 기다린다. 가상 스레드가 묶이지 않게 `synchronized` 대신 잠금 객체를 쓴다 |
| 4 | 시간 한도 | 설정 `widget.preview-convert-timeout-seconds`. 넘으면 변환기와 그 자식 프로세스를 끝낸다 |
| 5 | 캐시 자리 | 세션 작업 폴더의 `.preview/<파일 이름 해시>-<수정 시각>-<크기>/` 아래 `doc.pdf`, `p<쪽>-<가로>.png`. 가로 픽셀 설정을 바꾸면 새로 그린다. 산출물 폴더 `out/` 밖이라 칩 목록에 섞이지 않는다 |
| 6 | 캐시 지우기 | 산출물 정리(ArtifactGcScheduler)가 `.preview/` 도 같은 보관 기한으로 지운다. 원본이 바뀌면 열쇠가 바뀌어 새로 만든다 |
| 7 | 로컬 | 맥 bootRun 은 Homebrew LibreOffice(`/opt/homebrew/bin/soffice`)를 쓴다. PATH 에 있으므로 처음 값 그대로 돈다 |

### 3.5 위젯 설정 칸 추가 [PRD-463]

CR-175 위젯 설정 조회(`GET /api/v1/chat/widget-settings`) 응답에 `preview_html_script_sources` 를 더한다. HTML 실행 틀이 스크립트, 스타일, 글꼴, 그림을 불러올 수 있는 출처 목록이다. 값은 설정 `widget.preview-html-script-sources`.

## 4. 위젯

### 4.1 화면 구성

옆 창 자리, 너비, 여닫기는 CR-177 틀을 따른다(`docs/guides/chat-widget-frame.md` 3.3). 위젯 폭이 760px 보다 좁으면 옆 창을 열 때 크게 보기로 바뀌고, 옆 창은 위젯 폭의 56% 다. 이 CR 은 옆 창 안에 들어가는 미리보기와 답 안의 단추만 만든다. 화면 컨셉은 T3-3 「위젯 옆 창 미리보기」.

| 순번 | 자리 | 들어가는 것 | 틀의 자리 |
|---|---|---|---|
| 1 | 답 아래 파일 칩 | 기존 칩 그대로. 미리 볼 수 있는 파일(`preview_kind` 가 NONE 이 아님)은 누르면 옆 창 미리보기, 아니면 지금처럼 내려받기 | `ctx.ui.answer.addArtifactOpener` |
| 2 | 답 안 HTML 코드 블록 | 코드 블록 머리에 「실행」 단추(답이 끝난 뒤) | `ctx.ui.answer.addDecorator` |
| 3 | 답 안 SVG 코드 블록 | 코드 자리에 그림. 「그림」, 「코드」 바꾸기, 「옆 창에서 보기」 | `ctx.ui.answer.addDecorator` |
| 4 | 옆 창 머리줄 | 파일 이름, 쪽 표시(n / N, PAGES 만), CR-181 이 더하는 단추, 발표(PAGES 만), 내려받기(파일만), 닫기(틀) | `ctx.ui.sidePane.open` 의 `title`, `tools` |
| 5 | 옆 창 본문 | 종류별 보기(4.2) | `render` |
| 6 | 옆 창 아래 줄 | 비움. CR-181 고치기 입력칸 자리 | `footer` |

### 4.2 종류별 보기

| 순번 | 종류 | 보기 |
|---|---|---|
| 1 | PAGES, pptx | 한 장씩 보인다. 아래에 「이전」, 「다음」, n / N. 옆 창에 초점이 있으면 왼쪽, 오른쪽 화살표로 넘긴다 |
| 2 | PAGES, docx, pdf | 쪽을 위아래로 이어 보인다. 보이는 쪽만 그림을 받는다. 머리줄 쪽 표시는 지금 보이는 쪽을 따라간다 |
| 3 | SHEET | 시트가 둘 이상이면 위에 시트 탭. 첫 행 고정, 행 번호, 가로세로 스크롤. 한도에서 잘랐으면 표 위에 「처음 N행, M열만 보입니다. 전체는 내려받아 보세요」 |
| 4 | HTML | 격리 틀에서 실행한다(4.4). 머리줄 아래에 「실행」, 「코드」 바꾸기와 「다시 실행」 |
| 5 | SVG, IMAGE | 옆 창 너비에 맞춰 보인다. 누르면 원래 크기와 맞춤을 오간다 |
| 6 | MARKDOWN | 답과 같은 리치 렌더링 |
| 7 | TEXT | 고정폭 글. json 은 들여쓰기해 보인다 |
| 8 | 불러오는 중 | 「미리보기를 만드는 중입니다」. 변환이 몇 초 걸린다 |
| 9 | NONE, 오류 | 이유별 문구와 내려받기 단추. `too_large` 「파일이 커서 미리 볼 수 없습니다」, `too_many_pages` 「쪽이 많아 미리 볼 수 없습니다」, `unsupported` 「미리 볼 수 없는 파일입니다」, 변환 실패 「미리보기를 만들지 못했습니다」, `preview_busy` 「미리보기를 만드는 사람이 많습니다. 잠시 뒤 다시 열어 주세요」 |

### 4.3 동작

| 순번 | 기능 | 동작 |
|---|---|---|
| 1 | 열기 | 파일 칩, 「실행」, 「옆 창에서 보기」를 누르면 옆 창이 열리고 그 문서를 보인다. 이미 열려 있으면 내용만 바꾼다(옆 창 id 는 하나, `preview`) |
| 2 | 바뀐 파일 새로 불러오기 | 답이 끝났을 때(`answerDone`) 옆 창에 열린 파일의 `modified_at` 이 바뀌었으면 새로 불러온다. 옆 창이 닫혀 있으면 저절로 열지 않는다. 위젯 칸이 좁으면 옆 창을 여는 순간 크게 보기로 바뀌므로, 답이 끝날 때마다 화면이 커지는 일을 막는다 |
| 3 | 내려받기 | 옆 창 머리줄 단추. 미리 볼 수 없는 파일의 칩은 지금처럼 바로 내려받는다. 받는 방법은 CR-132 그대로 |
| 4 | 발표 | 지금 장부터 화면 가득(브라우저 전체 화면) 띄운다. 검은 바탕에 한 장, 오른쪽 아래 n / N. 오른쪽 화살표, 스페이스, Page Down, 오른쪽 절반 누르기는 다음, 왼쪽 화살표, Page Up, 왼쪽 절반 누르기는 이전, Home, End 는 처음과 끝. Esc 로 끝내고 옆 창은 마지막 장에 머문다. 브라우저가 전체 화면을 막으면 위젯을 붙인 페이지 전체를 덮어 같은 동작을 한다 |
| 5 | 다음 장 미리 받기 | 한 장씩 볼 때와 발표 중에는 다음 장 그림을 미리 받아 넘김이 끊기지 않게 한다 |
| 6 | Esc 순서 | 브라우저 전체 화면은 Esc 를 브라우저가 받아 끝낸다. 페이지를 덮는 방식일 때는 `ctx.ui.onEscape` 로 발표 끝내기를 먼저 받는다 |
| 7 | 새 대화 | 새 대화를 시작하면(`newConversation`) 옆 창을 닫는다. 앞 세션 파일은 그 세션을 다시 열 때 볼 수 있다(CR-178) |

### 4.4 HTML 실행 틀 [BIZ-190]

| 순번 | 정한 것 | 이유 |
|---|---|---|
| 1 | `iframe sandbox="allow-scripts allow-forms allow-modals"`, `srcdoc` 에 원본을 넣는다. `allow-same-origin` 은 주지 않는다 | 틀 안 코드는 출처가 없는 것으로 다뤄져 위젯 토큰, 부모 화면, 쿠키, 저장소에 닿지 못한다 |
| 2 | 원본 앞에 정책 meta 를 넣는다: `default-src 'none'; script-src 'unsafe-inline' <허용 출처>; style-src 'unsafe-inline' <허용 출처>; font-src data: <허용 출처>; img-src data: blob: <허용 출처>; media-src data: blob:; connect-src 'none'; form-action 'none'; base-uri 'none'` | 화면 안 계산과 입력은 되게 두고, 밖으로 데이터를 보내는 길(fetch, 폼 전송, 바깥 그림 주소)을 막는다 |
| 3 | 허용 출처는 위젯 설정 `preview_html_script_sources` | 외부 주소를 코드에 박지 않는다 |
| 4 | 답 안 HTML 코드 블록은 답이 끝난 뒤에만 「실행」 단추를 보인다 | 덜 온 코드를 실행하지 않는다. 답 번호(turn_id)도 그때 생긴다 |
| 5 | 틀 크기는 옆 창 본문을 채운다. 틀 안 `alert`, `confirm` 은 된다 | 계산기, 입력 양식이 흔히 쓴다 |

- SVG 는 `img` 로 보인다(`blob:` 주소). 그림 자리에서는 SVG 안 스크립트와 바깥 주소 불러오기가 돌지 않는다.

### 4.5 옆 창 문서를 가리키는 값 (CR-181 과 맞춘 것)

서버에 문서 행을 두지 않는다. 보기만 하는 데는 필요 없다. 판이 필요한 CR-181 이 문서 행과 판을 만든다.

```ts
type PreviewTarget =
  | { kind: "file"; sessionId: string; name: string; modifiedAt?: string; version?: number }
  | { kind: "block"; turnId: string; index: number; lang: "html" | "svg"; source: string; version?: number };
```

- 파일은 (세션, 파일 이름), 코드 블록은 (답 번호, 그 답 안 코드 블록 순번 0부터)로 가리킨다.
- 소스는 CR-177 틀 약속대로 `packages/chat-widget-embed/src/features/preview/` 폴더에 두고 `src/features/index.ts` 에 한 줄로 등록한다. 위젯 본체와 틀은 고치지 않는다.
- 이 폴더가 내보내는 함수(CR-181 이 import 한다). 붙이는 앱에는 내보내지 않는다.

| 순번 | 함수 | 뜻 |
|---|---|---|
| 1 | `openPreview(target)` | 옆 창에 연다. 열려 있으면 내용만 바꾼다 |
| 2 | `currentPreview()` | 열린 대상, 없으면 null |
| 3 | `onPreviewChange(listener)` | 열기, 바꾸기, 닫기를 알린다. 떼는 함수를 돌려준다 |
| 4 | `refreshPreview()` | 열린 대상을 다시 불러온다 |
| 5 | `addPreviewTool({ id, order, render: (target) => HTMLElement \| null })` | 머리줄 닫기 앞 단추 묶음. 대상마다 다시 그린다. CR-181 판 고르기 |
| 6 | `setPreviewFooter((target, foot) => void)` | 옆 창 아래 줄을 채운다. CR-181 고치기 입력칸 |
| 7 | `setPreviewBusy(busy)` | 옆 창 본문에 덮개를 씌우고 걷는다. CR-181 이 고치는 동안 |

- target 에 `version` 이 있으면 미리보기 두 API 에 `version` 인자를 싣는다. 서버가 그 인자를 받는 것은 CR-181 이 더한다. 코드 블록은 CR-181 이 `source` 를 그 판 본문으로 바꿔 넘긴다.
- 2026-11-13 CR-181 질의와 요청에 답한 내용이다.
- 화면 문구는 `defineStrings` 로 한국어와 영어를 함께 둔다.
- 쪽 그림과 원본은 글이 아니라 파일로 받아야 한다. 틀의 서버 호출(`ctx.api.request`)은 JSON 만 돌려주므로, 위젯 토큰을 실어 파일을 받는 자리를 CR-177 에 요청한다(`ctx.api.requestBlob(method, path)`).
