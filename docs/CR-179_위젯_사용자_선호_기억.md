### 1.2 넣지 않는 것

- 관리자가 남의 기억을 보는 화면. 기존 관리 API(`/api/v1/memories`)는 그대로 둔다.
- 응답 아래 「기억했습니다」 알림. 기억은 응답이 끝난 뒤 따로 뽑아 그 자리에서 알 수 없다. 기억 목록에서 본다.
- 프로젝트별 지시문. CR-178 이 한다(5.4 순서 참고).
- 글자 크기는 지금처럼 그 브라우저에 기억한다(BIZ-152). 서버로 옮기지 않는다.

## 4. 서버

### 4.1 내 선호와 마지막에 선택한 값 [PRD-440, PRD-442]

`widget_user_preferences`(5.1)에 한 사람 한 행으로 둔다. 처음 조회할 때 행이 없으면 빈 값과 자동 기억 켬으로 돌려준다(행은 처음 저장할 때 만든다).

- 내 선호 글은 `widget.preferences-max-chars` 자까지. 넘으면 400 `preferences_too_long`. `last_model` 이 100자를 넘으면 400 `model_invalid`.
- 마지막에 선택한 모델과 깊게 생각하기는 위젯이 사용자가 바꿀 때마다 저장한다. 모델은 허용 목록 검사를 저장할 때 하지 않는다(연결마다 목록이 달라서). 쓸 때 BIZ-185 로 거른다.

### 4.2 자동 기억 뽑기 [PRD-441]

기존 MemoryAutoExtractService 를 이 규칙으로 고친다. 새 서비스를 따로 두지 않는다.

- 언제: 위젯 대화(일반, 실시간 둘 다)의 응답이 정상으로 끝나 저장된 뒤, 응답과 따로(가상 스레드) 돈다. 실패해도 응답과 대화에는 영향이 없다. 응답 중지나 실패로 끝난 답에서는 뽑지 않는다.
- 조건: BIZ-180 의 주인이 있고, 테넌트 스위치와 그 사람의 자동 기억이 켜져 있을 때. 기존 10메시지 조건과 1분 간격은 없앤다. 질문마다 돈다.
- 입력: 이번 질문 글(첨부 제외)과 그 사람의 지금 기억 목록. 응답은 넣지 않는다(BIZ-182).
- 모델: `widget.memory-model`, 비어 있으면 그 대화 연결의 기본 모델. 연결은 그 대화 요청의 `connection_id`, 없으면 후속 질문과 같은 기본 CLI 연결. 생각은 끈다. 도구 목록을 전달하지 않는다. 시간 한도 `widget.memory-timeout-ms`. 별도 세션 `{session_id}:memory:{turn_id}` 로 부르고 대화 기록에 넣지 않는다. 사용량은 평소처럼 기록한다. 후속 질문(CR-175 3.6)과 같은 방식이다.
- 프롬프트 틀 `widget.memory-extract`(5.3)에 넣고 JSON `{"add": ["..."], "remove": ["<기억 id>"]}` 를 받는다. `remove` 는 사용자가 이번 질문에서 뒤집은 기억(예: 전에 짧게 달라 했다가 이번에 자세히 달라 함)이다. JSON 이 아니면 아무것도 바꾸지 않는다.
- 저장: `conversation_memories` 에 `memory_type = USER_PROFILE`, `scope = PRIVATE`, `user_id = user_ref`, `session_id` 는 비운다(대화를 지워도 기억은 남는다). 글이 최대 글자 수를 넘으면 자른다. 같은 글이 이미 있으면 넣지 않는다. 넣은 뒤 BIZ-183 개수를 넘으면 오래된 것부터 지운다.
- 코드에 고정된 모델 `anthropic/claude-haiku-4-5` 와 기존 뽑기 지시문(작업 사실 포함)은 없앤다. 기존 틀 `session.memory_extract.system` 은 지우지 않고 쓰지 않는다.

### 4.3 대화에 넣기 [PRD-440, PRD-441]

- 대화 요청을 만들 때 CR-178 이 만든 위젯 대화 칸(대화 주인, 질문 원문)에 위젯 토큰 요청인지를 한 칸 더 싣는다. 기억 주인은 위젯 토큰이고 user_ref 가 있을 때만 그 대화 주인이다(BIZ-180). 로그인 사용자는 대화 주인은 있어도 기억 주인은 없다. 사용자 칸(ChatController 의 빈 값 자리)은 사용량 기록에도 쓰이므로 건드리지 않는다.
- 덩어리는 신규 WidgetPreferenceService 가 만든다. 주인이 있고 테넌트 스위치가 켜져 있으면, 프롬프트 틀 `widget.user-memory`(5.3)로 내 선호 글과 자동 기억 목록(켜져 있을 때, 오래된 것부터)을 한 덩어리로 만든다. 둘 다 비면 넣지 않는다. 개수는 BIZ-183 이 막으므로 「최근 3개만」 같은 제한을 두지 않는다. 읽다가 실패하면 넣지 않고 대화는 그대로 간다.
- 기억 주인이 없는 요청(워크플로우, API 키, 관리 화면, 로그인 사용자)은 지금과 같다. MemoryService 와 기존 LONG_TERM, SYSTEM_RULES, USER_PROFILE, 팀, 글로벌 층은 손대지 않는다. 위젯 요청은 사용자 칸이 비어 기존 USER_PROFILE 층(최근 3개)이 돌지 않으므로 같은 기억이 두 번 들어가지 않는다.
- 이 덩어리는 질문마다 붙이는 지시(CR-178 표시, 2026-11-13 계약)로 마지막 질문 바로 앞에 넣는다. 화면 대화(실시간)는 맥락 조립을 거치지 않으므로 오케스트레이터의 일반, 실시간 두 경로가 모두 같은 자리에서 넣는다. 기억 덩어리를 먼저 넣고 CR-178 프로젝트 지시문이 뒤이어 들어가 질문에 더 가깝게 놓인다.
- Claude API 연결은 지금처럼 시스템 지시 끝에 붙는다.
- Claude CLI 연결은 2절 8, 9 때문에 시스템 지시가 첫 질문에만 가거나 통째로 빠지지만, 표시가 붙은 지시는 `system_prompt_override` 가 있어도 작업자가 그 질문 앞에 붙인다(CR-178 이 실행기 쪽을 고친다).
- 그래서 두 연결 모두 바꾼 선호와 기억이 다음 질문부터 들어간다(BIZ-181).
- 이 덩어리는 대화 기록(Redis, conversation_messages)에 넣지 않는다. 다음 질문에 다시 만든다.

### 4.4 위젯 설정 조회는 바꾸지 않는다

위젯 기능은 뜰 때 6절 1(내 선호 조회)을 한 번 부른다. 성공하면 메뉴를 보이고 마지막에 선택한 값을 적용한다. 403 `memory_unavailable`, 409 `memory_disabled` 면 메뉴를 숨긴다. 그래서 CR-175 위젯 설정 조회(`widget-settings`)에 칸을 더하지 않는다.

| 2 | PUT `/api/v1/chat/me/preferences` | 본문에 온 칸만 바꾼다(`instructions`, `memory_enabled`, `last_model`, `last_thinking`). 돌려주는 모양은 1 과 같다. 글자 수 넘으면 400 `preferences_too_long` |

- API 가이드(`docs/guides/aimbase-api-guide.md`)에 minor 로 올린다(v3.35.0 § 32). 런타임 설정과 프롬프트 틀이 늘어 운용 가이드(`docs/guides/aimbase-ops-guide.md`)도 minor 로 올린다(v3.32.0 § 2-18). 위젯 붙이기 안내(`docs/guides/embed-chat-widget.md`)에 기억 메뉴와 BIZ-185 를 적는다.

## 7. 위젯

화면 구조는 T3-3, 상호작용은 T3-4 「위젯 사용자 선호 기억」 절(컨셉 1, 2026-11-13 승인). CR-177 틀 사용법([guides/chat-widget-frame.md](guides/chat-widget-frame.md))대로 `src/features/memory.ts` 에 만들고 자리에 등록만 한다. 위젯 본체와 틀은 고치지 않는다. 문구는 기능 파일의 문구표(ko, en)에 둔다.

| 순번 | 기능 | 동작 |
|---|---|---|
| 1 | 메뉴 | 더 보기 group 0, order 40(대화 내보내기 10, 공유 링크 만들기 20, 이 화면 캡처 30 다음). 누르면 무언가 하는 항목은 group 0 이라는 틀 규칙(chat-widget-frame.md)을 따른다. 뜰 때 내 선호 조회(6절 1)가 성공했을 때만 보인다. 누르면 위젯 판 전체를 덮는 창(`ctx.ui.layer`)이 열린다 |
| 2 | 내 선호 | 여러 줄 글 칸과 남은 글자 수, 저장 단추. 저장하면 「저장했습니다. 다음 질문부터 적용됩니다」 |
| 3 | 자동 기억 켜고 끄기 | 바꾸면 바로 저장한다 |
| 4 | 기억 목록 | 최근 것부터 글과 생긴 날짜, 하나씩 삭제. 「모두 삭제」는 한 번 더 묻는다. 비어 있으면 안내 한 줄. 자동 기억이 꺼져 있으면 목록 위 회색 줄 |
| 5 | 모델과 깊게 생각하기 | 사용자가 바꾸면(틀 알림 `modelChange`) PUT 으로 저장한다. 실패해도 대화는 그대로다. 뜰 때(내 선호와 위젯 설정을 둘 다 받은 뒤)와 새 대화에서 마지막에 선택한 값을 `ctx.chat.selectModel`, `setThinking` 으로 적용한다. 목록 밖이면 위젯 본체 초기값 그대로 둔다(BIZ-185) |

- 5 의 알림과 선택 자리는 CR-177 이 받아 틀 사용법 1.1 3.7 에 정했다(dev 51bcdd5).

## 8. 레포 간 요청

- bp-wes: CS 문의 화면의 위젯 토큰은 bp-wes 서버가 받아 화면에 전달한다. 토큰을 받을 때 `origin`, `scopes`, `ttl_seconds` 만 보내고 `user_ref` 를 보내지 않는다(bp-wes origin/dev b3d5e82f, AimbaseClient.java:286-289). 그래서 지금 CS 상담원 전원이 같은 사람(`widget`, 2절 7)이다. 로그인한 백오피스 사용자 id 를 `user_ref` 로 실어 달라고 요청한다. 그 전까지 CS 화면에서는 BIZ-180 에 따라 기억 메뉴가 보이지 않는다. 같은 기준을 쓰는 CR-178 대화 목록, CR-175 응답 평가도 이 요청에 걸린다.
- 백오피스2: 없음. 토큰은 bp-wes 가 받고 화면은 그대로 위젯에 전달한다.
