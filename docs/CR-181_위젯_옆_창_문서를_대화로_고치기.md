## 3. 서버

### 3.1 문서와 판 [PRD-481, BIZ-200]

CR-180 은 서버에 문서 행을 두지 않고 옆 창 문서를 아래 값으로 가리킨다(2026-11-13 CR-180 회신). 이 CR 이 그 값으로 문서 행과 판 행을 만든다. 문서 행은 그 문서를 처음 고칠 때 만든다.

| 종류 | 무엇 | CR-180 이 가리키는 값 | 판 본문을 두는 곳 |
|---|---|---|---|
| BLOCK | 답 안의 코드 블록(html, svg) | (turn_id, 그 답 안 코드 블록 순번 0부터) | 판 행의 본문 칸 |
| FILE | 세션 작업 폴더 `out/` 의 파일(pptx, pdf, docx, xlsx, csv, html, svg, md, txt, json, 그림) | (session_id, 파일 이름) | 파일 저장소(StorageService, 첨부와 같은 저장소). 판 행은 저장 경로와 크기, 해시 |

- 1판은 처음 고치기 직전의 원본이다. 화면에 처음 보인 것과 같다. BLOCK 은 위젯이 보낸 블록 원문, FILE 은 그때 `out/<이름>` 의 내용이다. 고친 결과가 다음 판이다. 앞 판은 지우지 않는다(BIZ-200).
- 문서 행은 세션 안에서 FILE 은 이름, BLOCK 은 (turn_id, 순번)마다 하나다.
- 판 번호는 문서마다 1부터 1씩 늘린다. 보고 있던 판(바탕 판)이 마지막 판이 아니어도 고친 결과는 마지막 판 다음 번호다. 판 행에 바탕 판 번호를 남긴다.
- FILE 판을 저장소에 두는 이유는 `out/` 이 24시간 뒤 지워지고, 같은 이름으로 덮어쓰면 앞 판이 사라지기 때문이다.

### 3.2 고치기 요청 [PRD-480, BIZ-201]

대화 요청에 `document_edit`(선택)를 싣는다.

```json
{ "session_id": "...", "messages": [...],
  "document_edit": { "target": { "kind": "file", "name": "report.pptx" }, "base_version": 2 } }
{ "session_id": "...", "messages": [...],
  "document_edit": { "target": { "kind": "block", "turn_id": "...", "index": 0, "lang": "html", "source": "<!doctype html>..." } } }
{ "session_id": "...", "messages": [...],
  "document_edit": { "target": { "kind": "file", "name": "notes.md" }, "base_version": 3, "selection": { "text": "둘째 문단" } } }
```

- `target` 은 CR-180 의 옆 창 대상과 같은 모양이다. BLOCK 의 `source` 는 그 문서를 처음 고칠 때(문서 행이 없을 때)만 1판으로 쓰고, 문서 행이 있으면 무시한다.
- `base_version` 은 옆 창에 보이는 판이다. 없으면 마지막 판이다(처음 고칠 때는 1판).
- `selection` 은 옆 창에서 선택한 글이다(PRD-483). 글이 비었으면 없는 것으로 본다. 위젯은 글로 보이는 문서에서만 싣는다(BIZ-205). 서버는 문서 종류로 막지 않는다. 선택한 글은 고칠 범위를 알려 주는 자료일 뿐이고 판을 만드는 방법은 같다.

| 순번 | 검사 | 결과 |
|---|---|---|
| 1 | `session_id` 가 없음, `target` 이 없거나 모양이 틀림 | 400 `document_edit_invalid:no_session`, 400 `document_edit_invalid:target` |
| 2 | BLOCK 의 turn_id 가 이 세션 답이 아님, 또는 처음 고치는 BLOCK 인데 `source` 가 없음(현재 테넌트 DB 에서만 찾는다) | 404 `document_not_found`, 400 `document_edit_invalid:source` |
| 3 | 처음 고치는 FILE 인데 `out/<이름>` 이 없음(24시간 정리로 지워짐) | 410 `document_source_gone` |
| 4 | 바탕 판이 없거나 지운 판 | 400 `document_edit_invalid:base_version` |
| 5 | FILE 문서인데 원본(`out/.source/<이름>.json`)이 없고 이 연결이 실행기 연결이 아님. 또는 원본은 있는데 파일 만들기 설정(`chat.file-create.enabled`)이 꺼짐 | 400 `document_edit_unsupported` |
| 6 | 그 세션에 답이 도는 중 | 409 `session_busy`(CR-175 와 같다) |
| 7 | 통과 | 아래대로 이번 요청에만 고치기 지시를 싣고 평소대로 답한다 |

**고치기 지시.** 프롬프트 틀(테넌트 `prompt_templates`)에서 읽어 이번 요청의 마지막 질문 앞에 붙여 모델에 보낸다. 시스템 지시가 아니라 질문에 붙이는 것은 실행기 연결이 둘째 질문부터 시스템 지시를 다시 받지 않기 때문이다. 대화 기록에는 붙이기 전 질문만 저장한다. 고친 결과(답)는 기록에 남으므로 다음 질문은 그 답을 보고 이어 간다.

| 종류 | 틀 키 | 지시 요지 | 판을 만드는 방법 |
|---|---|---|---|
| BLOCK | `widget.document-edit.block` | 문서 이름, 언어, 바탕 판 본문을 주고, 요청대로 고친 문서 전체를 같은 언어의 코드 블록 하나로 답하게 한다. 바뀐 점은 블록 앞에 짧게 쓴다 | 답이 끝나면 서버가 답에서 그 언어의 마지막 코드 블록을 꺼내 다음 판으로 저장 |
| FILE, 원본 있음 | `widget.document-edit.file-source` | CR-182 `create_file` 로 만든 파일이다. 바탕 판의 원본(도구 입력 JSON)을 주고, 요청대로 고친 입력으로 `create_file` 을 같은 이름, `overwrite: true` 로 다시 부르게 한다. 모든 연결이 가능하다. 요청이 `file_create` 를 싣지 않아도 이 답에는 `create_file` 을 준다 | 답 전에 `out/<이름>` 과 `out/.source/<이름>.json` 을 바탕 판으로 맞춰 둔다(지워졌거나 다른 판이면 저장소에서 복원). 답이 끝나면 파일 해시를 비교해 바뀌었으면 파일과 원본을 저장소에 다음 판으로 저장 |
| FILE, 원본 없음 | `widget.document-edit.file` | 실행기가 직접 만든 파일이다. 고칠 파일 경로 `out/<이름>` 을 주고, 그 파일을 같은 이름과 형식으로 고쳐 저장하게 한다. 실행기 연결만 가능하다 | 위와 같다(원본 파일만 없다) |
| 선택한 부분 | `widget.document-edit.selection` | 선택한 글을 주고, 그 부분만 요청대로 고치고 나머지는 그대로 두게 한다. 채운 글을 위 셋의 `{{selection}}` 자리(질문 바로 앞)에 넣는다. 선택한 부분이 없으면 그 자리는 빈 글이다 | 위 셋과 같다 |

- 바뀐 것이 없으면(코드 블록이 없음, 파일 해시가 같음) 판을 만들지 않는다(BIZ-201).
- 답이 중지되거나 오류로 끝나면 판을 만들지 않는다. FILE 은 `out/<이름>` 과 원본을 마지막 판 내용으로 되돌린다.
- 다른 파일은 요청이 없으면 만들지 않게 지시한다. 그래도 다른 파일이 생기면 CR-132, CR-180 대로 산출물로만 보인다.

### 3.3 문서 이벤트 [PRD-480]

고치기 요청이면 끝 이벤트(done) 바로 앞에 스트림 이벤트 `document` 를 보낸다. 위젯 본체가 모르는 이벤트라 틀의 `streamEvent` 알림으로 받는다(틀 변경 없음).

| 칸 | 값 |
|---|---|
| `document.document_id` | 고친 문서 |
| `document.status` | `UPDATED`, `UNCHANGED`, `FAILED` |
| `document.version` | `UPDATED` 일 때 만든 판 번호 |

- 끝 이벤트(done)에도 같은 `document` 칸을 싣는다. 틀은 done 의 모르는 칸을 `AnswerView.extra` 로 넘기므로 위젯은 답 아래 문서 카드를 이 값으로 그린다. 스트림이 아닌 응답은 본문에 `document` 칸이 있다.

### 3.4 판 조회 [PRD-481]

| 순번 | API | 뜻 |
|---|---|---|
| 1 | `GET /api/v1/chat/documents?session_id=` | 세션의 문서와 판 목록 `[{document_id, kind, name, turn_id, index, lang, latest_version, versions: [{version, base_version, made_by, turn_id, size, created_at}]}]`. 지운 판은 빼고 준다. 지난 대화를 열었을 때(CR-178) 위젯이 답과 판을 잇는 데 쓴다 |
| 2 | `GET /api/v1/chat/documents/{documentId}/versions/{version}` | BLOCK 은 `{lang, content}`, FILE 은 파일 내려받기 |
| 3 | CR-180 `GET /api/v1/chat/artifacts/preview`, `.../preview/page`, `.../download` 에 `version` 인자 추가 | 있으면 판 저장소의 파일을 쓴다. 없으면 지금 `out/` 파일(CR-180 동작 그대로). 변환 캐시 열쇠에 판 해시를 넣는다. 글로 보이는 파일(HTML, MARKDOWN, TEXT)은 옆 창이 내려받기로 본문을 읽으므로 내려받기에도 같은 인자를 둔다 |

- 권한은 대화와 같은 위젯 토큰 `chat:stream` 이다. 문서는 현재 테넌트 DB 에서만 찾는다.

### 3.5 되감기와 판 [PRD-482, BIZ-202]

- CR-175 되감기가 메시지에 지운 표시를 할 때, 지운 답(turn_id)이 만든 판에도 같은 시각으로 지운 표시를 한다. 같은 트랜잭션이다.
- 마지막 판은 남은 판 중 가장 큰 번호다. 1판은 고치기로 만든 판이 아니어서 되감기로 지우지 않는다.
- 다음 판 번호는 남은 판 중 가장 큰 번호 다음이므로, 맨 뒤에서 지운 판 번호는 다음 고치기가 다시 쓴다(CR-175 메시지 순번과 같다). 판 2 를 만든 답을 다시 생성하면 새 결과가 다시 판 2 가 된다. 판 2 뒤에 되돌려 만든 판 3 이 있으면 새 결과는 판 4 다.
- FILE 은 되감은 뒤 `out/<이름>` 과 원본을 남은 마지막 판 내용으로 되돌린다.

### 3.6 되돌리기 [PRD-484, BIZ-204]

`POST /api/v1/chat/documents/{documentId}/versions/{version}/restore`

- 그 판 내용을 그대로 마지막 판 다음 번호로 복사한다. 판 행은 `made_by = RESTORE`, `base_version` = 되돌린 판, `turn_id` 는 비운다. 대화를 거치지 않으므로 답과 질문은 생기지 않는다.
- 되돌려 만든 판은 되감기로 지우지 않는다. 답이 만든 판이 아니기 때문이다(BIZ-204).
- 마지막 판과 내용이 같으면 판을 만들지 않고 `UNCHANGED` 다(BIZ-201).
- FILE 은 저장소의 그 판 파일과 원본을 새 판으로 함께 쓰고, `out/<이름>` 과 원본을 새 판 내용으로 맞춘다.
- 응답 본문은 `document` 이벤트와 같은 `{document_id, status, version}` 이다.

| 순번 | 검사 | 결과 |
|---|---|---|
| 1 | 문서나 판이 없음, 지운 판, 다른 테넌트 | 404 `document_not_found` |
| 2 | 다른 사람 세션의 문서(CR-046 세션 삭제와 같은 본인 확인) | 403 `document_forbidden` |
| 3 | 그 세션에 답이 도는 중 | 409 `session_busy` |

## 4. 위젯

### 4.1 화면 구성

정본은 T3-3 「위젯 옆 창 문서 고치기」 절이다(화면 컨셉, 2026-11-13 승인). 자리는 CR-177 틀 안내서(`docs/guides/chat-widget-frame.md`) 3.3 옆 창과 CR-180 옆 창 미리보기를 따른다. 위젯 소스는 `packages/chat-widget-embed/src/features/document-edit/` 에만 두고 `src/features/index.ts` 에 한 줄로 등록한다.

| 순번 | 자리 | 들어가는 것 |
|---|---|---|
| 1 | 옆 창 머리줄의 덧붙일 자리(CR-180 `addPreviewTool`) | 판 선택(「이전」 단추, 「2 / 3」, 「다음」 단추). 판이 둘 이상일 때만 보인다 |
| 2 | 옆 창 아래 줄(CR-180 `setPreviewFooter`) | 위에서부터 앞 판 안내 줄(마지막 판이 아닐 때 「버전 1 을 보고 있습니다」, 「이 버전으로 되돌리기」, 「마지막 버전 보기」), 선택한 부분 칩(「선택한 부분: "…"」, 「취소」 단추), 고치기 입력칸(「이 문서를 어떻게 고칠까요?」)과 「전송」 단추. 고칠 수 있는 문서일 때만 보인다 |
| 3 | 옆 창 본문(CR-180 `setPreviewBusy`) | 고치는 동안, 되돌리는 동안 「문서를 고치는 중입니다」 덮개와 판 선택 잠금 |
| 4 | 대화 칸 | 고치기로 보낸 글은 대화 칸에 내 질문으로 보이고 답도 대화 칸에 온다. 답 아래에 그 판의 문서 카드(CR-180 카드에 판 번호), 바뀐 것이 없으면 「문서가 바뀌지 않았습니다」, 실패면 「문서를 고치지 못했습니다」 |

### 4.2 동작

| 순번 | 기능 | 동작 |
|---|---|---|
| 1 | 고치기 입력칸 | 옆 창에 고칠 수 있는 문서(BLOCK, 원본 있는 파일, 실행기 연결의 파일)가 열리면 아래 줄에 보인다. 답이 도는 동안은 보내기를 막는다. Enter 보내기, Shift+Enter 줄바꿈 |
| 2 | 보내기 | 틀의 `ctx.chat.send(text, { body: { document_edit } })` 로 보낸다. `document_edit = {target = currentPreview(), base_version = 옆 창에 보이는 판}`. 아래 입력칸에서 보낸 글만 고치기이고, 대화 칸 입력칸에서 보낸 글은 일반 질문이다 |
| 3 | 결과 | `UPDATED` 면 `openPreview(target + version)` 으로 새 판을 연다. 마지막 판 파일은 `version` 없이 연다(`out/` 파일이 마지막 판이라 같은 변환을 두 번 하지 않는다). `UNCHANGED` 면 판은 그대로이고 답 아래 안내. `FAILED` 면 「문서를 고치지 못했습니다」 |
| 4 | 다시 생성, 질문 수정 | 그 답을 보낼 때의 `document_edit` 를 틀이 그대로 다시 싣는다(틀 안내서 3.7 요청 본문 덧붙임) |
| 5 | 판 선택 | 판 목록(3.4)을 읽어 앞 판, 다음 판으로 연다. 보는 판이 다음 고치기의 바탕 판이다. BLOCK 의 다음 판은 고친 답 안에도 코드 블록으로 있으므로, 그 블록을 열면 원래 문서의 그 판으로 연다 |
| 6 | 옆 창 함수 | CR-180 의 `openPreview(target)`, `currentPreview()`, `onPreviewChange(listener)`, `addPreviewTool`, `setPreviewFooter`, `setPreviewBusy` 를 쓴다. target 의 `version` 칸으로 판을 연다. 선택한 글은 CR-180 에 요청한 `onPreviewSelection(listener)` 로 받는다(7절) |
| 7 | 선택한 부분 고치기 | 글로 보이는 문서(BIZ-205)에서 글을 선택하면 아래 줄에 「선택한 부분: "…"」 칩(한 줄을 넘으면 말줄임)이 붙고 입력칸 안내가 「선택한 부분을 어떻게 고칠까요?」로 바뀐다. 입력칸을 누르면 문서의 선택 표시는 사라져도 칩은 남는다. 다른 글을 선택하면 칩이 바뀌고, 「취소」 단추, 보내기, 다른 문서나 다른 판을 열면 칩이 없어진다. 보낼 때 `document_edit.selection = {text}` 를 싣는다 |
| 8 | 되돌리기 | 마지막 판이 아닌 판을 보고 있으면 아래 줄 맨 위에 앞 판 안내 줄이 보인다. 「이 버전으로 되돌리기」는 3.6 API 를 부르고, `UPDATED` 면 새 판을 연다. `UNCHANGED` 면 「마지막 버전과 같습니다」를 잠깐 보이고 마지막 판을 연다. 답이 도는 동안은 막는다. 「마지막 버전 보기」는 마지막 판을 연다 |

## 11. 구현 기록

| 순번 | 정한 것 | 까닭 |
|---|---|---|
| 1 | 화면 이름 「이전」, 「다음」, 「취소」, 「전송」 | 승인한 컨셉의 「앞 버전」, 「다음 버전」, 지우기, 보내기는 위젯 본체에 없는 이름이라 용어 검사에 걸렸다. 본체의 답 버전 이동, 취소, 전송과 같은 이름으로 맞췄다. T3-3 도 고쳤다 |
| 2 | 판 번호는 남은 판의 번호를 그대로 보인다 | 되감기로 가운데 판이 지워져도 답 아래 카드의 「버전 n」 과 판 선택의 「n / m」 이 같은 번호를 가리키게 한다 |

| 4 | 고친 답 안의 코드 블록을 열면 원래 문서의 그 판으로 연다 | 그 답이 만든 판(made_by CHAT_EDIT, turn_id 같음)이 있고 글이 같을 때만 옮긴다. 옮기지 않으면 고친 블록이 새 문서가 된다(4.2 5번) |

| 6 | 판 목록은 옆 창 대상이 바뀔 때마다, 답이 시작하고 끝날 때마다 새로 받는다 | 되감기와 다시 생성이 판을 지우거나 새로 만든다 |
| 7 | 원본 있는 파일 고치기는 요청에 `file_create` 가 없어도 그 답에 `create_file` 을 준다. 파일 만들기 설정이 꺼져 있으면 400 `document_edit_unsupported` | 위젯은 `file_create` 를 싣지 않고(CR-182 위젯분 전), CR-182 도구 거르기는 요청의 `file_create` 만 본다. 설정이 꺼진 채 실행기 연결이 이진 파일을 직접 고치게 두면 원본이 고친 파일과 어긋나 다음 고치기가 옛 내용으로 돌아간다 |
