## 3. 설계

### 3.1 API

`PUT /api/v1/platform/subscriptions/{tenantId}` 가 `apiRpmLimit` 을 받는다.

| 순번 | 보낸 값 | 결과 |
|---|---|---|
| 1 | 보내지 않음 | 그 값은 그대로 둔다 |
| 2 | 0 이상의 정수 | 저장한다. 0 은 무제한이다 |
| 3 | 음수, 소수, 정수 범위 밖 | 400, 본문 `error` 는 `apiRpmLimit must be an integer of 0 or greater.`. 같이 보낸 다른 값도 저장하지 않는다 |
| 4 | 숫자가 아닌 값 | 400. 요청 본문 해석 오류로 거절한다 |

요청 칸의 자료형은 정수가 아니라 십진수로 받는다. 정수로 받으면 요청 본문 해석이 소수의 뒷자리를 버려 `1.5` 를 1 로 저장한다(Jackson `ACCEPT_FLOAT_AS_INT` 기본값). 시험에서 확인한다.

상한은 두지 않는다. 지금 쓰는 곳이 없다.

### 3.2 적용

한도 판정 코드는 고치지 않는다. 2.3 대로 다음 요청부터 새 값으로 판정한다. 그 분에 이미 센 수는 그대로다. 지금 수보다 낮게 바꾸면 그 분이 끝날 때까지 거절될 수 있다.

### 3.3 화면

화면은 「구독 관리」 하나다.

표의 칸:

| 순번 | 칸 | 서버 값 | 표시 |
|---|---|---|---|
| 1 | 테넌트 | `tenantId` | 그대로 |
| 2 | 플랜 | `plan` | 그대로 |
| 3 | 월간 토큰 한도 | `llmMonthlyTokenQuota` | 숫자. 「사용: N%」 줄은 뺀다 |
| 4 | 분당 요청 한도 | `apiRpmLimit` | 숫자. 0 은 「무제한」. 「일일 요청 한도」 칸은 없앤다 |
| 5 | 최대 연결 | `maxConnections` | 그대로 |

| 7 | 액션 | 편집 단추 | 그대로 |

편집 창의 칸은 「월간 토큰 한도」 「분당 요청 한도」 「최대 연결 수」 셋이다. 세 칸 모두 0 이상의 정수만 받는다.

| 순번 | 경우 | 동작 |
|---|---|---|
| 1 | 빈 칸, 음수, 소수 | 칸 아래 문구를 표시하고 저장 단추를 막는다 |

| 4 | 저장 실패 | 창을 닫지 않고 서버 문구를 표시한다 |

빈 칸을 막는 이유: 빈 「분당 요청 한도」가 0 으로 저장되면 무제한이 되고, 빈 「월간 토큰 한도」가 0 으로 저장되면 그 테넌트의 LLM 호출이 거절된다(`OrchestratorEngine.java:196`, `:559`).

## 4. 요청서와 다른 것

11-04 06:43 사용자가 세 건 모두 1 을 골랐다. 화면 컨셉은 칸 목록과 문구로 정하고 목업 없이 진행한다.

### 결정 1. 분당 요청 한도 0 의 처리

요청서는 1 보다 작은 값을 쓸 수 없는 값으로 보고 거절하라고 했다. 0 은 「무제한」으로 뜻이 정해진 값이고 59 `axopm_companyA` 가 쓰고 있다(2.2).

1. 0 은 받아 「무제한」으로 표시하고, 음수와 정수가 아닌 값을 거절한다(권장)
2. 요청서대로 1 보다 작은 값을 모두 거절한다(잃는 것: 화면과 API 로 무제한을 설정할 수 없어 DB 를 직접 고쳐야 하고, T3-1 의 「0=무제한」과 어긋난다)

### 결정 2. 운영 chaws 에는 「구독 관리」 화면이 없다

운영 compose 에 화면 컨테이너가 없고 `/home/ubuntu/aimbase` 에 화면 파일이 없으며 api 첫 주소는 404 다(11-04 06:37 확인). `deploy.sh` 의 chaws 대상도 「화면은 없다」고 적는다. 요청서 할 일 5 를 그대로 할 수 없다.

1. 운영 확인을 구독 조회 API 응답과 읽기 전용 DB 조회로 바꾼다. 화면 확인은 59 까지 한다. 운영 한도를 바꿀 때는 API 를 쓴다(권장)
2. 맥의 로컬 화면을 SSH 터널로 운영 api 에 붙여 화면으로 본다(잃는 것: 저장 단추가 운영에 살아 있어 값을 바꾸지 않는다는 약속을 화면이 막아 주지 않는다)
3. 운영에 화면을 새로 올린다(잃는 것: 운영 3PL 과 같은 서버에 공개 경로와 화면 서빙이 새로 생겨 이 건의 범위를 넘는다)

### 결정 3. 「만료일」 칸

요청서에 없는 칸이다. 화면은 `expiresAt` 을 읽고 서버 값은 `validUntil` 이라 같은 결함이다.

1. 서버 값으로 맞춘다. 표시 한 줄이고 값을 바꾸는 기능은 넣지 않는다(권장)
2. 그대로 둔다(잃는 것: 값이 있어도 늘 「-」로 보인다)
