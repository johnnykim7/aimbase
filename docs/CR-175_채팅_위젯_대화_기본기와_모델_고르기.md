## 3. 서버

### 3.1 답 단위 번호와 되감기 [PRD-369, BIZ-148]

**답 번호(turn_id).** 대화 요청 한 번이 만든 메시지들(붙이는 앱이 질문 앞에 보낸 맥락 메시지, 질문, 도구 호출과 결과, 마지막 답)에 같은 `turn_id`(UUID)를 붙여 저장한다. 서버가 요청을 받을 때 만들고, 끝 이벤트(done)로 위젯에 알린다. 답 평가와 후속 질문은 이 번호로 답을 가리킨다.

**되감기.** 대화 요청에 `rewind_from_seq`(정수, 선택)를 실으면 그 순번의 메시지부터 뒤를 지우고 이번 질문을 붙여 답한다. 그 순번은 대화 요청 한 번이 저장한 메시지 묶음의 첫 순번(끝 이벤트의 `turn_seq`)이다. 다시 생성은 같은 질문을, 질문 수정은 고친 질문을 보낸다.

| 순번 | 검사 | 결과 |
|---|---|---|
| 1 | 요청에 `session_id` 가 없음 | 400 `rewind_invalid:no_session` |
| 2 | 그 세션에 답이 도는 중 (CancellationRegistry.isActive) | 409 `session_busy`. 위젯은 답이 도는 동안 다시 생성, 수정 단추를 숨긴다 |
| 3 | 그 순번이 없거나, 지운 행이거나, 메시지 묶음의 첫 순번이 아님 | 400 `rewind_invalid:not_turn_start` |
| 4 | 그 순번보다 뒤에 압축 경계(COMPACT_BOUNDARY)가 있음 | 409 `rewind_before_compaction` |
| 5 | 통과 | 그 순번부터 뒤 메시지에 `deleted_at`, `delete_reason = REWIND` 를 찍고 Redis 대화 기록을 비운 뒤 남은 행으로 다시 채운다. Claude CLI 연결이면 그 세션 작업자를 닫는다(아래). 그다음 평소대로 답한다 |

- 지운 표시와 Redis 기록 비우기는 한 트랜잭션이다. Redis 를 비우지 못하면 지운 표시도 되돌리고 500 을 준다. 남은 행으로 다시 채우는 것은 그 뒤에 하며, 그것이 실패해도 다음 읽기가 DB 에서 다시 채운다.
- Claude CLI 연결. 실행기 작업자는 대화를 따로 기억하고 둘째 요청부터 마지막 질문만 받는다. 대화 기록만 되감으면 작업자가 지운 답을 계속 기억하므로, 되감은 뒤 그 세션 작업자를 닫는다(연결 묶음이면 묶음의 모든 CLI 연결). 다음 요청은 새 작업자가 남은 기록 전체를 받는다.
- 지운 메시지는 남는다(지운 표시). 응답 평가가 가리키는 답을 관리 화면에서 볼 수 있어야 하기 때문이다.
- 저장 순번의 근본 수정. 고유 제약을 **지우지 않은 행만** 대상으로 바꾼다(부분 고유 인덱스 `WHERE deleted_at IS NULL`). 최댓값 조회와 겹침 검사도 지우지 않은 행만 본다. 지운 순번은 새 메시지가 다시 쓴다.
- SessionStore.java:427 의 "지운 행까지 읽어 고유 충돌을 피하는" 우회는 위 수정으로 필요 없어지므로 함께 걷어낸다.
- 답 저장은 비동기에서 동기로 바꾸고, 순번을 지우지 않은 행의 최댓값 + 1 로 정해 넣는다. 되감기가 앞 요청의 저장과 엇갈리지 않게 하기 위해서다. 압축 뒤 Redis 기록 길이와 DB 순번이 어긋나 새 메시지가 조용히 버려지던 문제도 이것으로 없어진다.

**위젯의 버전 번호.** 다시 생성을 하면 위젯은 앞 답을 화면 메모리에 두고 「1/2」 처럼 넘겨 볼 수 있게 한다. 서버 대화 기록에는 마지막 버전만 이어진다. 새로고침하거나 다시 열면 마지막 버전만 보인다.

### 3.2 끝 이벤트(done) 추가 칸 [PRD-369, PRD-371]

| 칸 | 값 |
|---|---|
| turn_id | 이번 답 번호 |
| turn_seq | 이번 대화 요청이 저장한 메시지 묶음의 첫 순번(붙이는 앱의 맥락 메시지가 있으면 그 순번). 다시 생성, 질문 수정의 `rewind_from_seq` 로 쓴다 |
| model | 라우팅이 이 요청에 정한 모델 id(고른 모델 또는 연결 기본 모델). 답하는 도중 폴백으로 바뀐 모델은 반영하지 않는다 |

기존 칸(`rag_used`, `citations`, `artifacts`)은 그대로다. 위젯은 이 칸이 없는 이전 서버를 만나면 다시 생성, 질문 수정, 평가 단추를 숨긴다.

사용자가 응답 중지를 눌러도 서버는 받은 데까지 저장하고(DB 글 앞에 `[중단됨] `) done 을 보낸다. 그래서 중지한 답도 다시 생성할 수 있다.

### 3.3 응답 평가 [PRD-370, BIZ-149]

- 테이블 `message_feedback`(테넌트 DB). 5절.
- 한 사람(위젯 토큰 `user_ref`, 없으면 로그인 사용자 id)은 답 하나에 하나만 남긴다. 다시 누르면 바꾸고, 같은 것을 다시 누르면 취소다.
- 아쉬워요일 때만 이유를 고를 수 있다. 이유는 여러 개, 런타임 설정 `widget.feedback-reasons` 의 code 만 받는다. 한 줄 의견은 `widget.feedback-comment-max-chars` 까지.
- 답이 그 세션 것인지, 세션 주인이 적혀 있으면 요청한 사람과 같은지 본다. 아니면 404 `turn_not_found`. 세션 주인은 위젯 대화를 처음 저장할 때 토큰의 `user_ref` 로 적힌다.
- 되감기로 지운 답에 남긴 평가는 그대로 둔다(다시 만들게 한 이유가 되므로 남긴다).

### 3.4 모델 선택과 깊게 생각하기 [PRD-371, BIZ-150]

**연결 config 칸 추가.** `models`: `[{"id": "claude-sonnet-5-5", "label": "Sonnet 5.5"}, ...]`. 적힌 순서가 화면 순서다. 기존 `model` 은 기본 모델로 그대로 쓴다.

**허용 모델.**

| 순번 | 연결 config | 위젯 목록 | 요청 검사 |
|---|---|---|---|
| 1 | `models` 있음 | 그 목록. 기본은 `model`(목록에 없으면 목록 첫 번째) | 목록에 없는 모델이면 400 `model_not_allowed`. 요청에 `connection_id` 가 있을 때만 검사한다 |
| 2 | `models` 없음 | `model` 하나. 모델 선택 칸을 숨긴다 | 기존과 같다 |

- 요청 모델이 비었거나 `auto` 면 연결 기본 모델이다(기존 OrchestratorEngine 동작 그대로).
- 코드에 박힌 기본값을 런타임 설정 `llm.default-model` 로 옮긴다. ChatController 의 첨부 능력 판정은 `connection_id` 가 있으면 그 연결 어댑터의 능력으로, 없으면 이 설정의 모델로 정한다. ConnectionAdapterFactory 의 `DEFAULT_MODEL` 도 이 설정을 읽는다. 처음 값은 지금 값과 같게 넣어 동작이 바뀌지 않는다.

**깊게 생각하기.** 대화 요청 칸 `thinking`: `on`, `off`, 비움. 비우면 연결 config 그대로다. 다른 값은 400 `thinking_invalid`.

- 어댑터에 `supportsThinkingOverride()` 를 더한다(LLMAdapter, 기본 거짓). Anthropic API 어댑터와 Claude CLI 어댑터는 참이다.
- 어댑터에 `thinksByDefault()` 를 더한다(기본 거짓). 연결 config 에도 요청에도 생각 설정이 없을 때 그 어댑터가 생각하는지다. Claude CLI 어댑터는 참이다. CLI 2.1.197 은 생각 설정이 없으면 생각하고, 개발기 실행기 계정 폴더와 CLI 연결 config 어디에도 생각 설정이 없다(2026-11-10 확인).
- Claude CLI 연결은 생각 설정(연결 config 또는 요청 `thinking`)이 있을 때만 실행기 요청에 `thinking` 참거짓을 싣는다. 없으면 싣지 않고 CLI 기본대로 둔다. 그래서 워크플로우처럼 위젯 밖에서 부르는 동작은 바뀌지 않는다.
- 실행기 작업자는 질문을 쓰기 직전에, 받은 `thinking` 이 그 작업자에 지난번 보낸 값과 다르면 CLI 에 생각 한도 바꾸기 신호(`set_max_thinking_tokens`)를 먼저 쓴다. 끔은 한도 0, 켬은 한도를 지워 CLI 기본 생각으로 돌린다. 작업자를 다시 띄우지 않고 대화도 이어진다. 새로 띄운 작업자는 보낸 값이 없으므로 첫 질문 앞에 다시 보낸다. 신호가 실패로 돌아오면 그 턴을 실패로 끊는다.
- 실행기는 CLI 답의 생각 블록을 실시간 이벤트 `{"type":"thinking","delta":...}` 로 넘기고, 서버는 이것을 생각 조각으로 받아 위젯의 생각 접기로 보낸다. CLI 는 생각을 다 마친 뒤 한 번에 내보내므로 생각 접기도 생각이 끝난 뒤 한 번에 채워진다. 생각은 저장하지 않는다(Anthropic 연결과 같다).
- Claude CLI 연결에서 모델을 바꾸면 실행기가 그 세션 작업자를 새 모델로 다시 띄우고 앞 대화 전체를 다시 넘긴다. 새로 뜬 작업자에는 지난 질문과 답을 `<previous_conversation>` 한 덩어리로 묶어 이번 질문 앞에 붙이고 user 줄 하나로 보낸다. CLI 는 user 줄마다 따로 답하고 실행기는 첫 답에서 그 턴을 끝내므로, 지난 질문을 줄마다 쓰면 가장 오래된 질문의 답이 이번 답으로 나간다(2026-11-11 개발기에서 발견, 쉬던 작업자를 정리한 뒤 새로 뜰 때도 같다). 지난 도구 결과는 짝이 되는 도구 호출이 새 CLI 에 없어 넣지 않는다. 모델 비교와 이 묶음은 실행기(cli-runner) 쪽 수정이라 실행기를 다시 배포해야 켜진다.
- `on` 일 때 생각 예산은 연결의 기존 생각 설정(CR-031, CR-048)을 따른다. 새 수치를 만들지 않는다. Claude CLI 연결은 CLI 기본 예산이다.

### 3.5 위젯 설정 조회 [PRD-371]

위젯이 뜰 때 한 번 부른다. 모델 목록, 평가 이유, 후속 질문 사용 여부를 한 번에 받는다.

`GET /api/v1/chat/widget-settings?connection_id={id}`

```json
{
  "models": [{"id": "claude-sonnet-5-5", "label": "Sonnet 5.5"}, {"id": "claude-opus-5-5", "label": "Opus 5.5"}],
  "default_model": "claude-sonnet-5-5",
  "thinking_supported": true,
  "thinking_default": false,
  "feedback_reasons": [{"code": "WRONG_INFO", "label": "틀린 정보"}],
  "feedback_comment_max_chars": 500,
  "follow_ups_enabled": true
}
```

- 권한은 대화와 같다(`chat:stream` 또는 로그인).
- `thinking_default` 는 깊게 생각하기 단추의 처음 상태다. 연결 config 에 생각 설정이 있으면 그 값, 없으면 어댑터 기본(`thinksByDefault`)이다.
- `connection_id` 가 없으면 models 는 `llm.default-model` 하나다.
- 그 테넌트에 없는 연결이면 404 `connection_not_found`.

### 3.6 후속 질문과 대화 제목 [PRD-372, BIZ-151]

`POST /api/v1/chat/sessions/{session_id}/follow-ups` 본문 `{"turn_id": "...", "connection_id": "..."}`

```json
{"follow_ups": ["13박스 중 몇 박스가 출고됐나요?", "택배사 조회 결과도 보여 주세요", "고객 답변 초안을 다시 써 주세요"], "title": "라이프러버 13박스 누락 문의"}
```

- 답이 끝난 뒤 위젯이 부른다. 답 자체와는 따로 돈다. 실패하거나 시간을 넘기면 위젯은 칩을 보이지 않을 뿐 답에는 영향이 없다.
- 런타임 설정 `widget.follow-ups-enabled` 가 꺼져 있으면 409 `follow_ups_disabled`. 모델 답이 JSON 이 아니거나 시간 한도를 넘기면 502 `follow_ups_failed`. 답 번호가 그 세션에 없거나 남의 세션이면 404 `turn_not_found`.
- 모델은 `widget.follow-ups-model`, 비어 있으면 그 연결 기본 모델. 연결은 본문의 `connection_id`.
- 질문과 답(그 turn_id 의 마지막 답 글)을 프롬프트 틀 `widget.follow-ups`(테넌트 prompt_templates, CR-036)에 넣어 JSON 으로 받는다. 개수는 `widget.follow-ups-count`, 시간 한도는 `widget.follow-ups-timeout-ms`.
- 이 호출은 연결 기본값과 상관없이 깊게 생각하기를 끈다. 켜 두면 생각부터 해서 시간 한도를 넘긴다(2026-11-11 1차 자동 판정 IT-09-013 4).
- 도구 목록을 넘기지 않고, 대화 기록에 넣지 않는다. 사용량은 평소처럼 기록한다. 대화와 섞이지 않게 별도 세션(`{session_id}:follow-ups:{turn_id}`)으로 부르고 끝나면 닫는다.
- Claude CLI 연결은 실행기 쪽 도구를 요청마다 끌 수 없다. 프롬프트 틀이 도구를 쓰지 말라고 지시하는 것으로 막는다.
- 제목은 그 세션의 첫 답일 때만 만들고, 세션 `title_source` 가 `USER` 가 아닐 때만 저장한다(`GENERATED`). 사람이 meta 로 제목을 고치면 `USER` 로 바뀐다.

### 3.7 대화 요청 칸 정리

`POST /api/v1/chat/completions` 에 두 칸을 더한다.

| 칸 | 타입 | 뜻 |
|---|---|---|
| rewind_from_seq | 정수, 선택 | 3.1 |
| thinking | `on`, `off`, 선택 | 3.4. 다른 값은 400 `thinking_invalid`. 어댑터가 지원하지 않는데 `on` 이면 400 `thinking_not_supported` |

`model` 은 그대로이고 3.4 의 검사를 받는다.

## 4. 위젯

### 4.1 화면 구성 (목업 기준)

| 순번 | 자리 | 이번 판에 들어가는 것 |
|---|---|---|
| 1 | 머리줄 | 대화 제목, 새 대화, 크게 보기, 더 보기(글자 크기) |
| 2 | 첫 화면 | 안내 제목, 안내 한 줄, 추천 질문 최대 4개 |
| 3 | 대화 칸 | 내 질문(수정 단추, 시각), 생각과 도구 사용 접은 줄, 답(마크다운), 답 아래 줄(복사, 다시 생성과 버전 번호, 좋아요, 아쉬워요, 시각, 모델 이름), 후속 질문 칩, 맨 아래로 단추 |
| 4 | 입력칸 | 첨부(기존), 글 칸(늘어남), 모델 선택, 깊게 생각하기, 마이크(기존), 전송/응답 중지 |

### 4.2 동작

| 순번 | 기능 | 동작 |
|---|---|---|
| 1 | 응답 중지 | 답이 도는 동안 전송 단추가 응답 중지로 바뀐다. 누르거나 Esc 를 누르면 기존 abort API 를 부르고, 스트림은 끊지 않은 채 서버의 done 을 기다린다(8초 안에 오지 않으면 그때 끊는다). 받은 데까지 남기고 「응답을 중지했습니다」를 단다. done 의 `turn_seq` 를 받으므로 중지한 답도 다시 생성할 수 있다 |
| 2 | 다시 생성 | 마지막 답의 마지막 버전에만 있다. 같은 질문을 `rewind_from_seq = turn_seq` 로 보낸다. 앞 버전은 화면 메모리에 두고 버전 번호로 넘겨 본다 |
| 3 | 질문 수정 | 내 질문의 수정 단추 또는 빈 입력칸에서 위 화살표(마지막 질문). 그 자리에서 고쳐 전송하면 그 답의 `turn_seq` 로 되감는다. 마지막 질문이 아니면 수정 칸 안에 「이 질문 뒤 대화는 지워집니다」를 보이고, 전송을 누르는 것을 확인으로 본다(확인 창을 따로 두지 않는다) |
| 4 | 평가 | 좋아요는 바로 저장. 아쉬워요는 단추를 켜고 「어떤 점이 아쉬웠나요?」 이유 칩(여러 개)과 한 줄 의견 칸을 펼친다. 「전송」으로 저장하고 「의견을 보냈습니다」. 의견이 최대 글자 수를 넘으면 전송을 막고 칸 아래 「N자까지 쓸 수 있습니다」. 같은 단추를 다시 누르면 취소. 저장에 실패하면 단추를 원래대로 두고 「평가를 저장하지 못했습니다」 |
| 5 | 복사 | 답 전체를 마크다운 원문으로 클립보드에 넣고 「복사했습니다」를 잠깐 보인다 |
| 6 | 새 대화 | 답이 돌면 먼저 멈춘다. 새 session_id 로 화면을 비운다. 앞 대화는 서버에 남는다. 붙이는 앱에 `onNewConversation({previousSessionId, sessionId})` 를 알린다 |
| 7 | 추천 질문 | 첫 화면 칩을 누르면 그 글로 바로 보낸다 |
| 8 | 후속 질문 | 답이 끝나면 3.6 을 불러 칩으로 보인다. 누르면 바로 보낸다. 다음 질문을 보내면 사라진다. 제목을 받으면 머리줄 제목을 바꾼다. 실패하면 아무것도 보이지 않는다 |
| 9 | 입력칸 | 글 따라 최대 높이까지 늘어난다. Enter 보내기, Shift+Enter 줄바꿈, 한글 조합 중 Enter 는 보내지 않는다 |
| 10 | 스크롤 | 맨 아래 근처에 있을 때만 새 글을 따라 내려간다. 위로 올려 읽는 중이면 그대로 두고 「맨 아래로」 단추를 띄운다 |
| 11 | 생각과 도구 | 생각은 「생각 중」 접은 줄, 끝나면 「n초 동안 생각했습니다」. 도구 사용은 「도구를 사용하는 중입니다」, 끝나면 「도구를 n번 사용했습니다」 접은 줄. 눌러 펼치면 도구 이름, 입력 앞부분, 결과 앞부분 |
| 12 | 시각 | 질문과 답에 보낸 시각. 보는 사람 시간대로, 오늘이면 시:분, 아니면 월/일 시:분 |
| 13 | 모델 선택 | 3.5 목록이 둘 이상일 때만 보인다. 고른 모델은 그 대화 동안 유지한다. 답 아래에 실제 답한 모델 이름(done.model 을 목록 label 로)을 적는다 |
| 14 | 깊게 생각하기 | `thinking_supported` 일 때만 보인다. 처음 상태는 위젯 설정 `thinking_default` 다. 단추 상태대로 요청에 `thinking: on` 또는 `off` 를 늘 싣는다(CLI 연결은 끔을 보내야 생각을 멈춘다) |
| 15 | 크게 보기 | 위젯을 붙인 칸 위로 화면 가득 겹쳐 보인다. Esc 나 같은 단추로 닫는다 |
| 16 | Esc 순서 | 녹음 중이면 녹음 취소, 답이 돌면 응답 중지, 아니면 열린 메뉴 닫기, 아니면 크게 보기 닫기 |
| 17 | 글자 크기 | 더보기의 작게, 보통, 크게. 본문과 입력칸 글자가 함께 바뀌고 그 브라우저에 기억한다. 기억한 값이 붙이는 앱의 `fontSize` 보다 앞선다(BIZ-152) |

## 6. API 요약

| 순번 | 방법 | 경로 | 뜻 |
|---|---|---|---|
| 1 | POST | /api/v1/chat/completions | `rewind_from_seq`, `thinking` 칸 추가, `model` 검사, done 칸 추가 |
| 2 | GET | /api/v1/chat/widget-settings | 위젯 설정 (3.5) |
| 3 | PUT | /api/v1/chat/feedback | 평가 남기기, 바꾸기 (3.3) |
| 4 | DELETE | /api/v1/chat/feedback?turn_id= | 평가 취소 |
| 5 | POST | /api/v1/chat/sessions/{session_id}/follow-ups | 후속 질문과 제목 (3.6) |
| 6 | GET | /api/v1/chat/feedback | 관리 화면 평가 목록 (FE-043). 로그인 사용자만, 위젯 토큰은 거부 |

평가 남기기 본문:

```json
{"session_id": "cs-9471-...", "turn_id": "0b6f...", "rating": "DOWN", "reason_codes": ["NO_LOOKUP"], "comment": "출고 이력을 안 봤어요"}
```

| 오류 | 경우 |
|---|---|
| 400 `feedback_invalid:rating` | UP, DOWN 이 아님 |
| 400 `feedback_invalid:reason_codes` | 설정에 없는 code, 또는 UP 인데 이유가 있음 |
| 400 `feedback_invalid:comment` | 최대 글자 수 넘음 |
| 404 `turn_not_found` | 그 세션에 없는 답이거나 요청한 사람의 세션이 아님 |

관리 화면 평가 목록: 조건 `rating`, `from`, `to`, `model`, `page`, `size`. `from`, `to` 는 시간대 오프셋을 붙인 ISO-8601(예 `2026-11-04T00:00:00+09:00`)이고 `to` 시각은 넣지 않는다. 행마다 작성일, 평가, 이유 label, 의견, 모델, 질문 앞부분, 답 앞부분, 세션 id, 삭제된 응답 여부.

| 오류 | 경우 |
|---|---|
| 400 `feedback_invalid:from`, `feedback_invalid:to` | 오프셋이 없거나 날짜 형식이 아님 |
| 403 `feedback_list_forbidden` | 위젯 토큰으로 부름 |

## 7. 관리 화면

| 순번 | 기능 ID | 화면 | 내용 |
|---|---|---|---|
| 1 | FE-042 | 연결 편집 (Connections) | 「허용 모델」 목록 칸. 모델 id, 이름, 순서 바꾸기(위로, 아래로), 기본 모델 표시. 비우면 위젯이 모델 선택 칸을 숨긴다고 안내 |
| 2 | FE-043 | 응답 평가 (신규, 왼쪽 메뉴 「세션」 다음) | 6절 목록. 위 조건 칸, 표, 행을 누르면 기존 세션 상세(SessionDetail)로 이동 |

FE-042 를 개발기에 올리기 전에 같은 창의 결함 둘을 고쳤다(2026-11-11). 허용 모델을 이 창에서 고치게 되면서 바로 드러나는 결함이다.
- 서버는 연결 설정을 통째로 바꿔 끼우는데, 창은 자기가 아는 칸만 모아 저장했다. 그래서 실행기 연결을 한 번 저장하면 어느 실행기로 보낼지 정하는 agent_name 이 지워졌다. 이제 기존 설정을 깔고 그 위에 창의 값을 덮는다.
- 저장된 어댑터 값(anthropic-cli 등)과 창의 표시명(Claude CLI 등)이 달라, 기존 연결의 수정 창에서 어댑터 전용 칸이 숨겨졌다. 이제 서버와 같은 규칙으로 표시명을 찾는다. 어댑터를 바꾸지 않으면 저장값을 그대로 보낸다. 서버가 기본 CLI 연결을 어댑터 원문으로 찾기 때문이다.

같은 날 7월에 개발기에만 올라가 있던 연결 창 「Exposed Tools」 칸(CR-129)과 실행 이력의 채팅 구분(CR-130)을 커밋으로 옮겼다. 그대로 두면 이번 반영에서 빠진다.

### 9.2 통합 시험항목 (절차서에 올릴 것)

| 순번 | 시험항목 | 확인 |
|---|---|---|
| 1 | 답 도는 중 응답 중지 단추, Esc | 받은 데까지 남고 「응답을 중지했습니다」, 그 답을 다시 생성할 수 있고 다음 질문이 정상으로 돈다 |
| 2 | 다시 생성 | 새 답이 오고 버전 번호 1/2 로 앞 답을 볼 수 있다. 새로고침 뒤 세션 상세에 마지막 버전만 이어진다 |
| 3 | 가운데 질문 수정 | 경고 문구를 보고 전송하면 그 뒤 대화가 사라지고 고친 질문의 답이 온다. DB 에 지운 표시(REWIND)가 남는다 |
| 4 | 답 도는 중 되감기 | 위젯은 다시 생성, 수정 단추를 숨긴다. API 로 직접 보내면 409 `session_busy` |
| 5 | 좋아요, 아쉬워요 이유와 의견, 취소 | 관리 화면 응답 평가에 한 행으로 바뀌어 보이고, 취소하면 사라진다 |
| 6 | 모델 선택 | 연결에 모델 둘을 넣으면 칸이 보이고, 고른 모델로 답하며 답 아래 이름이 맞다. 하나면 칸이 숨는다 |
| 7 | 목록에 없는 모델 요청 | API 로 직접 보내면 400 `model_not_allowed` |
| 8 | 깊게 생각하기 | 지원 연결에서만 보이고, 켜면 생각 접은 줄이 생긴다 |
| 9 | 후속 질문과 제목 | 첫 답 뒤 칩 3개, 누르면 바로 묻는다. 세션 제목이 만든 제목으로 바뀐다. 사람이 고친 제목은 바뀌지 않는다 |
| 10 | 후속 질문 끔 | 설정을 끄면 칩이 안 보이고 답은 정상 |
| 11 | 첫 화면 추천 질문 | 붙이는 앱이 준 질문이 보이고 누르면 바로 묻는다 |
| 12 | 스크롤 고정 | 긴 답이 도는 중 위로 올리면 끌려 내려가지 않고 「맨 아래로」가 뜬다 |
| 13 | 입력칸과 단축키 | 여러 줄로 늘어나고, 한글 조합 중 Enter 로 보내지지 않으며, 빈 칸에서 위 화살표로 마지막 질문을 고친다 |
| 14 | 글자 크기 | 크게로 바꾸면 본문과 입력칸이 커지고 새로고침 뒤에도 유지된다 |
| 15 | 새 대화 | 화면이 비고 새 세션으로 묻는다. 앞 세션은 세션 목록에 남는다 |
| 16 | 크게 보기 | 화면 가득 뜨고 Esc 로 닫힌다 |
| 17 | 무채색 | 실화면 목업 「개선안」과 같은 색으로 보인다 |

절차서 영역 09(채팅 위젯 대화 기본기) IT-09-001 ~ IT-09-024 로 올렸다(2026-11-11). 위 17개에 서버 오류 표에서 뽑은 거절 셋(IT-09-005 되감기, IT-09-007 평가, IT-09-012 생각), 관리 화면 허용 모델 칸(IT-09-009), 도구 접기(IT-09-021), 결함 회귀 둘(IT-09-023 모델을 바꾼 뒤 답, IT-09-024 칸 높이)을 더했다. 백오피스2 가 아직 넘기지 않는 옵션과 연결을 바꿔야 하는 확인은 로컬 위젯 견본 화면에서 본다.

1차 자동 판정(2026-11-11, 개발기): 서버 판정 18개와 단위시험 13개 중 충족 29, 미충족 1, 재료 없음 1.
