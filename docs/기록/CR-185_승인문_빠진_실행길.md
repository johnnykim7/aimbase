# CR-185 승인 문이 빠진 실행 길

- 일자: 2026-11-13
- 쓴 곳: CR-185 워커 창(aimbase-83050)

## 지금 상태

설계(CR-185 문서 2절 관문 자리)는 승인 문을 두 곳에 둔다. 대화 중 도구 실행(ToolCallHandler)과 Claude CLI 가 서버 MCP 로 부르는 도구(ServerMcpToolDispatcher)다.

도구를 실행하는 길은 이 밖에도 있고, 거기서는 정책이 「실행 전 승인」이어도 묻지 않고 실행된다.

| 순번 | 실행 길 | 누가 부르나 | 소스 |
|---|---|---|---|
| 1 | 원격 트리거 도구 | AI 가 다른 도구를 대신 부른다 | RemoteTriggerTool.java:116 |
| 2 | 워크플로우 도구 단계(TOOL_CALL) | 워크플로우를 만든 사람이 정한 단계 | ToolCallStepExecutor.java:111 |
| 3 | 예약 실행 | 예약에 걸어 둔 도구 | CronScheduleManager.java:197 |
| 4 | 관리 화면 도구 실행, 도구 시험 | 관리자가 직접 누른다 | ToolController.java:92, ToolTestController.java:25 |

BIZ-241 은 「열린 턴이 없으면(스트림이 아닌 대화, 워크플로우 단계, 서브에이전트, 바깥 MCP 호출, 머리글이 없는 옛 실행기) 실행하지 않는다. 승인 없이 실행되는 길은 없다」이다. 1 ~ 4 가 이 문장과 어긋난다.

## 정할 것

1. 도구 실행 공통 지점(ToolRegistry 의 실행)에 문을 옮겨 1 ~ 4 를 모두 막는다. 열린 대화 턴이 없으니 「승인이 필요한 도구라 위젯 대화에서만 실행할 수 있습니다」로 실행하지 않는다. 관리 화면 도구 시험과 워크플로우 도구 단계도 막힌다 (권장)
2. AI 가 부르는 길(1)만 더 막는다. 2 ~ 4 는 승인 없이 돈다(잃는 것: BIZ-241 문구를 고쳐야 하고, 정책으로 막았다고 믿은 도구가 워크플로우와 예약에서는 그냥 돈다)

어느 쪽이든 CR-185 문서 2절 관문 자리 표를 고쳐 설계보정으로 남긴다.
