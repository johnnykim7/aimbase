## 1. 배경

- 사용자 결정(2026-10-31). 07:30 현장 화면 음성을 분류대 299개(BO2 CR-865, 맥에서 Qwen3-TTS 로 만든 것) 목소리로 맞춘다. 08:13 나머지 현장 음성도 같은 목소리로 서버가 만든다. 08:22 59 에서 속도와 소리를 재고 쓸 만하면 생성기는 Aimbase 에 둔다. 10:29 Aimbase 에 같은 목소리 생성기를 비동기로 둔다. 처음 나온 문장은 화면이 기기 목소리로 한 번 읽고, 뒤에서 만들어 저장해 다음부터 같은 목소리로 읽는다
- 59 실측: PyTorch CPU fp32 가 쓸 수 있는 유일한 판이다. 만든 소리 1초에 약 7초, 짧은 말 11 ~ 17초, 일반 문장 19 ~ 25초, 두 문장 35초. 길이와 높이가 분류대 299개와 같은 범위다. 화면이 기다리는 동안 만들 수는 없다

## 2. 쓰는 모양

1. 현장 화면이 bp-wms 에 문장 하나를 보낸다
2. bp-wms 에 저장분이 있으면 바로 준다. 없으면 「없음」 으로 바로 답하고(화면은 그 한 번을 기기 목소리로 읽는다) Aimbase 에 생성 작업을 맡긴다
3. bp-wms 정기 작업이 맡긴 작업을 5 ~ 10초 간격으로 조회해, 끝난 것의 소리를 받아 저장한다
4. 다음부터 그 문장은 bp-wms 저장분을 바로 준다

## 3. 설계

### 3.1 생성기 컨테이너 `tts-sidecar`

| 항목 | 값 |
|---|---|
| 소스 | 레포 `tts-sidecar/`(Dockerfile, `server.py`, `voices/`) |
| 실행 환경 | python 3.13-slim, ffmpeg, PyTorch CPU 판, `qwen-tts` 0.1.1, FastAPI |
| 모델 | `Qwen/Qwen3-TTS-12Hz-1.7B-Base`, fp32. 이미지에 넣지 않고 이름 있는 볼륨(`tts-models`)에 받는다. 처음 기동 때 한 번 받는다(4.3GB) |
| 망 | compose 기본 망. 호스트 포트를 열지 않는다. api 만 `http://tts-sidecar:8310` 으로 부른다 |
| CPU | 코어 8개 상한(`cpus: 8`), 연산 스레드 8개. CPU 몫(`cpu_shares`)을 다른 컨테이너의 1/4 로 둔다. 59 코어가 모자랄 때 api, 러너가 먼저 CPU 를 받는다 |
| 메모리 | 16GB 상한(59 실측과 같은 상한) |
| 동시 처리 | 한 번에 한 문장. 생성기 안에서도 잠금으로 한 번에 하나만 만든다 |
| 기동 | 모델을 올리고(약 7초) 등록된 음색마다 견본 특징을 한 번 만든다(약 0.6초). 끝나기 전에는 `GET /health` 가 503 |

생성기 창구(api 만 부른다)

| 창구 | 하는 일 |
|---|---|

### 3.2 음색 등록

음색 하나는 `tts-sidecar/voices/<이름>/` 폴더 하나다. `voice.json` 과 견본 소리 `ref.wav` 를 둔다. 레포에 넣어 같은 값을 다시 쓸 수 있게 한다. 음색을 늘리거나 값을 바꾸면 생성기를 다시 배포한다(음색 관리 화면은 두지 않는다, 요청서 5절).

`field-voice-07`(분류대 299개와 같은 값)

| 항목 | 값 | 출처 |
|---|---|---|
| 견본 소리 | `07_친근한_주문알림_000.wav` | 요청서 3-2 |
| 견본 글 | `1번. 스물한 개. 200번. 아흔아홉 개.` | 요청서 3-2 |
| 언어 | Korean | |
| 생성값 | temperature 0.65, top_p 0.90, top_k 30, repetition_penalty 1.05. subtalker 도 같은 값 | 요청서 3-2, 59 실측 |
| 씨앗 | 20261031. 실패해 다시 만들 때는 20261032, 20261033(최대 3번) | 분류대 299개 생성 스크립트(`generate_qwen_tts_batch.py`)와 같다 |
| 생성 상한 | 글자 수 x 8 토큰, 최소 48, 최대 1,600(소리 약 128초). 토큰 하나가 소리 1,920표본(24kHz)으로 풀려 소리 1초가 12.5토큰 | 299개는 짧은 말이라 48 |
| 실패로 보는 것 | 소리가 비었다, 숫자가 아닌 값이 섞였다, 무음이다(최대 진폭 0.00001 미만), 0.25초보다 짧다, 생성 상한까지 갔다(끝맺지 못하고 늘어진 것. 소리 길이를 1,920표본으로 나눈 토큰 수가 상한 - 1.5 를 넘으면 상한까지 간 것으로 본다. 상한까지 가면 상한보다 하나 적은 토큰이 나오고, 스스로 끝맺으면 그보다 적다) | 299개 생성 스크립트의 검사에 상한 도달을 더했다 |
| 뒤처리 | ffmpeg `silenceremove=start_periods=1:start_duration=0:start_threshold=-50dB,areverse,silenceremove=start_periods=1:start_duration=0:start_threshold=-50dB,areverse,atempo=0.90,apad=pad_dur=0.05,adelay=50`, 24kHz 단일 채널, MP3 96k | 요청서 3-2 |

같은 음색, 같은 글이면 씨앗 순서가 같으므로 다시 만들어도 같은 소리가 난다(BIZ-134). 299개는 맥 MLX 8bit 판으로, 이 생성기는 PyTorch fp32 판으로 만들어 소리가 비트 단위로 같지는 않다. 같은 목소리인지는 길이와 높이 범위로 보고 사용자가 들어 정한다(59 실측과 같은 기준).

### 3.3 비동기 생성 창구

녹음 변환 작업(CR-133 `transcribe-jobs`)과 같은 「맡기기, 조회」 모양이다. 주소는 이미 있는 음성 합성 창구(`/api/v1/speech/tts`) 옆에 둔다.

#### 작업 맡기기 `POST /api/v1/speech/tts-jobs`

```json
{ "voice": "field-voice-07", "text": "검수대 3번으로 이동하세요." }
```

| 칸 | 필수 | 설명 |
|---|---|---|
| `voice` | 예 | 음색 이름 |
| `text` | 예 | 읽을 글. 1 ~ 200자(공백만 있는 글은 빈 글). 글자를 바꾸지 않고 그대로 읽는다. 숫자로 쓴 날짜, 시각은 읽는 말로 바꿔 보낸다(CR-165 6절 5, 로컬 엔진은 `2026-10-31 14:00` 을 못 읽는다) |

202 와 작업을 바로 돌려준다.

```json
{ "success": true,
  "data": { "job_id": "9f3c1a20-...", "status": "PENDING", "voice": "field-voice-07",
            "reused": false, "created_at": "2026-10-31T01:40:00Z" } }
```

같은 테넌트에 같은 음색, 같은 글의 작업이 이미 있으면(실패한 것 제외, 보관 기간 안) 새로 만들지 않고 그 작업을 돌려준다. 이때 `reused` 가 true 이고 `status` 는 그 작업의 지금 상태다(이미 COMPLETED 일 수 있다).

#### 작업 조회 `GET /api/v1/speech/tts-jobs/{job_id}`

```json
{ "success": true,
  "data": { "job_id": "9f3c1a20-...", "status": "COMPLETED", "voice": "field-voice-07",
            "text": "검수대 3번으로 이동하세요.",
            "created_at": "...", "started_at": "...", "finished_at": "...",
            "mime_type": "audio/mpeg", "audio_base64": "SUQzBAAAAA...",
            "duration_sec": 2.21, "elapsed_sec": 21.7 } }
```

- `status`: `PENDING`, `RUNNING`, `COMPLETED`, `FAILED`(T1-5 TtsJob)
- `mime_type`, `audio_base64`, `duration_sec` 는 COMPLETED 일 때만, `error` 는 FAILED 일 때만 싣는다
- `elapsed_sec` 은 생성기가 만드는 데 걸린 시간(대기 시간 빼고)
- 시각(`created_at`, `started_at`, `finished_at`)은 UTC 로 싣는다(`2026-10-31T01:40:00Z`)

#### 오류

본문은 `{ "success": false, "error": "<코드>" }`.

| HTTP | 코드 | 때 |
|---|---|---|
| 400 | `voice_required`, `text_required`, `text_too_long:max=200`, `invalid_job_id` | 칸이 비었거나 길거나 작업 번호 모양이 틀림 |
| 404 | `voice_not_found:<이름>` | 없는 음색 |
| 404 | `job_not_found` | 없는 작업, 보관 기간이 지나 지운 작업, 다른 테넌트의 작업 |
| 429 | `tts_queue_full:max=500` | 그 테넌트의 대기, 진행 중 작업이 상한에 닿음 |
| 503 | `tts_generator_unavailable` | 생성기가 떠 있지 않거나 모델을 올리는 중 |

FAILED 작업의 `error`: `generation_failed:<까닭>`(empty_audio, non_finite_audio, silent_audio, too_short, hit_token_limit, internal_error), `tts_generator_unavailable`, `tts_generator_timeout`. 실패한 글을 다시 맡기면 새 작업이 된다.

### 3.4 처리 순서와 59 자원

- 서버 전체에서 한 번에 한 작업. 테넌트를 가리지 않고 맡긴 시각 순서대로 만든다(BIZ-133)
- 몰아서 맡기면 뒤에 맡긴 문장은 앞 것이 끝나야 만든다. 문장마다 약 15초라 299개면 약 75분이다
- 테넌트마다 대기와 진행 중 작업은 500개까지(설정 `aimbase.tts.max-pending-per-tenant`). 넘으면 429
- api 를 다시 띄우면 메모리에 든 작업 차례가 사라진다. 대기나 진행 중으로 남은 작업은 조회나 같은 글 다시 맡기기가 오면 맡긴 시각 그대로 차례에 다시 넣는다. bp-wms 가 5 ~ 10초마다 조회하므로 다시 떠도 이어진다
- 생성기가 쓰는 CPU 는 코어 8개(59 는 16개)가 상한이고, CPU 가 모자랄 때는 다른 컨테이너보다 늦게 받는다(3.1). 배포 뒤 생성하는 동안과 쉬는 동안의 api 응답 시간을 재서 7절에 남긴다

### 3.5 결과 보관

- 소리는 작업 행에 MP3 그대로 둔다(문장 하나 약 30KB)
- 끝난 작업(COMPLETED, FAILED)은 7일 둔다(설정 `aimbase.tts.retention-days`, 요청서는 적어도 하루). 그 테넌트에 새 작업을 맡길 때 기간이 지난 것을 지운다. 따로 도는 정리 작업은 두지 않는다

### 3.6 테넌트와 키

- bp-wms 가 이미 쓰는 Aimbase 테넌트와 키(`integration.aimbase.*`)로 부른다. 다른 테넌트 창구처럼 `X-API-Key` 와 `X-Tenant-Id` 를 함께 보낸다. 테넌트 키는 경로별 권한을 따로 걸지 않아(`ApiKeyAuthenticationFilter`, `/api/v1/**` 인증만 본다) 새 키나 권한 작업이 없다
- 작업은 테넌트 DB 에 두어(BIZ-003) 다른 테넌트의 작업은 조회되지 않는다

## 4. 요청서와 다른 것

요청서 4절은 bp-wms 의 제안이다. 받아들이고 아래만 더하거나 정했다.

1. 같은 글을 다시 맡기면 새로 만들지 않고 그 작업을 돌려준다(`reused`). bp-wms 가 막더라도 서버가 한 번 더 막아 CPU 를 아낀다
2. 429 `tts_queue_full` 을 더한다. 한 테넌트가 수천 개를 몰아 맡겨 생성기를 몇 시간 붙잡지 않게 한다
3. 오류 본문에 코드를 싣는다(`text_too_long:max=200` 등)
4. 결과 보관 7일(요청서 「적어도 하루」 안)
5. 조회 응답에 `text`, `created_at`, `started_at`, `finished_at` 을 더한다
6. 소리를 따로 받는 창구(`GET .../audio`)는 두지 않는다. 200자 문장도 소리가 약 0.4MB 라 조회 응답에 싣는다

## 8. 질의

1. 몰아서 맡길 일이 지금 있는지(bp-wms). 있으면 즉석 문장이 몰아 맡긴 것 뒤에 밀리지 않게 차례 칸을 둘지 정한다. 지금은 맡긴 순서대로다
   - 답(bp-wms, 컨타 회신): 지금은 없다. 화면이 처음 보낸 문장을 그때마다 한 건씩 맡긴다(같은 문장은 한 번). 차례 칸은 두지 않고 맡긴 순서대로 한다. 필요해지면 그때 요청한다
