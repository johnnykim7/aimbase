## 3. 서버

### 3.1 답 읽어 주기 [PRD-580, BIZ-251, BIZ-252]

`POST /api/v1/chat/tts`

```json
{ "session_id": "cs-9471-...", "text": "주문 3건이 2026-11-12 14:00 에 출고되었습니다." }
```

- 권한: 위젯 토큰은 `chat:tts` scope 가 있어야 한다. 로그인 사용자는 된다.
- 글은 위젯이 만든 읽을 글이다(4.4). 서버는 마크다운을 다시 다루지 않는다.
- 목소리는 `widget.tts.voice`, 속도는 `widget.tts.speed` 다. 목소리가 비면 목소리 목록(`tts.voices`)의 기본 목소리다. 목록 목소리면 기존 날짜, 시각 읽기(BIZ-137)를 거친다.
- 맥 음성 엔진은 `widget.tts.local-timeout-seconds` 까지만 기다리고, 넘으면 기존 전환 규칙대로 OpenAI 로 보낸다(BIZ-252). 다른 경로(bp-office 브리핑)는 지금처럼 연결 값을 쓴다.
- 응답: 200 `audio/mpeg`, 머리글 `X-Aimbase-TTS-Engine: local | openai`.
- 감사 로그 `WIDGET_TTS`: 세션 id, 글자 수, 엔진, 걸린 시간. 글 본문은 남기지 않는다.

| 상태 | 오류 | 경우 |
|---|---|---|
| 400 | `tts_invalid:text` | 글이 비었거나 `widget.tts.max-chars` 를 넘음 |
| 403 | `tts_forbidden` | 위젯 토큰에 `chat:tts` 없음 |
| 409 | `tts_disabled` | `widget.tts.enabled` 가 false |
| 429 | `tts_rate_limited` | 세션의 분당 요청이 `widget.tts.rate-limit-per-minute` 를 넘음 |
| 503 | `tts_unavailable` | 맥 엔진 실패에 OpenAI 전환 꺼짐, 또는 쓸 수 있는 OpenAI 연결 없음 |
| 502 | `tts_upstream_error` | OpenAI 가 오류를 돌려줌 |

### 3.2 음성 대화 입장권 [PRD-582, BIZ-253]

`POST /api/v1/chat/voice/tickets`

```json
{ "session_id": "cs-9471-..." }
```

```json
{ "success": true, "data": { "ticket": "vt_7Q...", "expires_in_seconds": 30, "stream_path": "/api/v1/chat/voice/stream" } }
```

- 권한: 위젯 토큰은 `chat:voice` scope 가 있어야 한다. 로그인 사용자는 된다.
- 입장권은 한 번만 쓰고 `widget.voice.ticket-ttl-seconds` 가 지나면 버린다. Redis 키 `voice:ticket:{ticket}` 에 테넌트 id, 세션 id, 사람(user_ref 또는 로그인 id), 허용 출처, 받아쓰기 연결 id 를 둔다.
- 받아쓰기 연결은 그 테넌트의 활성 `stt_local` 연결 중 첫 번째다(누르고 말하기와 같다).

| 상태 | 오류 | 경우 |
|---|---|---|
| 400 | `voice_invalid:session_id` | `session_id` 가 비었음 |
| 403 | `voice_forbidden` | 위젯 토큰에 `chat:voice` 없음 |
| 409 | `voice_disabled` | `widget.voice.enabled` 가 false |
| 409 | `voice_session_busy` | 그 세션에 이미 열린 음성 중계가 있음 |
| 429 | `voice_busy` | 열린 음성 중계가 `widget.voice.max-concurrent-streams` 개 |
| 503 | `voice_unavailable` | 그 테넌트에 활성 `stt_local` 연결이 없음 |

### 3.3 실시간 받아쓰기 중계 [PRD-582, BIZ-253, BIZ-254]

`GET /api/v1/chat/voice/stream?ticket=vt_7Q...` (웹소켓)

- 한 연결이 한 번의 말(발화)이다. 위젯은 듣기를 시작할 때마다 입장권을 받고 새로 연다. 받아쓰기 서버도 연결 하나에 발화 하나를 받고 끝에 마지막 글을 낸다(2절 3).
- 손잡기에서 입장권을 꺼내 지우고, 요청 출처(Origin)가 입장권의 허용 출처와 같은지 본다. 이 경로는 로그인 검사와 테넌트 머리글 검사를 거치지 않고 입장권으로만 들어온다.
- 서버는 받아쓰기 서버의 `/stream` 에 웹소켓을 열고(`base_url` 의 http, https 를 ws, wss 로, 연결의 `api_key` 를 붙여) 양쪽을 잇는다. 소리는 저장하지 않는다.

| 방향 | 프레임 | 뜻 |
|---|---|---|
| 위젯에서 서버 | 바이너리 | MediaRecorder 의 WebM(Opus) 조각. 그대로 받아쓰기 서버로 보낸다 |
| 위젯에서 서버 | 글 `{"type":"end"}` | 말이 끝났다. 받아쓰기 서버에 빈 프레임을 보낸다 |
| 서버에서 위젯 | 글 `{"type":"ready"}` | 받아쓰기 서버와 이어졌다. 이때부터 소리를 보낸다 |
| 서버에서 위젯 | 글 `{"type":"transcript","text":"...","buffer":"..."}` | 확정 글과 미확정 글. 받아쓰기 서버가 보낸 것을 그대로 옮긴다 |
| 서버에서 위젯 | 글 `{"type":"final","text":"..."}` | 마지막 글. 보낸 뒤 서버가 닫는다(1000) |

| 닫는 번호 | 뜻 |
|---|---|
| 4401 | 입장권이 없거나 지났거나 이미 썼다 |
| 4403 | 출처가 다르다 |
| 4408 | 발화가 `widget.voice.max-utterance-seconds` 에 5초를 더한 시간을 넘었다 |
| 4429 | 열린 중계가 상한이거나 같은 세션의 중계가 아직 열려 있다(입장권 뒤에 다른 연결이 먼저 찼을 때) |
| 1011 | 받아쓰기 서버에 잇지 못했거나 끊겼다. `end` 뒤 `widget.voice.final-timeout-seconds` 안에 마지막 글이 오지 않았다 |

- 감사 로그 `VOICE_STREAM`: 세션 id, 이은 시간, 받은 소리 바이트, 끝난 까닭(final, 시간 초과, 끊김). 받아쓴 글은 남기지 않는다.

### 3.4 위젯 설정 조회 칸 추가 [PRD-580, PRD-581]

`GET /api/v1/chat/widget-settings` 응답에 더한다.

```json
{
  "tts_enabled": true,
  "tts_max_chars": 300,
  "voice_chat_enabled": true,
  "voice_end_silence_ms": 1200,
  "voice_speech_level": 0.02,
  "voice_max_utterance_seconds": 60,
  "voice_idle_end_seconds": 120
}
```

- `voice_chat_enabled` 는 `widget.voice.enabled` 이고 그 테넌트에 활성 `stt_local` 연결이 있을 때만 참이다.

### 3.5 위젯 토큰 권한

- 새 scope `chat:tts`(답 읽어 주기), `chat:voice`(음성 대화 입장권)를 `widget.allowed-scopes` 에 더한다(코드 기본값과 V89 마이그레이션. 이미 값이 있으면 둘을 덧붙인다. CR-060 V19 와 같은 방식).
- 소비앱이 토큰을 받을 때 scopes 를 골라 보내면 두 scope 를 더해 달라고 요청해야 한다(8절).

## 4. 위젯

위젯 코드는 CR-177(위젯 틀)이 dev 에 들어간 뒤 쓴다. [guides/chat-widget-frame.md](guides/chat-widget-frame.md) 를 따라 위젯 본체와 틀은 고치지 않고 `src/features/` 에 기능 파일을 두고 자리에 등록만 한다.

| 순번 | 파일 | 등록하는 자리 |
|---|---|---|
| 1 | `src/features/read-aloud.ts` | 응답 아래 단추 `ctx.ui.answer.addAction`, Esc `ctx.ui.onEscape`, 알림 `newConversation`, `destroy` |
| 2 | `src/features/voice-chat/` | 입력칸 단추 `ctx.ui.composer.addTool`, 음성 대화 줄 `ctx.ui.layer`(입력칸 자리를 덮는다), 대화 동작 `ctx.chat.send`, Esc |
| 3 | `src/features/speech-text.ts` | 읽을 글 만들기와 조각 나누기(4.4). 두 기능이 같이 쓴다 |

틀에 없던 자리 셋(응답이 오는 동안의 알림 `answerStart`, `answerDelta`, 응답 중지 `ctx.chat.abort`, 위젯 본체 마이크 녹음 중 여부 `ctx.isRecording`)은 CR-177 이 틀 사용법 1.1 의 3.7절에 넣었다(dev 51bcdd5).

### 4.2 답 읽어 주기 동작 [PRD-580]

| 순번 | 경우 | 동작 |
|---|---|---|
| 1 | 「읽어 주기」를 누름 | 그 답의 마크다운에서 읽을 글을 만들고(4.4) 나눈 조각을 차례로 3.1 에 보낸다. 첫 조각 소리가 오면 바로 재생하고, 재생하는 동안 다음 조각을 하나 미리 받는다. 단추는 「읽기 멈춤」으로 바뀐다 |
| 2 | 「읽기 멈춤」 또는 Esc | 재생을 멈추고 받는 중인 요청을 끊는다. 단추가 「읽어 주기」로 돌아간다 |
| 3 | 다른 답의 「읽어 주기」 | 읽던 답을 멈추고 새 답을 읽는다. 한 번에 한 답만 읽는다 |
| 4 | 새 대화, 다시 생성, 질문 수정, 음성 대화 시작 | 읽기를 멈춘다 |
| 5 | 받아오지 못함(오류, 시간 초과) | 멈추고 「읽어 드리지 못했습니다」를 잠깐 보인다. 이미 읽은 데까지는 그대로 둔다 |
| 6 | 읽을 글이 비었음(코드만 있는 답 등) | 요청하지 않고 「읽을 글이 없습니다」 |

### 4.3 음성 대화 동작 [PRD-581, BIZ-254]

상태

| 상태 | 화면 | 마이크 | 넘어가는 때 |
|---|---|---|---|
| 준비 | 상태 글 「연결하는 중」 | 켬(보내지 않음) | 입장권을 받고 중계가 `ready` 를 보내면 듣는 중 |
| 듣는 중 | 「듣는 중」, 받아쓴 글 | 소리를 중계로 보냄 | 말이 끝나면(아래 끝 판정) 마지막 글을 기다림. 마지막 글이 비면 「잘 듣지 못했습니다」 뒤 다시 준비 |
| 답을 만드는 중 | 「답을 만드는 중」 | 멈춤 | 마지막 글을 질문으로 보낸다(글로 친 질문과 같은 길, 고른 모델과 깊게 생각하기 그대로). 답의 첫 문장이 끝나면 읽는 중 |
| 읽는 중 | 「읽는 중」 | 멈춤 | 답이 다 오고 읽을 조각이 다 끝나면 준비 |
| 끝 | 입력칸으로 돌아감 | 끔(장치 해제) | |

- 끝 판정: 말소리 크기가 `voice_speech_level` 을 넘은 뒤 `voice_end_silence_ms` 동안 그 아래면 `end` 를 보낸다. 한 발화가 `voice_max_utterance_seconds` 가 되면 그때 `end` 를 보낸다.
- 듣는 중에 `voice_idle_end_seconds` 동안 말이 없으면 음성 대화를 끝내고 「음성 대화를 마쳤습니다」.
- 읽는 중에는 답이 오는 동안 끝난 문장부터 읽는다. 코드 묶음이나 표가 열려 있으면 닫힐 때까지 기다린다.
- 「말 끊기」(답을 만드는 중, 읽는 중): 답이 아직 오면 응답 중지(CR-175)를 부르고, 읽기를 멈추고, 준비로 간다.
- 「끝내기」 또는 Esc: 듣기와 읽기를 멈추고 마이크를 놓는다. 오고 있는 답은 글로 끝까지 받는다.
- 음성 대화 단추를 누른 순간 소리 재생을 한 번 열어 둔다(브라우저 자동 재생 제한 때문에 사람이 누른 때가 아니면 재생이 막힌다).
- 마이크는 메아리 제거와 잡음 줄이기를 켜고 연다.

### 4.4 읽을 글 만들기 [BIZ-250, BIZ-251]

- 답 마크다운에서 읽을 글을 만든다. 제목, 굵게, 기울임, 목록 기호, 인용 기호는 기호만 뺀다. 링크는 보이는 글만, 그림은 뺀다. 줄 안 코드는 안의 글만 남긴다.
- 코드 묶음은 「코드는 화면에서 확인해 주세요」, 표는 「표는 화면에서 확인해 주세요」 한 줄로 바꾼다(같은 답에서 이어지면 한 번만).
- 생각과 도구 사용 접은 줄, 출처 칩, 산출물 칩은 읽지 않는다.
- 조각 나누기: 문장 끝(마침표, 물음표, 느낌표, 줄바꿈)에서 나눈다. 첫 조각은 한 문장이다(빨리 시작하려고). 그 뒤 조각은 `tts_max_chars` 를 넘지 않게 문장을 모은다. 한 문장이 상한보다 길면 쉼표, 띄어쓰기 자리에서 자른다.

### 4.5 문구

문구는 기능 파일의 문구표(`defineStrings`)에 한국어와 영어를 짝으로 둔다. 「읽어 주기」, 「읽기 멈춤」, 「음성 대화」, 「연결하는 중」, 「듣는 중」, 「답을 만드는 중」, 「읽는 중」, 「말 끊기」, 「끝내기」, 4.2, 4.3 의 알림 글, 4.4 의 바꿔 읽는 두 줄.
