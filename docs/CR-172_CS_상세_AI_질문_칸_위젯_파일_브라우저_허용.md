## 1. 배경

BO2 59 CS 상세(문의 9431)의 AI 질문 칸이 「AI 질문 칸을 불러오지 못했습니다.」 로 멈춘다. BO2 는 `aimbase-chat.umd.global.js` 를 `<script>` 로 읽고, 이 진입 파일이 실행 중에 같은 폴더의 `aimbase-chat.esm.js` 와 청크를 읽어 온다. 이 읽기는 교차 출처 요청이다.

## 2. 원인

`CorsConfig.WIDGET_PATHS` 에 `/widget/**` 가 없어 위젯 파일 응답에 허용 머리글이 붙지 않는다. 허용 목록 `widget.allowed-origins` 에는 3201 이 이미 있다. 브리핑의 원인과 같다.

반영 전 59 측정(11-08 23:56, Origin `http://59.8.160.12:3201`):

| 순번 | 요청 | 상태 | 허용 머리글 |
|---|---|---|---|
| 1 | `aimbase-chat.esm.js` GET | 200 | 없음 |
| 2 | 같은 파일 사전 요청 | 403 | 없음 |
| 3 | 청크 GET | 200 | 없음 |
| 4 | `/api/v1/chat` 사전 요청 | 200 | 있음 |

## 3. 변경

`WIDGET_PATHS` 에 `/widget/**` 를 더한다. 허용 판정은 다른 위젯 경로와 같이 `widget.allowed-origins` 를 따른다. 관리 API(`/api/v1/platform/**`, `/api/v1/admin/**`)는 범위 밖 그대로다.

| 파일 | 변경 |
|---|---|
| `backend/platform-core/src/main/java/com/platform/config/CorsConfig.java` | 허용 경로에 `/widget/**` |
| `backend/platform-core/src/test/java/com/platform/config/CorsConfigTest.java` | 새 단위시험 6건 |
| `docs/guides/aimbase-ops-guide.md` | § 2-5 `widget.allowed-origins` 설명, v3.22.3 |

## 4. 바뀌는 것과 바뀌지 않는 것

1. 허용 주소에서 위젯 파일을 읽으면 허용 머리글이 붙는다.
2. Origin 없는 `<script>` 요청은 교차 출처 판정을 받지 않아 지금처럼 200 이다. 기존 소비앱이 진입 파일을 읽는 방식은 그대로다.
3. 허용하지 않은 주소가 Origin 을 실어 읽으면 403 이다. 반영 전에는 200 이되 허용 머리글이 없어 브라우저가 어차피 막던 요청이다.

## 5. 설계서

규모 소라 T1, T2, T3 는 고치지 않는다. 운용 가이드 § 2-5 에 허용 범위를 적는다.
